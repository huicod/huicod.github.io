## 一句话总结

UMo 让一个统一的文本—音频—动作语言模型只负责生成稀疏关键帧，再由轻量网络补全密集动作；同时用动态 top-1 专家增加模型容量，在保留四部位协调的条件下改善生成吞吐与首帧等待，但实际实现仍依赖已知的目标音频窗口，并不是零前视的完整对话系统。

## 研究背景与动机

**领域现状：** 共语动画需要身体手势、手指和面部共同响应讲话。专用生成模型通常在配对语音—动作数据上学习；另一条路线则把文字、语音和身体各部位编码为 token，用统一语言模型同时训练动作建模、语音文字对齐及条件生成。后一种路线便于共享数据与任务，但生成一整段高维动作的计算开销较大。

**现有痛点：** 虚拟角色开口时不能等几秒后才开始做动作。若语言模型逐帧预测脸、手、上身和下身的所有 token，它需要经过很多次顺序解码；若简单把一次生成的窗口缩短，模型又容易丢失上下文，导致短块之间不连贯。与此同时，面部细节与身体摆动的统计模式不同，全部交给相同前馈参数未必容易兼顾。

**核心矛盾：** 为动作质量保留更多时间上下文、更多身体细节，通常会增加延迟；为了快速响应而削减上下文和模型容量，又会损失质量。吞吐足够高与第一帧来得足够快也不是同一件事：每次批量生成很多帧可能平均速度不错，却仍让用户等很久。

**本文目标：** 作者希望保留统一多模态模型的表达能力，用同一主干生成脸、手、上身和下身的共语动作，同时改善持续生成速度和首帧延迟。目标输出是可合并为 SMPL-X 的连续动作参数；语音在实际头像生成流程中来自外部输入。

**切入角度：** 动作在两个方向上存在可利用的冗余。空间上，不必让每个 token 都调用所有模型参数；时间上，相邻帧常常非常接近，不必让昂贵的语言模型逐帧决定所有细节。作者因此分别在网络计算和时间采样上引入稀疏性。

**核心 idea：** 空间上把 T5 的前馈层换成动态路由的混合专家，每个 token 只激活一个专家；时间上让主干每隔若干帧生成一个离散关键帧，再让独立插值网络一次补全中间位置。三阶段训练学习跨模态对应和分块续写，TTS 音色增强则让相同动作对应更多声学输入。[原文 Introduction、Overview、Method](https://arxiv.org/html/2605.14731v1)

## 方法详解

### 整体框架

先把音频与已有动作转换成离散 token，再连同文本任务模板输入 Flan-T5 派生的 MoE 主干。主干读取历史关键帧和覆盖目标窗口的音频，联合预测四个部位的新关键帧 token。轻量插值网络接着填补非关键帧位置，四路冻结的 VQ 解码器才把密集 token 还原为连续动作参数，并合成 SMPL-X 全身序列。

### 关键设计

1. **统一的是离散序列建模接口，不是把所有输入都变成连续动作向量**

   音频先经过 HuBERT 第 9 层特征提取与 k-means 量化，得到 500 类离散音频 token。16 kHz 音频每 320 个采样点产生一个 token，即每秒 50 个。动作则沿用 LoM 的四路 VQ tokenizer：脸、手、上身、下身各有一个大小为 256 的码本，密集时间轴为每秒 30 个 token／部位。[Overview，PDF 第 5 页、式 6](https://arxiv.org/pdf/2605.14731#page=5)

   这里至少有三层不同对象：原始语音与骨架参数是连续信号；量化后的音频和动作是离散 ID；这些 ID 进入语言模型后又会被查表映射为连续 hidden states。论文有一句把前缀处理称作 continuous encoding，但式 6、VQ 码本定义、token 交叉熵和 argmax 重建都明确表明，主干预测的动作目标是离散 token。它既不是直接输出关节浮点坐标，也不是人能直接读懂的动作语言。

   文本提供任务说明以及任务所需的文字条件。在预训练中，输出可以是转录、音频 token 或动作 token；共语推理的输出则是动作。把这些任务放进一个接口，有利于共享表示，但不能据此推断当前模型已经具备完整的语音回答生成或任意动作编辑能力。

2. **分块自回归：固定历史、生成未来，但音频条件覆盖未来窗口**

   为了把单次推理规模控制住，UMo 不重复处理无限增长的全部历史，而是保留一个滑动窗口。每次输入最近的动作前缀和对齐音频，固定已经提交的历史，只生成后面的部分。T5 encoder 对本次给定条件使用双向注意力，decoder 按因果顺序生成新的 token。[Chunk-Wise Autoregressive，式 7–9](https://arxiv.org/pdf/2605.14731#page=5)

   这个混合注意力结构不能简单叫作“完全因果”。原文实际条件包含历史区间与**待生成区间的音频**。可以把它简写成：

   <div class="equation">下一块动作 ∼ p（未来动作 | 已提交动作历史，历史 + 目标区间音频，任务模板）</div>

   如果目标语音已经由外部 TTS 生成，或整段音频已知，这个前视条件容易提供；如果音频来自尚未说完的现场讲话，就需要等待目标窗口可用，或另外提供预测机制。论文讨论过联合音频—动作生成的一般公式，但局限部分明确说明当前系统仍依赖外部音频，联合音频生成属于未来工作。

   默认推理保留 P=10 个历史**关键帧步**，预测 N=5 个新关键帧步，而不是只保留 10 个、预测 5 个原始 30 fps 帧。这个区别决定了模型实际看到多长历史，也决定了不能直接用 5/30 秒解释它的输出块长度。[Inference，PDF 第 9 页](https://arxiv.org/pdf/2605.14731#page=9)

3. **空间稀疏 MoE：四个动态专家，而非四个部位各自绑定一个网络**

   脸部、手指和身体动作有不同的分布。作者保留共享注意力，让部位之间交换信息；在 encoder 和 decoder 的每个前馈子层，把一个 FFN 换成四个专家 FFN 与一个路由器。路由器根据当前 token 的 hidden state 选择专家，默认只激活概率最高的一个。[图 3、式 10–11](https://arxiv.org/pdf/2605.14731#page=6)

   <div class="equation">e* = argmax Router(h)，　MoE(h) = FFN<sub>e*</sub>(h)</div>

   这是默认 top-1 情况的教学简式。四个部位并不被固定分配给四个专家：某个脸部 token 在某一层选择的专家，取决于上下文和路由参数；另一 token 或另一层可以作出不同选择。增加的是可选择的总参数容量，每次仍只有一条专家前馈路径工作。共享注意力、路由及调度仍有开销，不能把“只激活一个专家”理解成总模型存储和所有运行成本都不变。

   初始化也有明确来源：从预训练的 dense T5 出发，把原 FFN 权重复制到各专家，即 sparse upcycling；注意力、层归一化和 embedding 不因这一步被替换。所有专家起初相同，因此换成 MoE 不必立刻破坏原模型功能。论文明确复用并冻结的是 LoM 的 VQ-VAE 权重；没有证据足以把主干说成“直接加载完整 LoM 成品语言模型再微调”。

   作者用负载均衡辅助损失避免 token 全挤到少数专家。一个实现细节值得留意：默认 top-1 的选中权重归一化后等于 1，原文说明路由器只通过该辅助项得到梯度；不能把这里描述成四个专家的概率加权软混合。专家本身仍通过预测任务学习，路由和专家权重的训练路径需要分开理解。

4. **时间稀疏：语言模型预测固定间隔关键帧，让相同历史预算覆盖更长时间**

   UMo 的关键帧不是额外运行一个语义事件检测器挑出来的，而是按固定 stride 采样。默认 s=6，即在密集动作 token 时间轴上每隔 6 帧保留一个锚点：

   <div class="equation">关键帧位置 K = {1, 1+s, 1+2s, …}，　默认 s=6</div>

   主干只对这些位置进行昂贵的自回归预测，解码长度从密集的 T 个时间位置缩短到约 T/s 个。密集表示为 30 Hz 时，s=6 对应约 5 Hz 的关键帧网格；在相同数量的历史 token 下，它还能覆盖更长的过去。这同时解释了加速来源和质量收益的可能来源：少预测重复帧，保留更长范围的上下文。[Temporal Sparse Keyframe Framework，式 12–14](https://arxiv.org/pdf/2605.14731#page=7)

   代价是中间细节不再都由语言模型直接决定。如果锚点选错，后面的插值器会围绕错误锚点补全；快速局部运动也可能被较稀的时间采样遗漏。因此 stride 越大并不必然越好，也不等于精确动作事件越少就越高效。

5. **密集重建：在 token 空间补全空位，最后才解码连续姿态**

   插值器得到的是四路序列：关键帧及最后有效帧保留，其他位置换成 mask。它先使用部位专用 embedding，对时间序列做双向注意力，再在同一帧内部用 part-aware attention 处理脸、手、上身和下身的关系；四路预测头分别给出各自码本的类别 logits。一次前向即可并行预测所有被遮蔽位置，不必逐帧再跑语言模型。[图 4、式 15–17](https://arxiv.org/pdf/2605.14731#page=8)

   <div class="equation">完整 token = 原锚点 token（锚点位置）／插值器预测 token（mask 位置）</div>

   最后合并时直接保留原锚点，四个冻结 VQ decoder 才把密集 token 转回连续动作参数。这里保留的是**码本 ID**，并不是用户指定的世界坐标、足底接触或关节轨迹硬约束。它与“从两个固定动画片段生成一个严格保真的过渡”也不是同一评测任务。

   插值网络与关键帧主干**分别训练**，而不是同一个端到端损失联合更新；原文还明确移除了插值器条件中的原始音频，让它专注于锚点之间的补全。音频对中间动作的作用主要通过主干生成的锚点传递，而不是插值器再次直接对齐波形。

   训练使用 masked token 交叉熵，再加一阶、二阶 embedding 差分正则。由于预测 ID 的 argmax 被 detach，这个平滑项的梯度只作用于 token embedding 查表参数，不直接反传到预测 logits。它不是对最终关节速度、加速度或物理接触的直接惩罚，更不能保证连续动作完全无抖动。

6. **三阶段学习与音频增强：先学表示关系，再学对齐，最后适应短块续写**

   预训练混合稀疏动作建模与音频—文本互预测，先建立不同 token 序列之间的对应关系。后训练第一阶段加入以音频生成动作为主、文字生成动作为辅的任务，强化窗口内的条件对齐；第二阶段再加入全身和部位级的关键帧续写任务，让模型适应实际分块推理。[图 5、式 18–23](https://arxiv.org/pdf/2605.14731#page=8)

   各任务共享 token 交叉熵，但不是每项都用相同采样频率。作者以任务样本量的温度幂控制混合比例，避免数据量大的任务压过其他任务。MoE 辅助损失在预训练权重为 0，在后训练启用。混合 a2m 与 t2m 表明同一模型学习两类任务，却没有自动证明一次输出中能同时满足任意独立动作文字和语音对同一身体部位的要求。

   音频增强只在后训练第二阶段使用。作者用 MiniMax TTS 为同一条动作生成五种不同音色的语音版本，建立“多个声学输入对应同一个动作”的训练关系。这样可以削弱模型对单一音色的依赖，但没有增加新的真实动作表演，也没有自然保证合成语音与每一个原始动作事件精确对齐；原文没有充分展开逐词时间对齐的实现细节。实验中多样性和主观偏好改善，同时原测试分布的 FGD、BC 变差，正体现了这种增强的取舍。

### 一个完整例子

设想外部 TTS 已经生成一段 10 秒讲解，角色需要一边播放语音，一边做动作。下面用简化时间网格说明一次续写，是教学例子，不是作者公开的逐 token 运行记录；也不声称某个离散 ID 天然表示“指向”“抬手”之类语义。

1. **准备已知音频与动作历史。** 10 秒、16 kHz 音频经过 HuBERT 量化后约为 500 个音频 token。当前角色已有四路关键帧历史，系统保留每个部位最近 10 个。论文评测首块由真实关键帧预填，这里从已经具有历史的一块开始讲解。
2. **选择将要推进的时间段。** 把当前最后锚点简记为密集时间位置 0。s=6 时，下一块五个关键帧落在 6、12、18、24、30，约推进一秒；音频条件也必须覆盖这段目标时间。这个秒数是根据 30 Hz 与 stride 推导的网格直觉，不是论文测得的响应延迟。
3. **主干预测四部位锚点。** 模型读取任务模板、音频与历史。每个 token 经共享注意力处理，再被路由到当层的一个专家；decoder 依次输出新锚点。五个时间步各有脸、手、上身和下身四个 ID，主体动作值共 20 个，任务与分隔标记另计。
4. **在锚点之间补全。** 位置 0、6、12、18、24、30 保持为已知锚点，其余位置置为 mask。插值器同时看前后锚点与部位关系，一次预测中间的四路离散 token；它不再读取原始音频，也不会重新改写已提交的锚点。
5. **输出连续动画并继续。** 四路 VQ decoder 把完整 token 序列变成连续脸部、手和身体参数，合并为 SMPL-X。新关键帧加入缓存，保留最近 10 个，再处理下一段已知音频。

这个过程说明“稀疏”的是昂贵主干的预测频率，而最终动画仍然是密集的。它也说明为什么达到 44 FPS 仍可能有约 826 ms 的首帧等待：平均处理速度、一次块计算耗时和首次可播放结果的到达时间，是三个不同量。

### 训练/推理

动作表示直接使用 LoM 预训练的四路 VQ-VAE，并在所有训练阶段冻结；主干从预训练 dense T5 经 sparse upcycling 构建。主干的预训练、两阶段后训练与插值器独立训练承担不同职责，不能概括成“直接把整个 LoM 在 BEATv2 上微调一次”。

| 部分 | 论文披露的训练／推理设置 |
| --- | --- |
| 音频表示 | HuBERT L9 + k-means，500 类；16 kHz 输入，50 token/s |
| 动作表示 | 脸／手／上身／下身四路；各 256 码；密集 token 时间轴 30 Hz；LoM VQ 权重冻结 |
| 主干 | Flan-T5-Base 路线，encoder／decoder FFN 全部替换为 4 专家 MoE；top-1 |
| 主干损失 | 任务 token 交叉熵 + MoE 负载均衡；辅助权重预训练为 0，后训练为 0.01 |
| 后训练任务 | a2m + t2m；第二阶段加入全身／部位关键帧续写，排除历史前缀等非监督位置 |
| 插值器 | 独立训练；mask 位置 CE，label smoothing 0.1；embedding 平滑权重 λᵥ=10⁻³、λₐ=10⁻⁴ |
| 上下文增强 | 训练样本包含短上下文情况，帮助有限历史条件下的生成 |
| 音频增强 | MiniMax speech-2.6；每条动作五种音色，只用于后训练第二阶段 |
| 优化器 | AdamW，学习率 10⁻⁴，β₁=0.9、β₂=0.99，weight decay 0.05 |
| 训练配置 | bf16，batch size 24；8 × A100-80GB；每配置约 150 epochs，每 epoch 约 1 小时 |
| 默认续写 | s=6；每路历史 P=10 个关键帧，新预测 N=5 个关键帧；首块评测使用 GT 关键帧前缀 |

按披露配置相乘，一次配置约为 150 小时墙钟、1,200 A100 GPU 小时；这是算术估计，不是包含预处理、TTS、全部消融和失败尝试的完整研究账单。论文没有完整列出多任务训练数据清单、各阶段的单独开销及采样比例数值。[Implementation Details，PDF 第 10 页](https://arxiv.org/pdf/2605.14731#page=10)

一个需要保留的口径差异是：后训练第一阶段在文字中称窗口含 120 个 keyframes，图 5 标成 120 Frames，同时正文称采用 dense temporal supervision。这里据此解释“先做窗口内条件对齐，再适配分块续写”的训练次序，不把这个 120 强行换算成确定秒数。

推理时不再做负载均衡损失计算，只运行 top-1 路由、关键帧续写、一次插值和 VQ 解码。模型仍需要外部提供本块目标音频；TTS、网络传输、渲染、头像重定向和音视频播放调度没有被证明全部包含在其 GPU 推理指标内。

### 消融实验

**只缩短为自回归块并不够（Table 3）：** 从移除全部组件的基线出发，只加入 AR 后，FGD 从 5.81 恶化到 6.810；加入 MoE 的 AR 版本为 6.434。AR、关键帧和插值共同使用时为 5.331，再加入 MoE 后为 5.107。它支持组合设计能缓解短块预测的质量损失，不支持“使用自回归本身就让质量变好”。

**独立插值器不是可有可无的平滑后处理（Table 3、5）：** 无 AR、无 MoE 的关键帧版本，加入学习插值器后 FGD 从 5.607 降到 5.196。Table 5 在 s=6 下，线性插值为 5.90，学习插值为 5.107；但 BC 从线性方案的 8.01 变为 7.955，不能说每一指标都提高。

**关键帧步长与响应存在取舍（Table 6）：** 以下均为学习插值网络，按原表精确数值保留。

| stride 与预测块 | FPS ↑ | TTFF ↓（ms） |
| --- | ---: | ---: |
| s=4，N=5 | 31.54 | 811 |
| s=6，N=5 | 43.82 | 826 |
| s=8，N=5 | 57.41 | 817 |
| s=6，N=2 | 27.33 | 540 |

更稀的锚点能提高吞吐，却没有让首帧时间按相同比例缩短；把 N 从 5 降为 2，首帧更快，但持续吞吐反而下降到 27.33 FPS。对 30 Hz 动作，这个更短响应配置不能仅凭 TTFF 就宣称已经稳定超过实时播放速率。

**三阶段训练各有作用（Table 4）：** 去掉预训练，FGD／BC 从完整模型的 5.107／7.955 变成 5.920／6.572；去掉后训练第一阶段为 5.422／7.416；去掉第二阶段为 5.137／7.834。第二阶段对这两项质量分数的增益较小，其主要作用是适配分块推理；同时完整模型的 Diversity 14.75 并没有高于三个删阶段版本，不能把阶段收益概括成所有指标单调改善。

**音频增强有真实代价（Table 1–3）：** 增强让 Diversity 从 14.75 升到 16.77，人评偏好名次从 3.23 改善到 1.78；但 FGD 从 5.107 升到 5.368、BC 从 7.955 降到 7.787，在原测试分布上两项都退步。作者希望获得更广的声学适应与表现力，这个目标不能替代对实际指标方向的如实呈现。

**主要时间消耗仍在语言模型解码（Table 7）：** 默认 N=5 的一次前向总耗时为 818 ms，其中 decoder 因果注意力 371.1 ms、MoE FFN 232.3 ms、其他解码路径 176.6 ms；插值仅 6.5 ms。N=2 的前向总时间为 532 ms。它们与 Table 6 的 TTFF 826／540 ms 是不同测量项，不能混写为同一个数字。单独把插值器做得更快，不会消除主要的顺序解码等待。

### 关键发现

1. **相对同路线 LoM，UMo 的价值是更好的质量—时延折中。** 主表 FGD 由 5.301 到 5.107，FPS 由 19 到 44，TTFF 由 6269 ms 到 826 ms；但 GestureLSM 的 FGD 4.247、速度 411 FPS 和 TTFF 275 ms 仍更好，MambaTalk 更快。这里不是所有方法、所有指标的全面第一。
2. **吞吐、首帧等待和音频可用时间必须一起理解。** 约 44 FPS 表示一张 A100 上的计算吞吐超过 30 Hz 动作速率；它没有消除约 0.8 秒首帧等待，也不包含尚未来到的目标音频需要等待多久。N=2 则表明更小窗口可能用持续吞吐换首帧响应。
3. **多样性改善和真实分布拟合并不总同向。** 音频增强的人评很好，但 FGD、BC 退步；不增强的 UMo 平滑度名次 3.54 还差于 LoM 的 3.17 和 GestureLSM 的 2.72。保留这些差异，才能看清主干、插值和数据增强分别解决什么。
4. **初始状态与演示范围是结论的一部分。** 测试首块用 10 个真实关键帧作为前缀，不是从空历史完全自主启动；图 7 的额外头像展示由女性数据训练，并注明面部表情没有同步。这张重定向演示不能作为端到端口型同步已验证的证据。

## 亮点与洞察

- **把重模型放在时间结构的骨架上：** 语言模型负责稀疏锚点，轻模型负责密集补全。加速来自减少顺序决策次数，而不是单纯压缩输出动画帧数，因此最终仍可输出连续高帧率动作。
- **容量与激活计算分开设计：** 动态专家使不同上下文有更多可选择的参数，同时每个 token 只执行一条前馈专家路径。它比“脸一个模型、手一个模型”的硬拆分保留了更多共享注意力与跨部位交互。
- **表示复用与新建主干职责明确：** 冻结 LoM 的 VQ 动作表示，把优化重点放在生成器的容量、时间结构和任务训练上；有利于分析改进发生在哪一层，而不把 tokenizer 与生成器变化混在一起。
- **时延报告区分了多个实际量：** FPS、TTFF、组件级前向耗时与 N=2／N=5 比较揭示了固定开销。它提醒系统设计者：更短块并不自动代表更高吞吐，实时角色需要同时安排计算与播放缓冲。
- **多音色对应同一动作是一种数据关系改造：** 这类增强的关键不只是“多了五倍样本”，而是主动改变模型可以依赖的相关性，让音色成为不应过度绑定动作的变化因素。

## 局限与展望

1. **当前仍依赖目标窗口音频。** encoder 使用历史和目标音频，插值器也在完整当前窗口内双向处理。用于现场语音交互时，需要计算之外的音频缓冲或预测策略；不能只据自回归 decoder 就称整个系统零前视。
2. **首帧等待尚未很低。** 默认 TTFF 为 826 ms，较短块可降为 540 ms，但吞吐下降。主要瓶颈在顺序 token 解码，MoE 并没有让高层语言模型变成一个毫秒级动作控制器。
3. **锚点错误与块边界会传到密集动作。** 原文明确指出，预测关键帧的错误可能影响整个插值区间，任意分块边界也可能损伤长时间一致性。固定历史和 token 锚点并不等于连续坐标、速度和接触的严格保持。
4. **统一训练的能力范围需要独立验证。** 音频到动作与文字到动作混合训练，不等于任意组合文字条件、实时音频、用户关键姿势和场景目标都能同时满足；论文也没有给出音乐舞蹈、精确源动作编辑或对象指向控制的对应验证。
5. **主体评估仍集中于单说话人。** BEATv2 全库规模不能代替 speaker-2 主表的实际设置。域外音频人评只有 13 名参与者和 10 组片段，未报告显著性检验；多音色增强也不是新增多人的真实动作采集。
6. **脸部与头像演示证据不足以覆盖所有输出要求。** 主表没有独立的面部/口型同步分数，额外头像图还明确注明表情未同步。用于具体角色时仍需检查重定向、表情、音画同步及最终连续动画质量。
7. **部分复现细节尚不完整。** 主干和插值器的分工清楚，但训练数据的完整清单、任务采样比例、音频增强时间对齐及若干时窗术语没有充分消歧。没有公开实现与实际运行核验时，不能把这些未说明部分自动补成确定流程。

## 相关工作与启发

- **[The Language of Motion（LoM）](https://openaccess.thecvf.com/content/CVPR2025/html/Chen_The_Language_of_Motion_Unifying_Verbal_and_Non-verbal_Language_of_CVPR_2025_paper.html)（CVPR 2025）：** UMo 继承其文本、音频与四部位动作 token 的统一路线，并明确复用其冻结 VQ-VAE。新增重点是 T5 的稀疏专家、关键帧与分块实时化；不是同一论文换名，也未证实直接从完整 LoM 语言模型权重继续训练。
- **[GestureLSM](https://arxiv.org/abs/2501.18898)：** 同样处理跨部位协调和共语生成效率，通过时空建模与 latent shortcut 路线减少生成开销。UMo 把计算重点放在统一语言模型的稀疏 token 生成；两者在本文表中呈现 FGD、节拍、多样性和速度上的不同取舍。
- **[MIBURI](https://openaccess.thecvf.com/content/CVPR2026/papers/Mughal_MIBURI_Towards_Expressive_Interactive_Gesture_Synthesis_CVPR_2026_paper.pdf)（CVPR 2026）：** 使用语音—文本基础模型的条件和分部位动作编码进行在线生成。UMo 的动作 token 直接通过统一 T5 推理栈产生，再补全关键帧；它实际使用目标音频窗口，不能因都采用自回归就抹平因果条件的差别。
- **[Rhythmic Gesticulator](https://arxiv.org/abs/2210.01448)（SIGGRAPH Asia 2022）：** 它按语音 onset 组织动作块与词元，而 UMo 按固定 stride 组织关键帧 token。前者的节奏分块与后者的时间降采样并非同一种中间表示，两者都需要把时间指标与语义正确性分开评估。
- **启发：** 设计实时角色生成系统时，可以让昂贵模型负责较低频的联合决策，让轻模型负责密集实现；但需要同时说明高层条件能看到多远的音频、锚点如何保持、第一段如何启动，以及密集输出最终是否满足同步与接触要求。内部稀疏关键帧提供的是计算结构，不自动成为用户可编辑的语义计划或物理约束接口。
