## 一句话总结

MaDiS把“书面句子→手语动作”改写成**同时看前后文、逐轮填充缺失手语token**的问题，并用token、连续码本特征和动作重建三层监督进行预训练；随后通过分阶段补齐时间网格和动态融合身体/双手信息，提高生成质量与推理效率。[作者稿图1–4、§III][paper]

它的关键是让离散预测受连续动作结构约束，并缩小解掩码顺序的选择空间。手语token仍是从动作学到的码本索引，既不是可读gloss，也不是LLM先写出的可执行手语语法。

## 研究背景与动机

**领域现状：** 手语生成既有“文本→gloss→动作”的级联路线，也有直接从文本生成动作的gloss-free路线。SOKE等方法把身体、左手、右手分别压缩成离散token，再使用自回归语言模型生成；这使语言建模方法可以复用到手语动作上。[§I–II][paper]

**现有痛点：** 从左到右逐个生成时，当前动作只能依赖已经生成的片段，无法直接利用后续已确定的动作上下文；长序列还要执行多次串行预测。另一方面，仅训练token分类，会忽略“两个token不同，但它们对应的动作可能相近”这类连续几何关系。

**核心矛盾：** 手语需要同时协调句子语义、跨时间的动作连接、双手主次和身体姿态；单一的token损失与固定生成顺序，难以充分利用这些不同层次的信息。直接放开所有解掩码顺序又会显著扩大训练要覆盖的状态空间，导致收敛更慢。

**本文目标：** 在不依赖额外手语词典或输入gloss的设定下，由书面文本生成具有语义可理解性、较准确手型和较低延迟的三维手语动作，并提供更合适的互补评测指标。

**切入角度：** 将预训练Qwen3改为双向注意力的掩码扩散模型；既预测离散token，也预测其连续码本特征与解码动作。微调时先建立稀疏、覆盖整段的时间网格，再逐渐补密，同时根据动作内容调整身体和双手特征的权重。

**核心 idea：** 冻结已有的三部位动作tokenizer，以三层损失适配语言模型；保持文本可见，用时间检查点限制动作token的解掩码顺序，再用MoP门控融合三个部位的码本向量，最后经原tokenizer解码器输出连续手语动作。

## 方法详解

### 整体框架

训练数据先经过SOKE的部位化tokenizer，得到与书面文本配对的三个token序列。预训练时文本和动作都可能被遮盖，模型同时学习离散分类、码本向量预测和连续动作重建；微调时保持文本完整，加入UTC与MoP。推理从整段全mask动作开始，以由稀到密的时间顺序恢复token，三个部位同步更新，再由冻结的VQ-VAE解码器重建动作。[图2–4、算法1、§III][paper]

### 关键设计

1. **三部位tokenizer：同一个时间位置承载身体、左手与右手。**

   作者复用SOKE的三个并行VQ-VAE，分别负责上身（包含面部）、左手、右手。输入为T×133的SMPL-X表示：11个上身相关关节、30个手部关节的旋转参数，加10维表情参数。下采样倍率为4，因此400帧对应100个token时间位置，每个位置有三个部位ID。[§III-A][paper]

   三路token不是串成300个逐部位位置；在同一个时间索引被选中时，三个部位一起mask、一起恢复。输出端根据三个ID分别查码本，再用三个解码器组合成动作。这样保留了手指表示的专门容量，同时让生成器在统一时间轴上建模身体和双手。

   **这个表示没有gloss监督，也不保证一个ID对应一个固定手语词。** 同一个词的不同执行方式可能量化为不同ID，这是作者讨论SiBLEU局限时明确指出的问题。[§V-B][paper]

2. **掩码扩散语言模型：以双向上下文填空，而非从左到右续写。**

   MaDiS以Qwen3-0.6B-Base初始化，将每层的因果注意力改成非因果注意力。前向过程按噪声比例t把位置替换为mask；反向过程利用当前可见位置预测缺失token，并在一次网络调用中恢复多个时间位置。式1中，某个位置被mask的概率是t，保持原token的概率是1−t。[§III-A、式1–3][paper]

   因为模型预测的是“给定可见token，缺失位置是什么”，基础MDLM不必额外接收连续扩散时间作为输入。token交叉熵在被遮盖的位置计算，并按1/t加权。**已经恢复的token在这一采样定义中保留，不会每轮全部重新生成**；双向注意力允许利用前后可见上下文，却不等于任意已提交错误都可以反复重写。[式2–3；采样实现][sampling]

3. **三层跨模态预训练：分类正确之外，还要接近可解码动作。**

   预训练把文本、结束符、手语token与结束符组合成序列，并同时随机遮盖文本和动作。三个目标分别提供不同监督：

   - **Token层：** 恢复被遮盖的文本及三个部位token，学习跨模态对应。
   - **Latent层：** 从动作位置的隐藏状态经过三个MLP，预测对应部位的512维码本向量，以smooth L1约束其与真实码本特征接近。
   - **动作层：** 把预测的连续特征送入冻结的三个VQ-VAE解码器，以重建动作与真实动作的差异监督模型。

   作者更新稿式4–6可概括为：**Lpre = Ltok + Llat + Lphy**。Latent误差针对被遮盖的有效动作位置；动作重建使用完整预测特征序列。后者让梯度穿过冻结解码器到达语言模型，解码器本身不重新训练。[式4–6；训练实现][training]

   “Physical space”在这里指连续动作表示的重建层级，**不是物理仿真、接触约束或动力学可行性求解**。源码对应的是解码后动作特征的重建误差，不能据此宣称没有穿插或手型一定具有语言学正确性。

4. **UTC时间检查点：先覆盖全句，再填时间间隙。**

   普通置信度解掩码会在所有未生成位置中挑选最有把握的k个；哪些位置先生成的组合数非常大。UTC将反向过程分成三个阶段：在t=0.75时形成每4个位置取1个的均匀网格，在t=0.5时形成每2个位置取1个的网格，最后补齐剩余位置。每个阶段内部仍按置信度选择。[图3、算法1、式7–8][paper]

   用0起始位置解释：第一阶段只允许生成{0,4,8,…}；第二阶段保留这些位置，加入{2,6,10,…}；第三阶段再补奇数位置。模型不是先从句首生成连续的四分之一段，而是先形成横跨整句的稀疏上下文。训练时也按同样网格构造mask，使训练状态与推理过程对应。

   论文以M=100、每步约恢复4个位置为例，估计候选顺序减少超过10<sup>41</sup>倍。**这是组合数量的缩减，不是计算量或运行速度提高10<sup>41</sup>倍。** 检查点不整除步长时，作者注明阶段末轮可恢复不足k个的位置；具体轮数还受实现的取整与调度影响。

   UTC的“关键点”只是时间网格上的内部token，不是检测出的语义事件，也不是外部可编辑的关节关键帧。它没有直接提供“第2秒完成某个手势”的硬控制。

5. **MoP部位融合：在输入嵌入中学习身体与双手的贡献。**

   简单平均三个部位的随机初始化嵌入，会忽略已有码本中的动作结构，也无法区分单手和双手手语。MoP先分别读取三个已训练码本向量，再通过线性层对齐语言模型维度；另一个MLP读取三者拼接，经过softmax输出三个权重，最后求加权和。[图4、式9][paper]

   简化表达为**E = gb·Eb + gl·El + gr·Er**，三个权重之和为1。它是一个稠密的部位融合层，身体和双手都参与计算；不是给每个Transformer块增加一个大型稀疏专家系统。门控控制的是输入特征贡献，不是把输出动作按权重混合，也不是用户可直接设置的手部控制开关。

   预训练阶段使用平均嵌入，微调阶段启用MoP；公开实现对有效三码本ID使用门控融合，对mask等特殊位置回退到普通嵌入平均。微调仍保留连续监督：**Lsft = Ltok + α(Llat + Lphy)**，默认α=0.5。[式10；嵌入实现][embedding]

6. **互补评测：姿态距离、token重叠与语义检索分别衡量不同东西。**

   DTW-JPE先做动态时间规整，再比较关节位置，可以容忍生成长度差异；作者不使用Procrustes旋转对齐，以免把真实姿态差异消去。SiBLEU将手语token序列与参考token比较，Body单独计算，Hands取左手与右手分数均值；论文采用SiBLEU-4。SiCLIP则另外训练动作—文本共同嵌入模型，以生成动作检索对应句子的R@1评估语义相关性。[§III-D、§IV-A][paper]

   SiCLIP使用三个部位动作编码器、多语言文本编码器及细粒度对比学习；它是独立评测器，**不在动作生成推理链中**。这些指标互补，但都不能单独证明每个词的手型、句法与面部非手动成分均被正确表达。

### 一个完整例子

以作者图5中的中文句子“**吃完午饭要多吃点水果。**”为例，下面展示数据流；网格位置说明属于教学示意，不添加论文未提供的词到动作精确对齐。

1. **文本输入：** 句子经过Qwen分词，作为完整可见的条件；不要求先生成gloss或查询手语词典。
2. **初始化：** 建立100个动作时间位置，身体、左手、右手都处于mask状态。100是生成容量上限，不意味着句子必须恰好输出400帧。
3. **稀疏到密集恢复：** 先在每4个位置取1个的网格上恢复高置信度位置，三个部位同步产生ID；之后扩展至偶数网格，再填剩余位置。已经出现的部位ID通过MoP影响下一轮的双向上下文。
4. **判断长度：** 生成结束符后截断其后的部分。当前公开实现以身体流的首个EOS作为三个流共同的边界。
5. **连续解码：** 三路token经各自码本与解码器还原为手语动作参数，拼接身体、双手及表情，再驱动SMPL-X角色显示。这里的连续动作由VQ-VAE解码器产生；语言模型本身输出的是离散ID。

作者图5展示与真实动作、SOKE结果的视觉对照，但没有给出此句每个时间位置对应哪个词的标注；不能把网格阶段解释为“先完成午饭，再生成水果”的显式语义计划。[图5；解码入口][decode]

### 训练/推理

**训练数据：** CSL-Daily约20K对中文文本/中国手语样本，Phoenix-2014T约8K对德语文本/德国手语样本，How2Sign约35K对英语文本/美国手语样本。动作来自SOKE整理的SMPL-X姿态。先混合三个训练集进行预训练，再分别在各数据集微调，因此是**共享预训练、数据集专门微调**；不能把三个评测结果说成同一最终权重零样本覆盖三种手语。[§IV-A–B][paper]

**模型与优化：** 主干为Qwen3-0.6B-Base，隐藏维度1024；码本向量512维。文本与动作监督仍依赖配对数据，复用tokenizer也带有既有训练知识。两阶段均采用AdamW、初始学习率2×10<sup>−4</sup>、cosine调度、每GPU batch size 64；预训练200 epochs，微调150 epochs，使用4张NVIDIA GH200。tokenizer保持冻结，语言主干与新增映射/门控模块参与训练。

**推理设置：** 作者默认25轮、最多100个动作时间位置，对应解码后最多400帧，覆盖约98%的训练视频；更长训练样本均匀采样到400帧。推理既不是语音同步流式系统，也没有输入事件时间戳；完整文本与整段mask共同参与双向计算。

### 关键发现

1. **主要质量增益来自整套适配，而不是只换成双向attention。** MDLM baseline已能提高吞吐和部分语义指标，但How2Sign的Hands DTW为10.16，略差于SOKE（Qwen3）的10.09；完整MaDiS才降至9.45。不能把所有增益都归因于并行采样。
2. **速度与质量需要共同看。** 完整MaDiS吞吐132.97低于简单MDLM的134.17，但质量更好；约40%的吞吐提升是相对启用KV cache的SOKE，不能把它写成“减少40%延迟”。
3. **有连续监督的离散生成更有效，但不构成物理保证。** 由token监督加入latent、动作重建后，CSL R@1从34.76升至38.61；这是数据分布内的质量提升，不是接触、碰撞或每个手语符号均正确的证明。
4. **人工评价仍有明显差距。** MaDiS在CSL评分6.9优于SOKE的4.6，但低于真实动作8.4；三种手语数据集和8位专业参与者的结果不足以代表全部手语社区或实际辅助交流的可靠性。

## 亮点与洞察

- **把token预测落到连续表示：** 码本特征与冻结解码器为语言模型提供比离散分类更细的训练信号。这一思路可以迁移到其他动作token模型，但应保留重建表示与真实几何/物理约束的区别。
- **把生成顺序作为可设计对象：** UTC通过时间网格约束减少无必要的解掩码组合，并保持整段上下文覆盖；它的价值在于训练分布与采样策略配合。
- **部位结构进入输入层：** MoP利用已学到的部位码本和小型门控网络，而不是假设三个身体部位在每个时刻同等重要。
- **评测贴近任务语义：** 作者同时报告动作距离、token重叠、文本检索和专业手语使用者评分，避免只靠一种姿态误差定义生成成功。
- **更新稿提供具体成本：** 预训练、各数据集微调和推理成本分开披露，便于估计复用已有主干/tokenizer后所需的适配预算。

<span id="reading-6" class="reading-anchor"></span>
## 局限与展望

- **token不是稳定的手语语义单元。** 量化主要依据动作，同词不同执行可能映射为不同ID；SiBLEU可能因此低估语言正确的结果，也会受到tokenizer选择影响。作者将更鲁棒的tokenizer列为后续方向。
- **时间容量和输入模式受限。** 默认100个位置/400帧，长样本被压缩；没有验证连续长篇翻译、实时增量文本、语音到手语或用户精确指定动作事件时间的控制。
- **三种手语不是普适多语言能力。** 预训练融合三数据集，最终分别微调。Qwen的语言覆盖不等于模型已学会同样数量的手语。
- **评价具有模型依赖与样本范围。** SiCLIP由同一研究中的训练数据训练；SiBLEU依赖码本，DTW允许时间对齐。专业评估覆盖CSL与ASL的小样本，仍需更广泛的语言学错误分析和社区评估。
- **几何重建监督不等于动作执行约束。** 论文没有碰撞检测、接触求解、机器人控制器或保持指定身体区域不变的编辑机制。用于交互avatar时，还需要独立处理角色重定向、手型细节与显示质量。
- **当前发布代码与论文评测有差异。** 尤其是SiBLEU计算口径需要对齐后才能谈原表复现；本次仅核对公开实现，没有进行模型运行验证。

<span id="reading-7" class="reading-anchor"></span>
## 相关工作与启发

- **[SOKE：Signs as Tokens][soke]：** MaDiS直接复用其三个部位tokenizer与整理的动作数据，并将生成器从自回归改为双向掩码扩散。SOKE还使用外部手语词典，MaDiS的生成设定不依赖该额外输入。
- **[Large Language Diffusion Models][llada]：** 提供从掩码状态恢复token、双向建模与并行解掩码的基础。MaDiS增加了手语特有的连续监督、时间网格和部位融合，并不是仅将动作ID加入现成文本模型词表。
- **[MoMask][momask]与[SnapMoGen / MoMask++][snapmogen]：** 都使用掩码动作生成，但任务、tokenizer和训练目标不同。MaDiS表III中的MoMask++是作者适配到手语数据上的比较，不能直接与HumanML3D文本动作排行榜互换。
- **[SignCLIP][signclip]与[CiCo][cico]：** 提供动作—文本对比学习和细粒度语义对应的相关思路。MaDiS把SiCLIP用于生成结果的互补评估；检索高分仍不等于每个手语动作都已正确执行。
- **启发：** 对动作token模型，可以分别设计“离散序列如何恢复”“连续解码是否合理”“任务语义如何验收”。这三层互相帮助，但不能互相替代；若要加入可执行动作控制，还需明确的控制字段、约束与最终测量。
