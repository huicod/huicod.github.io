## 一句话总结

TMR 学习把动作描述和一整段三维人体运动放进同一个向量空间。训练时，表示既要识别同批中配对的文字和动作，也要保留足够信息以重建运动；检索时，只需给查询编码、与预先存好的库向量比较，便能返回最相关的真实片段。

## 研究背景与动机

**领域现状：** 动作生成研究需要衡量“做的动作和文字是否相符”，已有工作会用文本或动作为查询，在几十个候选中找回其配对项。真正为动画师搜索已有动作时，候选库常大得多，返回什么、排在第几直接决定这个系统有没有用。

**现有痛点：** “向前迈一步再倒立”和“做侧手翻”都有手支撑身体的时刻。只学会从描述生成大致合理的动作，并不必然能把正确片段排在几千个相近动作之前。

**核心矛盾：** 用库中其他动作作为负例能学会区分相似片段，但不同人可能用不同文字描述同一种动作。若把“向左转”和“逆时针转”一概推远，模型会奖励不重要的措辞差异。

**本文目标：** 建立两种对称的检索任务，既能用自然语言找动作，也能用动作找已有描述。用不同库规模和匹配标准检查表现，再检验同一个模型能否在长动作中找出某一小段。

**切入角度：** 在 TEMOS 的动作合成框架中保留生成所需的细节，同时加入跨模态对比学习，让语义相合的文动对排在其他候选之前。

**核心 idea：** 编码器为每段运动和每句描述输出一个向量。用检索损失教它“与谁相配”，用动作重建教它“配对里具体做了什么”，训练时借助另一套句子表示跳过可能被误标为负例的配对。

## 方法详解

### 整体框架

一条训练样本包含动作帧序列及其描述。两个独立 Transformer 将两种输入各自编码到共享的连续空间，然后进入两条并行训练支路：双向匹配和共用解码器的动作重建。实际文搜动作时，数据库只需提供动作向量，无须为候选读取文字或重新生成动作。把图中查询端和建库端调换，就得到动作搜文。[正文 §3、图 2][paper]。

### 关键设计

1. **用分开的编码器建立可预计算的索引。**

   文字经过冻结的 DistilBERT 得到每个词元的特征，再进入可训练的文本 Transformer。动作则从连续帧特征进入独立的运动 Transformer。实验沿用 Guo 等人的运动表示，包括局部关节位置和速度、根节点运动以及足部接触等。训练中对左右动作和文字同时镜像，避免只镜像骨架却仍用原先的“左手”描述。[正文 §3.1–3.2、§4.1][paper]。

   两个编码器分别读出高斯分布的均值与方差信息，训练从分布中采样 256 维潜向量，检索直接采用均值。把所有库动作提前编码一次，查询来的时候只需要运行文本编码器和向量相似度计算。这个向量概括整段运动，一个位置没有对应某个指定关节、某个动作码或某个时间点的固定解释。

2. **同一个动作解码器要能从两种条件重建动作。**

   同批中某个样本可以走两次解码：一次用文本向量，要求输出配对动作；一次用动作向量，要求还原输入自身。解码器拿到潜向量与目标时间位置编码，一次性预测所需长度的动作帧。两种结果都和同一条真实序列比 smooth L1。另有模态间潜向量的 smooth L1 距离，以及四项 KL，用于将两种分布分别靠近标准正态、并在两个方向互相靠近。[正文 §3.2][paper]、[训练损失代码][losses]。

   这给检索表示增加了另一种压力。只记住“倒立”也许足以从一批走路样本里认出目标，但重建“先向前走，再倒立”还需要描述中的准备动作。实验可以检验加重建后检索是否改善，不能据此认定每条描述的各个事件都已在潜向量中单独定位。

3. **双向对比，让文字找动作和动作找文字一起受训。**

   对批中的 N 条配对样本构建 N×N 矩阵，每个元素是第 i 句描述与第 j 段动作的余弦相似度。沿每行做一次交叉熵，正确目标是本句配对的动作；沿每列再做一次，正确目标是本段运动的文字。两个方向取平均即式 1 的对称 InfoNCE。温度控制那些很相似的竞争者会多大程度主导梯度。[正文式 1][paper]。

4. **通过句子相似度跳过疑似假负例。**

   计算两个样本的完整描述在外部 MPNet 句向量空间中的相似度。超过训练阈值 0.8 的非对角组合，从对比损失的竞争项中排除。两条原始文动对各自的重建仍然保留。近义句仅提供“不宜强行拉开”的线索，训练并没有把所有这类配对宣布为正确动作。[正文 §3.3、图 2][paper]。

   这里有三个容易混淆的分数。DistilBERT 的词特征喂给可训练的检索文本编码器，MPNet 的句间相似度只辅助识别描述之间的近义关系，实际检索则用 TMR 的文动向量相似度。仓库将文中 0 到 1 尺度的阈值 θ 换算为原始余弦的 2θ−1。因而“阈值 0.8”不能直接读成“原始余弦 0.8”。[过滤实现][filter]。

5. **长动作中的时间定位来自滑窗检索。**

   用一句动作描述，和一条长运动的多个局部窗口分别算分。逐帧中心的 20 帧窗给出一条时间相关曲线。定量实验还用 10 至 60 帧的多尺度窗口、以 5 帧为步长，在全部位置和长度中取分数最高的一项，再与标注区间计算时间 IoU。模型用 HumanML3D 训练，把它直接用在 BABEL，训练时没有为这个定位任务提供边界。结果反映一个局部窗口与请求吻合的程度。[正文 §4.5、图 4][paper]、[补充 §B、图 A.1–2][sup]。

### 一个完整例子

正文图 3 用“向前迈步，然后倒立”的描述检索 HumanML3D 测试库。这里能跟着原图走完查询和核对的全过程。

1. **先建库。** 对测试集中每个现有片段，仅把运动帧送入运动编码器，保存均值向量和片段 ID。它们的真实文字供事后验收，不参加候选动作编码。
2. **输入查询。** 把描述变成词特征，再经文本编码器得到均值向量。它只有一份，可与几千个预编码动作依次或批量比较。
3. **按相似度排序。** 原图前五名显示的相似度分数依次为 0.82、0.68、0.61、0.48、0.42。第一名确实是走一步再倒立。第二、三名包含侧手翻，两手短暂撑地使其在动作上与倒立共享一些特征。
4. **看清返回结果。** 点击第一名得到的是库里已有的三维运动。系统没有在查询时把“走”和“倒立”生成两个片段再拼起来。若要问倒立在一段长录像的哪一时刻发生，需要切换到滑窗检索，并用时间标注检验位置。[正文图 3–4][paper]。

### 消融实验

KIT-ML 宽松全库协议 b。正文表 3（p. 9493），为紧凑起见，每格依次写 R@1、R@2、R@3（%，↑）和 MedR（↓）。

| 重建 | 对比目标 | 文搜动作 | 动作搜文 |
|---|---|---|---|
| 否 | Margin | 15.06 / 22.17 / 25.78 / 12.00 | 8.19 / 11.57 / 16.39 / 19.50 |
| 否 | InfoNCE | 19.76 / 25.30 / 36.87 / 6.00 | 17.47 / 19.76 / 30.60 / 9.50 |
| 是 | 无 | 18.55 / 24.34 / 30.84 / 7.00 | 17.71 / 22.41 / 28.80 / 13.25 |
| 是 | Margin | 19.88 / 24.46 / 34.46 / 7.00 | 14.70 / 19.76 / 28.19 / 12.50 |
| 是 | InfoNCE | **24.58 / 30.24 / 41.93 / 5.00** | **19.64 / 23.73 / 32.53 / 9.50** |

**重建是否值得保留。** 从单独 InfoNCE 到两者联合，文搜动作 R@3 从 36.87 升到 41.93。删掉合成分支时作者还改为单个确定性向量，故对照同时涉及表示参数化。联合配置中的 InfoNCE 优于 Margin 的 41.93 对 34.46 是 **R@3**，正文一处写成 R@1，与表头冲突。

**训练过滤与温度。** 完整模型在不使用负例过滤时文搜动作 R@3 为 36.02，阈值 0.8 时为 41.93。此阈值在 KIT 每批平均剔除 17.29% 的负对。温度从 0.1 增到 1.0 时，文搜动作中位排名从 5.00 变成 306.5。反向检索部分指标反而偏好温度 0.01。批量 16 的文搜动作 R@1 也略高于 32，且实验会随批量成比例调整学习率。[正文表 4–5][paper]、[补充表 A.1][sup]。

### 关键发现

1. **54 到 19 有特定前提。** 摘要举例的中位排名改善出现在 HumanML3D 全库、允许文字近义匹配的协议 b，比较对象是 Guo 等。严格协议 a 则是 81 到 28；只看 32 项的成绩会高估真实搜索难度。
2. **改进并不覆盖每列。** KIT 严格全库动作搜文，TEMOS 的 R@1 为 11.69，TMR 为 11.20，R@3 两者同为 20.12。两套数据的小批协议中，Guo 等部分 R@10 也较高。TMR 最稳健的收益体现在多个库规模下的整体排名。
3. **长片段能粗定位，边界精度另算。** BABEL 的多尺度窗在时间 IoU 阈值 0.4 下约 20% 定位正确；固定 20、40、60 帧分别为 17%、19%、14%。这些数字比单幅相似度曲线更能刻画限制，也说明有必要把片段检索与时间边界验收分开。[补充 §B、图 A.1][sup]。

## 亮点与洞察

- **把图库难度写进实验。** 从随机 32 项换成几千项，错误会从“动作大类不对”转变为“非常像但不是配对的那一条”。四档设置让这两种使用场景可区分。
- **用动作监督教检索器留住细节。** 训练时多付一次重建代价，查询时仍只需一次编码与索引比较。共享空间能否用于检索，由消融和真实图库排名共同检验。
- **保留可疑负例的原始监督。** 文本间相似只能提示标注歧义。将该交叉项跳过，同时继续重建两条原样本，比无条件将近义文本认作完全相同的运动更谨慎。

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

- **描述的分辨率有限。** 同样是倒立，进入动作可能完全不同。一个整段余弦分数不揭示“先迈步”或某侧肢体是否做对。需要这些细节时，要另加局部运动或事件检验。
- **图库和模型都有覆盖范围。** 一条陌生查询只能从现有片段中取近邻，编码器也由规模有限的动捕语料训练。原文提到大规模库的向量内存开销，并提出分层索引作为方向。
- **定位依赖候选窗口。** 固定或枚举窗容易漏过短时发生的动作，长段中的多个相似动作还会产生多峰。专用边界预测或更好的时段提议是原文给出的后续方向。
- **检索器会影响对生成质量的判断。** 同模型自评分数高于独立评估器时，解释新生成方法的结果需要注明采用哪个编码器、骨架表示、图库和评分协议。

<span id="reading-7" class="reading-anchor"></span>

## 相关工作与启发

- **[TEMOS](https://mathis.petrovich.fr/temos/)** 为 TMR 提供概率双编码器和动作解码器。TMR 保留合成监督，并额外学习区分负配对，使空间更适用于排序。
- **[Generating Diverse and Natural 3D Human Motions from Text](https://openaccess.thecvf.com/content/CVPR2022/html/Guo_Generating_Diverse_and_Natural_3D_Human_Motions_From_Text_CVPR_2022_paper.html)** 提供 HumanML3D、动作特征和生成任务的配对评估背景。TMR 将检索独立成任务，并同时测量大库严格匹配、近义匹配和小批协议。
- **[TMR-SOMA-RP-v1][soma]** 是后续在 Bones Rigplay 数据与 SOMA 骨架上训练的模型，服务于 Kimodo 等方法的评价。虽然同样输出文动向量，输入运动表示与训练分布已有变化。
- **启发：** 检索向量可以先为某种动作建立候选集。若任务还要求“在第几秒、哪只手、做到了什么”，应再看候选内的时间和身体局部证据，不能把 R@1 或高相似度当作这些条件的逐项验收。
