## 一句话总结

**TM2D 先让音乐—舞蹈数据与文字—动作数据共用一套离散动作词表，再训练音乐和文字两条条件路径共享动作解码器；推理时只在用户指定的时间窗内混合两条路径的隐藏特征，让角色跟着音乐跳舞，同时插入“侧手翻”“转圈”等文字要求。** 它不需要音乐、文字、动作三者同时配对的训练集，时间窗则由用户提供。[§3、图2–3][paper]

## 研究背景与动机

**领域现状：** 音乐驱动舞蹈模型可以从节奏与声学特征生成身体运动，文本到动作模型则能把“跳跃”“旋转”等语言映射为姿态序列。二者已有各自的数据集与评价体系，但在音乐里指定一个动作、并决定它何时发生，仍需要把两类能力连接起来。[§1–2][paper]

**现有痛点：** 一段音乐可以对应许多舞步，却不会直接告诉模型“6–8秒做侧手翻”。只换音乐难以获得想要的动作；把独立生成的文字动作直接插进舞蹈，又可能造成过渡突兀，或让音乐节奏被打断。[图1、§4.2][paper]

**核心矛盾：** 用户希望同时使用音乐和动作文字，但现成数据主要是 AIST++ 的音乐—舞蹈对与 HumanML3D 的文字—动作对。直接联合训练还面临舞蹈和日常动作分布不同的问题，缺乏三模态监督也使“如何融合”难以直接从配对样本学习。[§1、§3.2][paper]

**本文目标：** 在不额外采集大规模三模态配对数据的情况下，让一套生成框架同时接受音乐与文字，并允许用户指定文字作用的开始时间和持续时间，同时保留单独使用音乐或文字的能力。[§3.1、§4.4–4.5][paper]

**切入角度：** 先解决输出空间不一致：把两套数据的运动编码成同一个码本里的 token；再让两个条件任务共用动作解码器，使两条条件路径最后得到的特征具有可组合的接口。[§3.2–3.4][paper]

**核心 idea：** 训练时分别学习“音乐→动作 token”和“文字→动作 token”；推理时按时间窗构造文字权重，把同一动作历史下的两条隐藏特征做加权和，再预测下一个动作 token。窗口边缘平滑提高、降低文字影响，而连续自回归生成负责把新动作接进舞蹈。[图2–3、§3.4][paper]

### 关键设计

1. **用共享 VQ-VAE 给两套动作数据建立同一个输出词表。**

   输入运动 M 先经过一维卷积编码器，在时间上压缩，再对每个潜向量寻找最近的码本向量。最近向量的索引是动作 token，查表后的向量则送入卷积解码器重建运动。训练同时使用两套数据的动作，损失包含 L1 重建、码本学习和 commitment 项；量化采用直通梯度估计。[§3.2、式1–3][paper]

   <div class="equation">z = Encoder(M)，kᵢ = argminⱼ ‖zᵢ − eⱼ‖<br/>M̂ = Decoder(e[k₁], e[k₂], …)</div>

   这里 kᵢ 是码本索引，**不是“侧手翻第几阶段”之类的人工语义标签**。正式设置时间下采样8倍，码本有1,024个向量；补充材料将两套数据统一到60 fps，所以一个潜在时间位置对应8个原始帧的采样间隔，但卷积感受野并不因此只包含独立的8帧。[§3.5、§4.6][paper]、[补充§1/3][supp]

   作者统计 AIST++ 使用855个码，HumanML3D使用912个，其中846个共享。它支持“两个域能使用共同输出符号”的判断，但码本重用本身不证明同一个 token 在两套数据里具有一致、可读的动作含义。[§4.6、补充图3][paper]

2. **音乐与文字分别编码，动作 token 预测部分共享参数。**

   音乐先提取 MFCC、MFCC delta、constant-Q chromagram、tempogram 和 onset strength 等 Librosa 特征，再经嵌入层与 Transformer 编码。文字使用 GloVe 词表示、嵌入层和另一套 Transformer 编码。两种输入长度可以不同，不需要把一句话强行复制成与音乐等长的词序列。[§3.3][paper]

   动作解码器先对已有动作 token 做因果自注意力，只读取当前之前的 token，再交叉关注某一种条件特征。训练时音乐路径使用 AIST++ 的真值动作 token，文字路径使用 HumanML3D 的真值 token，分别计算交叉熵；**两条路径共享动作解码器参数，条件编码器则各自保留。**[图2、§3.3/3.5][paper]

   因此这是“两个配对任务共同塑造一个动作生成器”，并非训练中每个样本都有音乐、动作指令和目标舞蹈三者。统一词表与参数共享提供了推理时融合的基础，却没有直接监督任意音乐和任意文字组合的最佳答案。

3. **在末端隐藏特征处融合，让文字只在指定时间窗内介入。**

   在给定同一动作历史的前提下，解码器分别通过音乐条件和文字条件得到末端隐藏特征 hₐ、hₜ。作者的 late fusion 在各自完成多层解码之后进行加权和，再接线性分类层和 softmax，预测下一个动作 token。[§3.4、图3][paper]

   <div class="equation">hᵢ = (1 − wᵢ) hₐ,ᵢ + wᵢ hₜ,ᵢ<br/>p(kᵢ | k&lt;ᵢ, 音乐, 文字) = softmax(W hᵢ)</div>

   这是对图3的简化写法。wᵢ 由用户给定的 effect range 决定：区间外为0，开始20%的时间内通过半余弦曲线升到0.8，中间维持该值，最后20%再下降；音乐权重为1−wᵢ。这样给文字较强影响的同时，仍保留音乐条件，边缘变化也更平缓。[§3.4][paper]

   这里的0.8是特征混合权重，不能解释为“80%的关节服从文字”。它也不包含按左右手划分的权限表，更没有同一身体部位冲突时的硬约束求解：音乐与文字如何同时落实，仍依赖共享生成器的学习结果。

4. **自回归采样后统一解码，不依赖把独立动画剪贴到一起。**

   推理从随机起始动作 token 出发，每一步读取已生成历史和对应音乐条件，在文字生效时加入融合，再从 token 分布采样。完整序列最后通过预训练 VQ 解码器恢复为三维运动。补充实验使用 top-k 采样，并分析总取最大概率 token 与在候选集合中采样的差别。[§3.1/3.5][paper]、[补充§6][supp]

   这种共享历史让文字介入时仍能利用已有身体状态。与之对比的 slerp 基线先生成音乐舞蹈和文字动作，再用10帧窗口对旋转做球面插值；两者不仅融合位置不同，下一步生成时能否看到同一个历史状态也不同。[§4.1–4.2][paper]

5. **用冻结比例与运动预测距离补足传统分布指标。**

   FID可能无法突出“跳着跳着突然不动”的问题。PFF统计最大关节速度低于0.015 m/s且持续超过3秒的冻结帧比例；AUCf进一步在速度阈值0–0.03范围内汇总PFF曲线。因此静止但符合语义的动作，仍可能被这种指标计入低运动量，需要结合任务解释。[§4.1][paper]

   MPD则把文本介入前的25帧交给DLow运动预测器，获得多种可能的未来，再取生成后续与这些候选未来之间的最小距离；论文报告未来第10、20、30帧的距离。它衡量的是**与一个学习到的短期未来分布的相容性**，不是侧手翻成功率、文本时间边界误差或物理稳定性证明。[式6、§4.2][paper]

### 一个完整例子

沿用论文图1/4的任务：给定一段音乐，在 **6–8秒**插入 “A person does a cartwheel.”。下面中间量是依据机制展开的教学示意，不是本次实际运行日志。[图1、图4][paper]

1. **用户输入音乐、动作句与[6,8]秒区间。** 系统不从“侧手翻”这句话自行推断发生时间。
2. **两路条件编码。** 音乐变为与动作 token 时间轴对应的声学特征；GloVe与文字编码器得到指令序列特征。随机起始 token 与随后采样的历史共同进入共享动作解码器。
3. **6秒之前以音乐分支驱动。** w=0，只使用音乐路径的末端特征预测下一 token；不是先生成完整舞蹈再删除6–8秒。
4. **进入2秒窗口后平滑增加文字权重。** 按论文的比例，头0.4秒升到0.8，中间约1.2秒维持，尾0.4秒下降；实际在离散潜在时间位置上取对应权重。此处的秒数是由原机制计算的示例。
5. **融合后采样同一条 token 序列。** 每个新 token 回到共同历史；最后由VQ解码器恢复全身运动。将句子改为“伸开手臂转圈”可得到论文图4的另一种结果，而音乐和作用时间保持一致。

论文还展示把同一跳跃指令从6–8秒移到7–9秒，以及把持续时间从2秒改成3秒。但这些是定性控制示例，没有报告逐帧语义边界命中率，也不能把持续3秒等同于保证跳跃次数。[图5–6][paper]

### 消融实验

**加入HumanML3D混合训练：** 相比只用舞蹈，AIST++的FIDk从23.94降为19.01，但FIDg从9.53升为20.09，Beat Align从0.2127降为0.2049；Wild Audio的FIDk从43.85降为27.65、冻结PFF从0.78降为0.12。结果支持部分分布与域外稳定性改善，同时有几何特征和节拍指标的代价。[正文表1][paper]

**top-k采样与冻结：** 补充表1直接比较k=1、10、100。下表保留全部结果，每格为PFF / AUCf，均越低越好。[补充表1，p2][supp]

| top-k | 只用AIST++训练／AIST++测试 | 只用AIST++训练／Wild测试 | 混合训练／AIST++测试 | 混合训练／Wild测试 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 4.08 / 4.08 | 3.76 / 3.40 | 5.67 / 4.88 | 1.21 / 0.87 |
| 10 | 1.31 / 1.38 | 0.61 / 0.63 | 2.58 / 2.10 | 0.10 / 0.12 |
| 100 | 0.00 / 0.00 | 0.78 / 0.75 | 0.00 / 0.00 | 0.12 / 0.11 |

扩大采样候选通常减少冻结，但并非每列严格单调：仅舞蹈训练的Wild PFF在k=10为0.61，k=100为0.78；混训也并非对每个k都优于单数据训练。

**动作下采样率：** 补充实验使用两套数据各30%的样本，比较4、8、16、32倍下采样。较低下采样率通常有更多使用中和共享的码、较低重建损失，但会增加后续Transformer序列长度，作者据此选8倍。曲线未给逐点数值，不将图像读数当精确报告。[补充§3、图2][supp]

**文字与音乐融合：** 正文表3从仅文字到LFR 0.8时，R-precision为0.319→0.300，MM Dist为4.098→4.307，显示加入音乐会让文字一致性有所下降。补充图5另画了融合率扫描，但横轴刻度与正文0–1权重表述不够清楚；这里不据该图推算新的默认权重或精确阈值。[正文表3][paper]、[补充§5、图5][supp]

### 关键发现

1. **时间窗内融合比完成后拼接更连续。** AIST++的MPD@30为0.102，低于slerp的0.135；但真值为0.088，不能说TM2D在全部客观指标上超过真实动作。
2. **任务偏好与纯音乐自然度要分开看。** 双模态表2中，参与者对TM2D相对GT的偏好为70.0%；仅音乐表1中，相对GT则为41.9%。两组任务的控制内容不同，不是同一实验得出了互相矛盾的胜率。[表1–2][paper]
3. **共享表示带来的收益有明确取舍。** 混训提升某些分布指标并缓解域外冻结，但几何分布和节拍对齐并不全面提升；文字加入后语义检索精度也有下降，说明两类条件尚未无损结合。
4. **主贡献是跨模态接口与采样机制，不是物理执行保证。** MPD、PFF和人评支持连续性与观感，但没有直接衡量指定动作是否完整完成、持续时间是否准确、落地是否稳定或手脚是否接触目标。

## 亮点与洞察

- **把数据缺口转化为共享输出空间问题：** 不必先补齐音乐—文字—动作三元组，而是让两个已有任务在同一动作词表与共享解码器上相遇。这是可迁移的数据利用策略。[图2][paper]
- **融合位置清楚且可调：** 条件先分别处理，再在末端特征层混合，控制区间与权重均可显式编辑，便于分析“何时引入哪一种条件”。[图3][paper]
- **把冻结当作独立失败模式：** 仅看平均分布距离可能忽略长时间不动，PFF/AUCf把这一现象单列出来；同时要记住它们也不等于高质量舞蹈。[§4.1、补充§6][paper]
- **公开了不完美的权衡：** 混合训练不是每个指标都获益，单模态性能和双模态语义之间也有差距。这些结果比一句“多模态统一后全面更强”更有研究价值。

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

1. **控制时间是外部给定的。** 本文没有从长篇文本自动规划时间线；窗口权重控制条件影响，不保证动作语义的真实起止时间严格等于窗口边界。若用于精确编舞，需要额外测量动作检测边界误差。[图1、§3.4][paper]
2. **音乐与动作文字仍有竞争。** 统一全身特征的加权融合没有显式的部位权限、接触目标或冲突规则。对同一身体部分提出相互不兼容要求时如何处理，论文没有建立独立对照。[§3.4、表3][paper]
3. **共享码不等于语义完全对齐。** 码使用重合和t-SNE可视化表明表征重叠，却不能证明两套数据的动作分布已经一致，也不能推出token可解释或任意组合均可生成。[§4.6、补充§3][paper]
4. **MPD依赖另一个学习模型。** 与DLow候选未来接近只能反映一种连续性代理；它可能偏好常见动作，且不直接判定舞蹈是否踩准拍点、文字动作是否正确完成。[式6][paper]
5. **推理效率的外推有限。** 正文报告的0.143秒/1秒音乐不是经过统一硬件协议测得的通用实时承诺，完整发布材料与运行环境仍需另行核验。[表4][paper]

## 相关工作与启发

- **[Bailando](https://github.com/lisiyao21/Bailando)（CVPR2022）：** 两者都把动作压缩成离散表示并逐步生成。Bailando围绕音乐和舞蹈组织模型；TM2D增加独立文字任务、共享动作解码器与时间窗内后期融合，不能只把它看成“在Bailando旁边加一句提示”。[§2.1、§3][paper]
- **[TM2T](https://github.com/EricGuo5513/TM2T)（ECCV2022）：** 同样使用离散动作和序列翻译思想。TM2T研究文字与运动的双向关系；TM2D借用文字到运动能力，进一步处理音乐—文字并发条件。[§2.2、表3][paper]
- **[STMC](https://mathis.petrovich.fr/stmc/)：** STMC在扩散过程中按时间与部位组合局部运动预测；TM2D在自回归token分类前融合音乐与文字隐藏特征。二者都让用户提供时间区间，但组合对象和身体部位控制接口不同。
- **[CustomDance](https://github.com/XulongT/CustomDance)：** 从人参与创作的角度看，TM2D提供文字动作与时间窗接口，而CustomDance进一步组织舞句选择和局部编辑。具体交互自由度与是否保留源动作，应按各自生成流程比较。
- **启发：** 当音乐、语音或文字难以收集完整联合标签时，可先建立共同输出表示与明确的融合位置；随后应单独测量语义保留、节奏同步、时间边界和控制冲突，而不只证明“两个输入都能接入”。
