## 一句话总结

UniMo 让同一个语言模型先写出按时间顺序组织的动作描述，再生成动作 token 或最终 caption；它用真实动作渲染视频辅助构建这类 CoT 监督，并以 GRPO 对完整候选回答评分，联合改善文本生成动作与动作生成文本。它提供的是可读的语义中间步骤，并不把这些文字变成逐帧姿态、接触或位置的硬约束。

## 研究背景与动机

**领域现状：** 文本生成动作通常把一句描述映射为连续动作，或先将动作压缩为离散 token，再用 Transformer 生成。反方向的动作描述，则把动作概括成文本。MotionGPT、MotionLLM 等模型已经尝试让两类数据进入同一语言模型，因此“共享一个模型”本身并非本文的新起点。

**现有痛点：** “一个人跪着，随后用右手撑起身体”包含初始姿态、使用哪只手、动作先后关系和终止状态。简短 caption 与一串动作码之间缺少显式的中间解释；模型可能抓到“起身”，却忽略右手支撑。反过来，把动作压缩成一句话时，也可能漏掉关键过渡。

**核心矛盾：** 同一句话可以对应多种合理动作，动作码也不是天然具有词义的语言单位。直接做下一 token 预测，训练目标主要约束局部续写，而生成序列整体是否与文字一致、能否被准确描述，是更长尺度的问题。作者据此引入序列层面的奖励；这不是证明自回归生成必然不可行，而是在其上补充另一种监督。

**本文目标：** 在一个共享模型内完成 T2M（text-to-motion）和 M2T（motion-to-text），让模型能先展开动作顺序，再给出对应动作或摘要，并验证两项任务是否能互相帮助。

**切入角度：** 给已有动作—文本配对增加动作细节说明。与仅凭 caption 扩写相比，作者把真实动作渲染成视频，让视觉语言模型同时看视频和 caption，降低把不存在的动作编进监督文本的风险。这里增加的是合成语言标注，不是合成一套新的真实动作。

**核心 idea：** 用冻结的 VQ-VAE 建立动作词表，以 Qwen2.5-3B-Instruct 为共享生成器；先监督学习“输入 → CoT → 答案”的格式，再按任务对多个完整回答评分，通过 GRPO 强化动作、文本与目标之间的对应关系。

## 方法详解

### 整体框架

UniMo 的流水线分为离线标注、监督微调、强化学习和推理。离线的 Qwen2.5-VL-72B 只负责根据动作视频制作 CoT；最终对外执行两项任务的是另一个较小的 Qwen2.5-3B-Instruct。动作编码器、量化器和解码器构成固定的表示接口，LLM 则学习如何在文字与动作码之间续写。

### 关键设计

1. **把连续动作变成离散词表，但不把动作编码器与语言模型混为一体**

   一段动作先经 VQ-VAE 编码器下采样成连续潜特征，再为每个潜特征查找最近的码本向量。LLM 接收的是这些向量的离散索引，而不是直接读取关节坐标。生成时反向操作：LLM 输出索引，查码本并经过解码器，恢复连续动作序列。[正式论文 §3.2](https://ojs.aaai.org/index.php/AAAI/article/download/37936/41898#page=3)

   附录 B.1 给出 **512 个动作符号**，从 `<Motion_0>` 到 `<Motion_511>`，再增加 `<think>`、`<Motion>`、`<Answer>` 及对应结束符。新增词嵌入以原嵌入的均值初始化，减少扩词表时的分布突变。VQ-VAE 在后续 SFT 和 RL 中冻结，因此 UniMo 的奖励训练并没有重新学习动作压缩空间。

   这里的“统一”有明确层次：两任务共享动作码本和 LLM 的扩展词表、参数与续写机制；文本原有 tokenization 与动作 VQ 编码仍然不同，生成动作还需要额外的 VQ 解码器。公开配置使用 22 关节、263 维 HumanML3D 特征、20 fps，时间下采样为 4；这些是该实现的动作接口，并非任意骨架都能直接输入。

2. **用动作视频制作 CoT，监督的是可读动作分解**

   对 HumanML3D 的动作—caption 配对，作者先用 Blender 渲染动作，再把视频与原 caption 一起交给 Qwen2.5-VL-72B。提示词要求完整观察视频，按先后顺序写成连贯段落，使用“首先、接着、最后”之类连接词，只描述观察到的动作与过渡。结果放入 `<think>...</think>`，并以结构化字符串保存。[正式论文 §3.3；附录 A.1、图 7](https://arxiv.org/html/2601.12126v1#A1)

   因而本文的 CoT 更接近**细化的时序动作描述/计划**。标注提示词甚至明确要求不要额外解释或反思；不能把标签名中的 “think” 理解为获得了模型真实内部推理的证明。附录的词云、PCA 加 t-SNE 图显示标注文字包含更多转折和身体细节，但这类可视化并不测量标注正确率。

   这种监督比只靠短 caption 扩写多了一份动作证据；不过 VLM 仍可能误读视频。论文没有给出人工审核比例、标注错误率或严格的“文本扩写 vs 视频标注”同规模对照，因此“更有依据”和“保证无幻觉”应当分开。

3. **同一个自回归模型，使用两种输入输出顺序**

   T2M 的输入是任务指令和 caption，目标序列先给 CoT，再给动作码；M2T 的输入是任务指令和动作码，目标序列先给动作分析，再给最终 caption。其格式可简写为：

   ```text
   T2M：caption → <think>动作步骤</think><Motion>动作码序列</Motion>
   M2T：<Motion>输入动作码</Motion> → <think>动作分析</think><Answer>caption</Answer>
   ```

   CoT 是训练目标的一部分，也是推理时生成的显式前缀。它不是只在训练中使用、推理时删除的辅助头。代码中的 SFT 对输入 prompt 屏蔽损失，监督后续 CoT 与答案 token；共享 LLM 可以从一种任务中学到的动作语言对应关系，迁移到另一种任务。附录 B.2–B.3 与[序列构造代码](https://github.com/GuocunWang/UniMo/blob/20b56864b9bfab13d36ef3cb6a3463daa9135030/models/training_utils.py)。

   但这不是“先生成动作、再由理解模块自动纠错”的闭环。常规 T2M 推理不必调用一次 M2T，常规 M2T 也不必重建一次动作后再比较。双向能力主要通过共享训练形成。

4. **GRPO 比较同一输入的多个完整回答，推理仍逐 token 生成**

   监督微调只能告诉模型一个参考续写；GRPO 则让当前模型针对同一 prompt 采样 **G = 8** 个候选回答，给每个回答计算总奖励，再比较它在本组中的相对表现。论文式 4 的简化表达是：

   <div class="equation">Aᵢ = (rᵢ − 本组奖励均值) / 本组奖励标准差</div>

   奖励较高的回答获得更正向的更新信号。裁剪项限制单次策略改变，KL 项限制模型偏离参考策略的程度。这里的 group 指**多个完整候选回答**，不是把若干动作 token 改成一次并行预测。模型在训练采样和最终推理时仍使用自回归续写；强化学习增加了针对完整输出的目标，不是取消下一 token 机制。[正式论文 §3.4，式 3–4](https://ojs.aaai.org/index.php/AAAI/article/download/37936/41898#page=4)

5. **两个任务使用不同内容奖励，格式奖励只检查结构**

   T2M 回答中的动作码先经冻结解码器恢复动作，再用已有动作—文本评估编码器评分：动作相似度比较生成动作与参考动作的特征余弦相似度，语义相似度比较生成动作与输入 caption 的跨模态特征。前者拉近参考动作分布，后者鼓励符合语言条件。它们都不是关节坐标硬约束，也没有逐接触点的物理检查。

   M2T 使用 CLIP 文本编码器，比较生成 caption 与参考 caption 的余弦相似度，并乘以 2，对齐 T2M 两项内容奖励合计的量级。两项任务再各加格式奖励，按是否满足指定标签结构给 1 或 0。依式 5–7，可将任务奖励概括为：

   <div class="equation">T2M：r = r<sub>format</sub> + cos(动作特征, 参考动作特征) + cos(动作特征, 输入文本特征)</div>
   <div class="equation">M2T：r = r<sub>format</sub> + 2 × cos(CLIP(输出描述), CLIP(参考描述))</div>

   GRPO 通过策略概率接受评分，不要求对离散采样结果反向传播穿过动作解码器。格式正确、特征相似与动作真正完成所有细节仍是不同性质；论文没有为 CoT 中每条陈述设置单独的真实性奖励。[正式论文 §3.4，式 5–7](https://ojs.aaai.org/index.php/AAAI/article/download/37936/41898#page=5)

### 一个完整例子

以原论文图 1 和附录图 8 的输入为例：**“一个人跪着，然后用右手撑起身体。”** 下述中文步骤是对作者案例的教学转述，不是本次实际运行的输出。

1. **制作监督时看真实动作。** 训练样本本来就有对应的动作和 caption。动作被渲染成视频，VLM 同时看到视频与文字，形成“开始跪地 → 用右手支撑并起身 → 最后站直”的时间描述。这样可避免仅凭“起身”自由补出左手支撑等与样本不同的细节。
2. **动作走另一条表示路径。** 同一训练动作经过固定 VQ-VAE，变成索引序列。模型不需要把“右手”单独编码成一个预先定义的右手符号；身体结构主要由动作 tokenizer 和已学到的动作—语言关系表达。
3. **T2M 先展开步骤，再续写动作。** 用户只输入 caption，UniMo 先生成 `<think>` 内的步骤，然后继续生成 `<Motion>` 内的一串动作码。原图展示了 `<Motion_17>` 等码，但具体索引是码本编号，不能逐个翻译成“跪下”“右手”“站起”。
4. **解码得到动作，而非把文字计划直接执行成姿态。** VQ 解码器将码序列恢复成连续动作。右手支撑是否真的出现，要检查解码后的动作；文字中出现“右手”不是几何正确性的保证。
5. **强化学习在训练中评比较好的候选。** 同一输入采样出 8 个完整回答，格式与特征奖励比较它们。更符合参考动作和 caption 的候选会更有利，但评分器仍可能漏掉细节。
6. **反向任务复用同一模型。** 若输入的是一段动作，它先变成 VQ 索引，UniMo 再输出步骤分析和简短 caption。这个方向没有渲染视频给 VLM；视频教师只在离线标注中使用。

### 训练/推理

**论文训练流程。** 冻结动作 tokenizer 后，Qwen2.5-3B-Instruct 先在 T2M 上训练 10 epochs，适应新增动作词；再用 T2M 与 M2T 联合训练 10 epochs。SFT 使用学习率 1 × 10⁻⁴ 与余弦衰减。然后进行 14,000 步 GRPO，学习率 5 × 10⁻⁵，每个 prompt 采样 8 个候选，梯度范数上限 0.1，裁剪参数 ε = 0.2，KL 系数 β = 0.001。论文报告 **8 × A100、global batch size 8**，没有报告总训练小时、GPU 小时、VLM 标注费用或端到端推理延迟，不能据此给出“低成本”或“实时”结论。[正式论文 §4.3；附录 B](https://ojs.aaai.org/index.php/AAAI/article/download/37936/41898#page=5)

**推理流程。** T2M 只需要文本、训练后的 UniMo 与动作解码器；M2T 需要动作 tokenizer 和同一个 UniMo。两种情况下都先输出 CoT 再输出最终内容。公开推理实现调用采样式 `generate`，最长新增 512 token；这是代码预算设置，不是论文给出的动作时长保证，也不是 512 帧。[推理接口](https://github.com/GuocunWang/UniMo/blob/20b56864b9bfab13d36ef3cb6a3463daa9135030/models/mllm.py)

**当前发布与实现差异。** 本次静态核查固定官方提交 [20b56864b9bf](https://github.com/GuocunWang/UniMo/commit/20b56864b9bfab13d36ef3cb6a3463daa9135030)：仓库为 Apache-2.0，含 SFT、GRPO、T2M/M2T 评测和 demo，以及约 24.5 MB 的 CoT 文本 ZIP；基础 VQ-VAE、评估器和 Qwen 需要另备。README 的 UniMo 训练后权重仍未发布，演示脚本也要求填写自己的 checkpoint 路径。因此“有源码”还不等于已经能用官方最终权重复现论文。

### 关键发现

1. **理解方向的主表优势更集中。** 表 2 中 UniMo 的五个描述指标均高于列出的比较方法，尤其 CIDEr 46.69 对 MotionLLM 的 33.74；但这些仍是参考描述匹配指标，不是开放世界动作理解的完整评测。
2. **生成方向是指标取舍。** UniMo 的检索匹配和 MM-Dist 更好，FID 0.177 却不如 MoMask 的 0.045、T2M-GPT 的 0.116；MModality 1.924 也低于 MDM 的 2.799、Motion-R1 的 2.317。不能将论文概括为所有生成指标第一。
3. **真正被消融支持的是 CoT、奖励与联合训练的组合。** 单独加 CoT 会退步，双任务 SFT 也会在 FID 上退步；完整训练改善了若干重要指标，但没有消除两任务之间的取舍。
4. **解释性来自可阅读中间文本，忠实性仍待单独验证。** 论文展示了动作步骤和最终结果，没有量化每条 CoT 是否真的被动作执行，也没有证明这些中间文字是最终动作决策的必要原因。

## 亮点与洞察

- **把动作证据放进标注环节：** 渲染视频让教师模型能观察原动作，补充 caption 漏掉的先后关系和身体细节；这比无限扩写输入文字更接近动作语言对齐问题本身。
- **同一 CoT 在两个方向扮演不同角色：** 生成时是先写计划，理解时是先展开观察再压缩成 caption，统一的输出结构使两个任务能够共享训练信号。
- **奖励目标可以分解检查：** 动作相似、跨模态相似与 caption 相似分别对应不同期望，表 3 显示它们确实会改变不同指标。这也提醒设计奖励时不要只看一项综合分数。
- **离散接口使完整回答可被评分：** 生成的 motion token 能经固定解码器转回动作，因而可以让已有动作评估器参与 RL；不需要声称文字计划本身就是动作执行器。

## 局限与展望

1. **语言计划不保证几何执行。** 没有逐关节目标、接触、避障或源动作严格保持机制；需要精确动作控制时，仍须在最终解码动作上检查约束。
2. **CoT 标注与可解释性都缺少独立真实性评测。** VLM 生成的文字可能包含误读；可读步骤也不保证忠实解释模型的动作选择。未来可以按事件、身体部位和动作执行逐项验证，而不是只检查标签格式。
3. **奖励与评估空间相关。** T2M 内容奖励复用已有动作—文本特征，奖励改善不自动等于独立的人类判断或物理质量改善。需要额外评估器、人工检验与物理指标才能扩大结论。
4. **证据集中于有限动作域。** 主表仅覆盖 HumanML3D，没有跨骨架、多人交互、长时流式生成或未见环境的系统结果；公开表示接口也不是通用任意人体模型。
5. **效率与复现仍有空缺。** 显式 CoT 增加输出 token，GRPO 需要多候选采样，离线教师为 72B VLM；论文没有给出相应时延与总费用。最终 UniMo 权重尚未在官方仓库发布，公开配置也与论文存在差别，本次结论是论文阅读和静态审计，非模型复现。

## 相关工作与启发

- **[MotionGPT](https://arxiv.org/abs/2306.14795)：** 已将动作离散为词表并统一处理多种动作语言任务。UniMo 沿用“动作作为一种可续写符号”的方向，进一步加入显式动作 CoT 与任务奖励，贡献不只是把动作接入 LLM。
- **[Motion-Agent / MotionLLM](https://arxiv.org/abs/2405.17013)：** 是 UniMo 对照与实现依赖的重要来源，官方仓库借用其动作 tokenizer 等资源。MotionLLM 以少量参数适配动作任务，UniMo 当前公开训练代码则直接优化共享 LLM，并添加视频标注的 CoT 和 GRPO；不能把基础模块可下载等同于 UniMo 最终权重已发布。
- **[Motion-R1](/blog/iclr2026-motion-r1/)：** 同样在文本生成动作中结合 CoT 与 RL；UniMo 将其作为生成侧对照，并强调视频依据的标注和双向共享训练。这里比较的是 UniMo 文中采用的结果与论述；Motion-R1 后续版本的机制、数据和评测应按其独立解读核查，不能把旧版描述当作当前完整定义。
- **[LaCT-Motion](/blog/eccv2026-lact-motion/)：** 先学习显式动作分解，再逐步将文字步骤压缩到连续隐藏状态，在推理时通过潜在规划后生成动作码。UniMo 保留可读 CoT，并强调生成与理解共享训练；LaCT-Motion 主要研究去掉显式文字后的生成效率与质量取舍。二者规划表示不同，不能只按是否使用 CoT 归为相同方法。[LaCT-Motion 正式论文 §3.4–3.6](https://media.eventhosts.cc/Conferences/ECCV2026/pdfs/13122.pdf)
- **启发：** 如果希望动作模型既能执行指令又能解释动作，可以先尝试共享表示与可检查的中间步骤；但应把“步骤写得合理”“动作做得正确”“反向描述准确”分成三个评测目标。UniMo 的消融说明，这些目标会互相促进，也会发生冲突。
