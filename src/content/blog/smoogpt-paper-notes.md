## 一句话总结

SMooGPT 先把动作内容和风格各自解释为六个身体部位的文字描述，在文字中处理冲突，再由全量微调的语言模型生成部位动作 token，最后用扩散模块协调并解码为动作。它让风格组合更容易检查和修改，但文字描述、学得的动作码与最终连续轨迹之间仍有误差；v2 的参考动作模式也保留了风格特征直接进入扩散模块的支路。

## 研究背景与动机

**领域现状：** 动作风格化要同时决定“做什么”和“怎样做”：同样是向前走，可以谨慎、疲惫或像飞机一样展开双臂。传统动作迁移从一段动作取得内容、另一段取得风格；SMooDi 等方法进一步允许用内容文本驱动生成，同时从参考动作提取风格。大多数方法在潜在特征中混合两者，最终才看到解码结果。

**现有痛点：** 当内容和风格要求同一个身体部位采取不同动作时，直接混合不一定能作出合理取舍。例如右手投掷需要挥臂，而飞机风格要求双臂展开。如果把两个要求同时施加在右臂上，生成器可能牺牲投掷内容，也可能丢掉风格。另外，100STYLE 主要包含各类行走式动作；仅围绕这类数据学习风格，可能把跳跃、投掷等内容拉回走路。

**核心矛盾：** 风格经常是局部的，输入却通常只有一个全局风格名称或一个整体潜在向量。人知道飞机式展开可以交给左臂，让右臂继续投掷；一个混合特征却不会直接告诉用户哪个部位继承了什么，也难以检查冲突在哪里被解决。

**本文目标：** 建立可以同时接受文字与动作参考的风格生成流程，让内容和风格先以可读形式分解、组合，并支持不局限于既有风格标签的描述。作者尤其关注纯文本输入的风格化，同时评测内容文本加参考风格动作的设置。

**切入角度：** 把全身动作分成根部、躯干、左右臂、左右腿六部分，用文字分别说明姿态、运动方向和节奏。许多新风格未必需要全新的部位运动，而可能来自已有部位模式的新组合；语言模型可以在这个层面给出组合方案。

**核心 idea：** 用同一个微调后的语言模型依次担当解释者、组合者和生成者：先分别输出内容与风格的部位描述，再生成统一描述，最后翻译为学得的部位动作 token。为了处理不同部位连续运动的协调，v2 在动作解码前加入条件扩散模块；这也说明“文字上的合理组合”本身并不等于最终身体运动已经协调。[§1、§3–4](https://arxiv.org/pdf/2509.04058v2#page=2)

## 方法详解

### 整体框架

SMooGPT 有三层不同的表示：人能直接读懂的全局/部位文字、VQ-VAE 学出的离散部位动作 token，以及供扩散模块协调和解码的连续动作特征。离线先构建动作与文字训练对，训练动作 tokenizer 和语言模型；推理时，内容与风格分别进入解释流程，在部位文字中组合，再生成动作 token。v2 将这些 token 对应的连续码向量作为扩散条件，从随机噪声生成协调后的特征，交给预训练解码器输出动作。

图按“数据与表示 → 训练产物 → 三步语言推理 → 连续动作生成”阅读。实线表示数据、条件与输出，虚线表示训练产物复用或指定模式的可选支路。动作参考有两种角色：经过 tokenizer 后可被语言模型解释；在 **motion-guided** 设置下，参考风格动作还通过轻量适配器直接影响扩散模块，不能把整套方法画成所有信息都只能经过文字的单通道。[图 4、§3–4；附录 D](https://arxiv.org/pdf/2509.04058v2#page=4)

### 关键设计

1. **部位文字空间：把风格冲突变成可以检查的局部描述**

   作者将一个样本表示为动作序列、全局文字、六部位文字三者的对应关系。全局文字说明整体任务，部位文字进一步说明根部如何移动、躯干如何倾斜、哪条手臂伸展、双腿怎样迈步。描述不只包含静止姿势，也包括运动方向和动态模式。

   这一层的作用是表达意图。例如“右臂完成投掷，左臂保持飞机式侧向伸展”，比“投掷加飞机风格”更明确。但它没有天然定义逐帧关节角、接触时间或严格轨迹。“向前伸出左臂”是可读语义约束，不等于某个关节在某一帧必须达到指定三维坐标。[§3.1、图 3](https://arxiv.org/pdf/2509.04058v2#page=3)

2. **六套动作 tokenizer：学得的动作 token 与可读部位文字分开**

   模型使用 HumanML3D 的 263 维动作表示，再按六个部位拆分。每个部位有自己的编码器、码本和解码器。编码器把连续动作压缩为向量，再取码本中最近的向量；码本索引就是可供语言模型预测的离散动作 token。

   <div class="equation">部位动作 m<sub>p</sub> → 编码向量 E<sub>p</sub>(m<sub>p</sub>) → 最近的码本向量 c<sub>p</sub> → 部位解码器 D<sub>p</sub></div>

   这是对原文式 1–2 的流程表达。VQ-VAE 训练包含动作重建、码本拟合和 commitment 三部分损失；码本负责学习可重用的局部运动片段，并不是人工列出“抬手”“挥手”等语义符号。附录 D 给出每个码本 512 项，Root 的码向量为 64 维，其他部位为 128 维，时间下采样率为 4。[§4.1、式 1–2；附录 D](https://arxiv.org/pdf/2509.04058v2#page=5)

   语言模型词表加入六组带部位前缀的动作 token，例如 `left_arm_<idx>`，以及各部位序列的起止标记。这与用普通文字写“左臂向前”不同：前者是运动码的离散编号，后者是描述意图的自然语言。它们共享预测接口，但没有因此变成同一种可解释表示。

3. **真实训练语言模型：对齐、指令学习与组合任务各有作用**

   SMooGPT 使用作者报告的 **220M Flan-T5-Base** 编码器—解码器模型，并在预训练和后训练阶段微调整个模型的权重，不是仅向现成聊天模型发送提示。

   首先，通过“部位动作 token → 部位文字”和“部位文字 → 部位动作 token”的双向任务建立两种表示的对应。随后加入指令模板，包括全局文字到部位文字，以及内容部位描述与风格部位描述到统一描述的组合任务。输入经过 T5 编码器，输出由解码器自回归预测下一个 token；训练目标是原文式 3 的序列交叉熵。

   <div class="equation">输入条件 s<sub>i</sub> + 已生成的输出前缀 → 预测下一个文字或动作 token</div>

   需要区别两个“LLM”：离线 **ChatGPT-3.5** 用于生产部位文字和组合标注，**MotionGPT** 为 100STYLE 动作补全局内容描述；推理阶段执行本文三步任务的是训练后的 **SMooGPT**。不能将离线教师模型的提示调用误写成 SMooGPT 没有训练，也不能据论文推定每次生成都要在线调用 ChatGPT。[§4.2–4.4；附录 B–D](https://arxiv.org/pdf/2509.04058v2#page=5)

4. **解释—组合—生成：三次任务复用同一个模型**

   **解释阶段**分别处理内容与风格。若输入是全局文字，直接要求输出六部位描述；若输入是真实动作，先经六套 VQ 编码/量化变为动作 token，再由已学会动作到文字翻译的模型生成部位描述。模型因此接触了源动作的编码，而不只是读取一个外部给定的风格名。

   **组合阶段**接收两套部位文字，生成一套统一描述。原文的投掷加飞机例子中，一条手臂承担投掷，另一条借用飞机姿势。它不是将两句话机械拼接，也没有预先规定只能整段选择内容或风格；模型需要在部位层面作语义取舍。

   **生成阶段**再把统一描述翻译为六组动作 token。这里的“三角色”是同一个训练模型执行不同指令，不是三个独立智能体或调用外部动作工具的规划器。文字方案可以被检查和修改，但论文没有给出冲突必然消除、每个描述必然被解码兑现的形式化保证。[§3.2、图 4；§5.4、图 9](https://arxiv.org/pdf/2509.04058v2#page=4)

5. **扩散协调：在连续特征中解决部位之间的运动衔接**

   六个部位分别有动作码，不意味着它们拼在一起就自然。例如手臂挥动、躯干旋转和脚步重心需要相互配合。v2 因此在 VQ 解码器前加入轻量扩散头。

   先把 LLM 输出 token 对应的码向量经 MLP 投影并拼接为条件 `z_cond`；另从高斯噪声 `z_T` 开始，迭代预测噪声并得到统一连续特征 `z_0`，最后拆回各部位特征进行解码。

   <div class="equation">LLM 动作码向量 → Ψ（MLP 与拼接）→ z<sub>cond</sub><br>高斯噪声 z<sub>T</sub> → ε<sub>θ</sub>(z<sub>t</sub>, t, z<sub>cond</sub>) → 协调后的 z<sub>0</sub> → 部位分解 → VQ 解码</div>

   这个模块不是给整数 token ID 直接加噪，也不是先生成完整动作、再接一个未说明的滤波器。附录式 4–5 采用噪声重建损失；原文将部位分解写为 Ψ 的逆操作，但没有提供足以核验严格可逆性的结构细节，讲解时按“还原为部位特征的映射”理解即可。最终输出仍是生成结果，协调模块不构成动力学、脚部接触或源动作保留保证。[§4.5；附录 D、式 4–5](https://arxiv.org/pdf/2509.04058v2#page=13)

6. **参考动作模式的直达支路：承认文字会丢失动态细节**

   作者在附录明确指出，把参考风格动作全部翻译成文字，会丢失高频动态。因此，在内容文本加风格动作的 **motion-guided stylization** 中，另从参考动作提取风格特征 `s`，通过轻量适配器进入扩散去噪器：

   <div class="equation">ε<sub>t</sub> = ε<sub>θ</sub>(z<sub>t</sub>, t, z<sub>cond</sub>, s)</div>

   这对应附录式 6–7。文本路径负责可读的意图与组合，风格特征路径补充直接的动作信息；最新方法的效果不能全部归因于文字推理。原文没有完整展开该风格编码器、适配器的层数、所有参数冻结关系和采样细节，图中只画有证据的模块和连线。[附录 D，Motion-guided stylization](https://arxiv.org/pdf/2509.04058v2#page=13)

### 一个完整例子

以论文图 9 的“**右手投掷 + 飞机风格**”为例。以下中文部位描述是依据该案例整理的教学概括，不是原始模型逐字输出，也不是本次运行结果。

1. **给出两类要求。** 内容是用右手完成投掷，风格是模仿飞机。若把风格改成一段参考动作，模型可先经部位 tokenizer 编码，再解释它的动作特征；纯文本例子不需要先合成参考动作。
2. **分别解释。** 内容描述让右臂承担投掷，躯干和双腿提供配合；风格描述突出双臂侧向伸展。此时右臂的要求存在冲突，说明为什么不能直接拼接两组文字。
3. **形成统一方案。** 组合步骤让右臂保留投掷任务，左臂采用飞机式伸展，躯干与下肢采用相容的支持动作。这里保留的是“投掷”这一内容要求，不是在复制另一段源动作的每一帧右臂轨迹。
4. **生成离散运动序列。** SMooGPT 根据统一描述预测六组运动码，每组对应其部位码本。用户看到的部位文字和模型生成的 token 序列是不同对象。
5. **协调、解码并检查。** 运动码向量形成扩散条件，从噪声得到全身协调特征，分回六部位解码为连续动作。若采用参考动作模式，风格特征同时从旁路影响扩散头；最后仍需查看投掷内容、左臂姿势和身体运动是否真正表现出来。

论文用这一案例说明冲突处理的价值，但没有以逐关节误差验证“只改变左臂，其余所有源动作完全不变”。该例更接近可解释的重新生成，而非有硬保持机制的局部动画编辑。[图 9、§5.4](https://arxiv.org/pdf/2509.04058v2#page=9)

### 训练/推理

**数据准备。** 附录 C 描述了 HumanML3D 与 100STYLE 的整体标注构建流程：利用全局内容描述和风格标签产生部位文字，给 100STYLE 动作用 MotionGPT 补内容描述，再生成同时体现内容与风格的统一文字。标注来自模型推断，不能视为每个关节的人工精确标签。

**按协议区分训练数据。** 论文的总流程涉及两套数据，但不能因此说每个实验都用过全部数据。§5.1 将纯文本主表设置描述为仅在 HumanML3D 训练；motion-guided 的 cross-dataset 设置同样只用 HumanML3D，再接受 100STYLE 风格参考。held-out 设置才加入 100STYLE 的已见风格子集，并把 10 类完整留出。附录没有提供可下载的逐阶段样本清单，不能进一步推断所有训练任务和标注池的精确使用比例。

**训练模块。** 六套 VQ-VAE 学习动作重建与离散码；语言模型先进行运动/文字双向对齐，再进行指令和组合训练，pre/post 均为全权重微调；扩散头用噪声重建监督学习连续协调，参考动作模式加入风格特征条件。论文把解码器称为预训练组件，但没有完整列明后续每个训练阶段对 tokenizer 和扩散相关模块的冻结/联调安排，本文不补造统一的冻结表。

**已披露设置。** 最大输入长度 512；预训练与指令训练分别 300,000 次迭代，学习率分别为 2×10⁻⁴ 和 1×10⁻⁴，batch size 均为 48；风格增强训练另有 50,000 次迭代。训练时随机遮蔽全局文字或一至两个部位文字，以减少模型依赖单一条件。作者使用 2 张 NVIDIA H200，但没有报告总墙钟训练时长，不能据迭代数直接推出完整费用。tokenizer、教师标注、各配置重训与消融也不自动包含在一个主模型预算内。[§4.4；附录 D](https://arxiv.org/pdf/2509.04058v2#page=13)

**推理范围。** 三步语言任务后接连续扩散与部位解码。作者报告单张 RTX 4090 生成一个动作片段平均约 **25.761 秒**，但未同时明确统一片段长度、采样次数、各子阶段耗时或端到端计时边界，不将它转换成 FPS 或实时交互承诺。[附录 D，Inference time](https://arxiv.org/pdf/2509.04058v2#page=14)

| ChatGPT + MLD | 9.609 | 1.246 | 0.289 | 0.652 | 0.181 |
| SMooGPT | **17.344** | **1.132** | **0.669** | **0.670** | **0.0832** |

|---|---|---:|---:|---:|---:|---:|
| 跨数据集 Zero-Shot | SMooDi | 7.110 | 1.185 | **0.504** | 0.640 | 0.112 |
| 跨数据集 Zero-Shot | SMooGPT | **12.695** | **1.153** | 0.481 | **0.659** | **0.104** |
| 同数据集 Held-Out | SMooDi | 14.775 | 1.157 | **0.509** | 0.651 | 0.118 |
| 同数据集 Held-Out | SMooGPT | **15.527** | **1.150** | 0.474 | **0.660** | **0.110** |

| 指标 | 具体口径 | 如何理解 |
|---|---|---|
| SRA-L ↑ | 使用 100STYLE 训练的风格分类器，仅在 HumanML3D 测试集中与移动行为有关的序列上计算风格识别率 | 分类器主要见过移动动作，因此过滤非移动内容；这个分数不代表挥拳、敬礼等所有动作内容的风格成功率 |
| MM Dist ↓ | 内容文本与生成动作的嵌入距离 | v2 附录 D 指定使用 TMR 评估器，不能直接与其他论文采用标准 HumanML3D 评估器的数值横比 |
| R-Precision Top-3 ↑ | 文本—动作检索匹配，亦采用 TMR | 是内容一致性的代理指标，不是所有动作细节都准确的成功率 |
| CLIP-score ↑ | 内容文本与风格化动作的对齐程度 | 与 MM Dist、R-Precision 共同观察内容表现，不代替几何或物理验证 |
| FS-Ratio ↓ | 脚滑比例 | 只覆盖真实感的一个方面，低脚滑不等于全身动力学、接触和碰撞都正确 |

**数据和“未见”的含义。** 文本引导实验的 §5.1 声明各方法仅以 HumanML3D 训练，再以 100STYLE 的风格标签作为测试输入。动作引导的跨数据集设置也只用 HumanML3D 训练生成模型，测试时提供 100STYLE 风格动作；同数据集设置则使用 HumanML3D 加上 100STYLE 的已见风格，把 10 类风格完整留给测试。它们检验的是对应生成训练协议下的风格泛化，并非证明语言模型预训练中从未接触过相关概念；风格评估分类器本身仍由 100STYLE 训练。[§5.1、附录 C–D](https://arxiv.org/html/2509.04058v2#S5.SS1)

附录 C 列出的 10 类留出风格为 Zombie、SwingShoulders、SwingArmsRound、Swimming、Swat、Superman、Stiff、Star、ShieldedRight 和 ShieldedLeft。论文说这些类别完全排除在对应训练之外；其余已见风格用于风格增强训练。没有报告按类别分解的主表分数，也没有列出各协议最终使用的测试片段数量和 SRA-L 筛选后数量。这里的 held-out 是**风格类别留出**，不是未见人物测试。

论文整体的数据构建还涉及 100STYLE：附录 C 使用其风格标签和动作，借助 GPT-3.5、MotionGPT 构造身体部位描述及内容—风格组合文本。因此不能将整个方法概括成“训练从未使用 100STYLE”。应按上面的具体实验设置区分；论文未给出可逐条核对各训练配置的样本清单。HumanML3D 和 100STYLE 的原始数据规模也不等于每个设置实际用于训练或评价的样本量。

**动作引导基线的调整。** 附录 E 说明：SMooDi 在跨数据集设置中训练 10 个 epoch 后早停，在 held-out 设置中训练 50 个 epoch；分类器自由引导权重设为 1，并关闭基于风格分类器的引导。SMooGPT 的动作引导版本则在扩散头中额外接入参考动作的风格特征，避免所有动态细节都经过文本中转。因此表 2 比较的是这些特定配置，不能直接当作 SMooDi 原论文主表的复现，也不能把结果完全归因于文本组合单一环节。[附录 D–E，PDF 第 13–14 页](https://arxiv.org/pdf/2509.04058v2#page=13)

**用户研究。** v2 图 8 与附录 F 使用文本引导任务，共 75 名参与者、21 对动作，均分给三个对照方法，即每个对照 7 对。视频匿名、随机排列，参与者分别判断内容保持、风格表达和动作真实感。下表是偏好 SMooGPT 的比例，50% 表示两者持平。

| 对比方法 | 内容保持 | 风格表达 | 动作真实感 |
|---|---:|---:|---:|
| ChatGPT + MLD | 72.5% | 73.5% | 74.5% |
| ChatGPT + MotionGPT | 80.7% | 81.7% | 81.3% |
| ChatGPT + ParCo | 79.53% | 75.1% | 79.57% |

### 消融实验

v2 表 3 在文本引导任务上比较身体部位表示、预训练和扩散精修头，完整结果如下。

| 变体 | SRA-L ↑ | MM Dist ↓ | R-Precision Top-3 ↑ | CLIP-score ↑ | FS-Ratio ↓ |
|---|---:|---:|---:|---:|---:|
| w/o BP：不使用身体部位空间 | 13.674 | 1.231 | 0.452 | 0.6324 | 0.0963 |
| w/o PT：去掉预训练阶段 | 15.234 | 1.380 | 0.501 | 0.667 | 0.0958 |
| w/o DF：去掉扩散精修头 | 16.328 | 1.134 | 0.512 | 0.669 | 0.0953 |
| 完整模型 | **17.344** | **1.132** | **0.520** | **0.670** | **0.0832** |

**跨表差异须保留：** 表 1 完整模型的 R-Precision 为 **0.669**，表 3 则是 **0.520**，其余四个完整模型指标相同。v2 未说明这一差异的原因。这里分别按原表呈现，消融只在表 3 内比较，不擅自把其中一个数值改成另一个。[v2 表 3，PDF 第 9 页](https://arxiv.org/pdf/2509.04058v2#page=9)

**身体部位空间：** w/o BP 使用仅处理全局文本的原始 MotionGPT，在相同数据集上训练。加入本文表示后，SRA-L 从 13.674 到 17.344，表 3 的 R-Precision 从 0.452 到 0.520，FS-Ratio 从 0.0963 到 0.0832。这支持细粒度表示的价值，但它是完整表示方案的比较，不是仅替换一句提示词的实验。

**模态对齐预训练：** 去掉预训练后，SRA-L 降至 15.234，MM Dist 从完整模型的 1.132 增至 1.380，其余指标也变差。说明在指令训练之前先对齐部位动作 token 和部位文本，有助于后续生成；不能把这种能力解释成只靠原始语言模型的常识而无需动作训练。

**扩散精修头：** 去掉它后，SRA-L 从 17.344 降至 16.328，FS-Ratio 从 0.0832 增至 0.0953；加入后脚滑比例相对下降约 12.7%。内容距离的变化较小，MM Dist 为 1.134→1.132。其证据主要支持连续协调和质量改善，没有证明所有关节关系与接触约束都被严格满足。

**风格与身体部位的语言判断：** 附录 A 让 GPT 仅根据风格名称和文字描述预测相关身体部位，对比人工观看 100STYLE 示例后给出的多标签标注，micro-F1 为 **0.72**。这验证的是“风格主要影响哪些部位”的语言判断，不是生成动作的 72% 成功率，也不是 SMooGPT 最终三维动作的精确控制指标。[附录 A，PDF 第 12 页](https://arxiv.org/pdf/2509.04058v2#page=12)

### 关键发现

1. **最新版文本引导实验在所列指标上均优于三个组合基线。** 例如，相较 SRA-L 最好的 ChatGPT + ParCo，SMooGPT 从 13.359 提升到 17.344，约为相对提升 29.8%；这不是提升 29.8 个百分点。这个结论限于 v2 的基线、指标和数据协议，不沿用旧版未过滤 SRA 的数值。

2. **动作引导结果存在内容指标取舍。** 跨数据集设置中，SRA-L 从 7.110 增至 12.695，FS-Ratio 从 0.112 降至 0.104，但 R-Precision 从 SMooDi 的 0.504 降至 0.481；held-out 设置也从 0.509 降至 0.474。MM Dist 和 CLIP-score 同时改善，所以应说不同内容指标给出了不同信号，不能写成“内容保持全面胜出”。

3. **风格可描述，不代表最终动作一定能实现。** 附录 G 的失败案例中，“利落敬礼”能生成大致手臂轨迹，却不能在峰值处急停；“像鸟飞一样走路”可以形成张开双臂的配置，却缺少清楚、周期性的振翅动态。作者将其分别联系到文本表示的时间粒度，以及身体部位 VQ-VAE 所学动作分布的限制。开放词汇能力提供组合空间，最终输出仍受动作表示与训练数据约束。

4. **披露了训练步数和单片段生成时间，但没有完整训练成本。** 附录 D 报告预训练和指令训练各 300,000 次迭代，batch size 48，学习率分别为 2×10⁻⁴、1×10⁻⁴；风格增强训练另加 50,000 次迭代，使用 2 张 NVIDIA H200。论文没有给训练墙钟时间或可据此计算的 GPU 小时，也没有拆分 tokenizer、精修头、数据合成与全部对照实验的成本。单张 RTX 4090 生成一个动作片段的平均耗时约 **25.761 秒**；该段未明确片段时长、各阶段计时边界或实时因子，因此不能换算成稳定的 FPS 或承诺实时交互。[附录 D，第 13–14 页](https://arxiv.org/pdf/2509.04058v2#page=13)

## 亮点与洞察

- **把可解释性放在真实中间表示里：** 内容和风格的部位描述能够被直接查看、修改和组合，不只是生成结束后再附一段解释；这让“哪条手臂继承什么要求”成为可讨论的设计对象。
- **语义与动作采用不同精度的表示：** 自然语言承担意图和冲突取舍，VQ 动作码承载已学到的运动模式，扩散模块处理连续协调。三者合作的价值，恰好来自它们并不等价。
- **对文字瓶颈作了实际补偿：** motion-guided 的直接风格特征支路承认文字对高频动态的表达不足。它是最新版本的重要组成，提醒我们评价语言规划时还要检查底层生成器获得了哪些额外信息。
- **将“新风格”拆成可重组的局部行为：** 组合已有部位模式可能扩大输出范围，无需每个风格都建立独立标签。但这种语义组合能力仍受 tokenizer 和解码器已学运动的限制，不能由文字词汇无限外推。

## 局限与展望

- **可读描述没有精确时间轴。** 附录 G 的急促敬礼失败例中，模型能产生抬臂大致轨迹，却没有表现出突然停止，峰值附近被过度平滑。描述“快速抬起”与约束一个明确时刻的速度突变是不同能力。
- **语言知道的风格可能超出动作模型会生成的范围。** 飞鸟式行走例子能展开手臂，却缺少清楚的周期拍翼。作者将这一限制归因于部位 VQ-VAE 已学运动空间；扩散协调也没有消除这种表示边界。[图 A1、附录 G](https://arxiv.org/pdf/2509.04058v2#page=14)
- **内容保持主要按语义评估。** R-Precision、MM Dist 和 CLIP-score 衡量动作与内容文字的匹配，不是源动作逐帧保持误差。本文没有验证任意源动作局部编辑时，未指定部位的姿态、根轨迹、接触和时长都严格保留。
- **未知风格的证据需要按协议阅读。** 跨数据集、留出风格、画廊中的新文字描述各有不同证据；SRA-L 又仅评价行走相关子集，不能替所有非行走动作认证风格正确。motion-guided 对比中也有检索指标退步，不能概括为对 SMooDi 全面胜出。
- **语言组合的正确性仍依赖训练标注和生成器。** 离线描述来自教师模型，组合指令没有硬冲突求解器；附录报告的风格—部位 micro-F1 是文字分类测试，而非最终动作成功率。若用于精确动画控制，需要另外验证描述是否在最终轨迹中兑现。
- **复现与部署尚有披露缺口。** 当前没有可核实的完整公开实现，扩散采样、适配器和训练调度的部分细节未充分展开；已有单片段计时也不支持低延迟控制结论。作者提出未来加入按时间组织的关键姿态 token，这是未来方向而非当前已经实现的约束接口。

## 相关工作与启发

- **[SMooDi](https://neu-vi.github.io/SMooDi/)（ECCV 2024）：** 以冻结的预训练扩散主干、风格适配器及引导实现风格化。SMooGPT 把内容与风格组合显式放到部位文字层，但参考动作模式仍借鉴适配器思路。本文比较的是针对未知风格重新配置的 SMooDi，而非直接复用其原论文所有设置与分数。
- **[MotionGPT](https://motion-gpt.github.io/)（NeurIPS 2023）：** 将运动码与文本放进统一语言建模接口，提供动作与语言双向转换。SMooGPT 进一步采用部位 token、部位文字与内容—风格组合任务；不能把“运动作为语言”理解成每个运动码本身都是可读语义符号。
- **[ParCo](https://arxiv.org/abs/2403.18512)（ECCV 2024）：** 为本文部位 tokenizer 和局部动作建模提供基础。SMooGPT 的新增重点是部位文字中间层、微调后的三步任务，以及生成后的连续潜在协调；部位表示相近不意味着控制和评测任务相同。
- **[StyleMotif](https://stylemotif.github.io/)（ICCV 2025）：** 通过特征中的内容—风格交互与多模态对齐扩展风格控制。SMooGPT 强调可读语言组合；论文投稿时未取得其代码，因此未把它作为主表直接对照，不能将本文结果推成对 StyleMotif 的实测胜出。
- **启发：** 对需要可编辑方案的动作系统，可以把“可读意图”“学得的运动实现”“最终轨迹检查”分为三个层面。部位文字适合作为人机协商接口，但要保证动作细节、时间或接触，仍需在更精细的表示和解码输出上建立约束；这是应用设计推论，不是本文已完成的功能。
