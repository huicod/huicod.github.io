## 一句话总结

Parasitic Co-Denoising在冻结的**Wan2.1-T2V-14B视频模型**旁边训练一个约**19M参数的Parasitic Motion Decoder（PMD）**：每个去噪时刻都读取视频模型的中间特征，引导一条同步推进的动作潜变量流，最终同时得到视频和显式3D动作。[方法、图2][html]

关键贡献是把视频生成过程中逐步形成的运动信息持续转给动作分支。它需要训练动作自编码器、对齐投影和PMD；推理也需要运行大型视频宿主，因此这里的“小”指新增可训练部分，而非整套系统的规模或运行成本。

## 研究背景与动机

**领域现状：** 文本到3D动作模型多从文本—动捕配对数据学习。与此同时，大规模视频生成模型已经能按文字生成跳舞、体育运动等多种人体活动；这些视觉先验来自远大于常用动作数据集的视频分布。[引言、相关工作][html]

**现有痛点：** 动作数据对长尾动作、复杂语义和风格的覆盖有限。遇到“Salsa dancing”等提示时，模型可能生成大致合理的摆动，却缺少对应活动的特征。直接先生成视频再做人体恢复，又要承担额外的恢复误差和流程开销。

**核心矛盾：** 视频模型可能知道某个动作“看起来怎样”，但其状态是面向像素重建的时空特征，不能直接作为可用的3D关节运动。动作需要明确的运动学表示，而视频中还混合着视角、外观和背景信息；两种表示的维度、结构和训练目标不同。

**本文目标：** 在保持视频宿主参数冻结的条件下，利用它已经学到的生成能力获得显式3D动作，并尽量改善文本语义覆盖。作者希望让动作成为视频生成过程的一条伴随输出，而无需另行从零训练同等规模的动作基础模型。

**切入角度：** 作者先探测视频DiT在不同噪声水平的速度场特征，发现其中有可恢复的动作区分信息。因而不只看最终视频，而是研究怎样在整个去噪轨迹上读取这种信息，再把它变成动作分支可以使用的条件。

**核心 idea：** 先用配对数据把动作潜空间与视频潜变量的低维投影对齐；再让两个分支共享同一流匹配时刻，由轻量PMD融合不同视频层的特征，预测动作潜变量的更新方向。视频分支持续提供条件，动作分支持续去噪，最后由动作解码器输出连续运动。

## 方法详解

### 整体框架

整个方法分为**潜空间对齐训练、同步速度场训练、联合采样**。第一阶段解决“视频特征怎样对得上动作表示”；第二阶段解决“在任意去噪时刻，怎样利用宿主特征预测动作更新”；推理时从两份独立噪声出发，同步运行视频宿主与动作分支，最后分别解码。[图2、公式1–6][html]

读图先看训练区如何获得动作编码器、解码器与视频投影，再沿推理区的两条噪声流往下走，最后展开PMD内部的特征融合和注意力模块。图中冻结与可训练模块分别标明；训练监督支线不表示推理时还必须提供真实动作或参考视频。

### 关键设计

1. **先探测视频特征：证明存在可读出的动作信息，再设计解码器。**

   作者将HumanML3D动作放入UE5，在10个视角下渲染，并随机化人物身份、服装和背景，构造动作相同而外观不同的样本。冻结Wan，读取不同去噪时刻的速度场特征；以HY-Motion作为专门动作模型的参照，测试从400个候选中检索对应动作。后文的层深度比较属于生成器消融，不能与这组探测实验混为一项。[实验设置、图1][html]

   Wan特征的top-1检索率约为24%–31%，高于400选1的0.25%随机水平；相对HY-Motion的对应检索准确率，达到54%–81%，最高相对比例出现在σ=0.9。这里的81%是<strong>两种表征检索准确率的比值</strong>，不是81%的生成动作正确，也不是从真实视频恢复人体的精度。

   这组实验支持“冻结视频模型中有可利用的动作信息”，但它是在受控渲染数据上的探测，不能证明内部特征已经显式分离了动作、视角和身份。HY-Motion用于这一参照实验，不是PMD推理链中必需的第二个动作生成器。

2. **第一阶段对齐：把不同形状的表示变成能对应的动作序列潜变量。**

   原始动作记为m，形状是T×dₘ；动作Transformer编码器Eₘ将它变为T×d_z的连续潜变量xᵐ₀，再由Dₘ重建。视频经冻结VAE得到的是Tᵥ×H×W×C张量，不能直接与动作序列相加，因此引入视频投影Pᵥ：先逐帧用空间CNN压缩空间与通道维，再通过时间插值对齐到T帧。[方法“Stage 1”][html]

   <div class="equation">xᵐ₀ = Eₘ(m)，xᵛ₀ = Pᵥ(VideoVAE(video))；二者形状均为 T × d_z。<br />L₁ = ‖Dₘ(xᵐ₀) − m‖² + λ₁‖xᵐ₀ − xᵛ₀‖² + λ₂‖xᵐ₀‖²。</div>

   第一项要求潜变量保留可重建动作的信息，避免只为对齐而塌缩；第二项拉近配对视频与动作的表示；第三项约束潜变量幅值。Pᵥ也参与第一阶段训练，所以不是拿一个任意视频向量硬塞给动作网络。[公式1][html]

   这里的“共享空间”指经过投影后的表示几何和形状兼容，原始视频潜变量仍是高维时空张量。原文仅以dₘ描述运动学维度，未完整列出具体关节数、旋转参数化和通道清单；不能据相邻工作自行补成263维或某个SMPL布局。

3. **共享流匹配时刻：让两个分支在相同生成进度交换信息。**

   对视频和动作各自构造从干净样本到高斯噪声的插值路径。保留原文视频变量的撇号：x′ᵛ指视频VAE的原始高维潜变量，区别于第一阶段Pᵥ投影后的xᵛ。公式2–3为：

   <div class="equation">x′ᵛσ = (1 − σ)x′ᵛ₀ + σεᵥ，xᵐσ = (1 − σ)xᵐ₀ + σεₘ；<br />目标速度分别为 εᵥ − x′ᵛ₀、εₘ − xᵐ₀，σ ∈ [0,1]。</div>

   σ=1对应噪声，σ=0对应干净潜变量；采样沿1→0推进。两个分支使用同一个σ，但<strong>εᵥ与εₘ独立采样</strong>。耦合来自匹配的进度与逐步传入的视频特征，而不是两边使用相同随机数。[公式2–3][html]

   同一个σ也不自动保证两条潜变量轨迹相等，更不保证输出关节与画面人物逐帧完全重合。它提供的是使训练和条件读取保持一致的时间坐标，具体跨模态对应仍由对齐损失和PMD学习。

4. **多层特征适配：先解决宿主中间层的分布差异，再让动作分支读取。**

   作者从Wan的40层DiT中选择5层，默认索引为{9,19,24,29,39}，并非只读取最后一层。每层特征fℓ都要经过三个步骤：<strong>冻结的宿主输出头 → 该层的小型可训练adapter → 冻结的Pᵥ</strong>，得到T×d_z的对齐特征f̂ℓ。[图2、图4、实验设置][html]

   宿主输出头原本面向最后一层的分布，中间层直接通过它会有分布差异，因此adapter用于校正；第一阶段已经学好的Pᵥ再把结果映射到动作可用的空间。这比简单拼接各层特征多了一个明确的跨层、跨模态接口。

   这一支读取的是生成过程中的表征，不是在每一步先渲染完整RGB视频、再调用外部人体姿态估计器。它也不是让动作网络反过来修改Wan：条件传递方向始终是视频宿主→动作分支。

5. **σ自适应融合：不同去噪阶段可以借用不同深度的特征。**

   固定平均所有层，会假设各层在所有生成进度下同样有用。作者用σ的嵌入tσ生成一组权重，再在层维度做softmax：

   <div class="equation">w(σ) = softmax(MLP(tσ))，kv_vid = Σℓ wℓ(σ) · f̂ℓ。</div>

   每个去噪步只计算一次融合结果kv_vid，供PMD的所有block复用。原图4中第29层持续占较大权重，其他层的贡献随σ变化；这说明网络学到了与生成进度有关的特征取舍。[公式4、图4][html]

   这里的权重作用于<strong>网络层与去噪进度</strong>，不是“第2秒由腿控制、第4秒由手控制”的动作时间表，也没有显式定义语义事件、身体部位优先级或用户编辑接口。

6. **PMD块：动作内部连贯性、视频运动先验与文本语义分别注入。**

   PMD默认有6个block，隐藏维256。每个block依次执行动作self-attention、对kv_vid的video cross-attention、对文本特征的text cross-attention，以及FFN：先让动作时间位置交换信息，再读视频生成线索，最后保留对原始文字的直接访问。[方法“Decoder blocks”][html]

   文本特征来自冻结文本编码器。保留独立文本分支有实际作用：视频特征虽然也受文字条件影响，却不一定完整保留动作所需的所有语义；消融中移除文本输入，会使MCC从0.57降到0.42。

   各子模块通过AdaLN接收σ条件。按原公式5，tσ产生缩放γ、偏移β和残差门α，使当前模块的输入变换与贡献大小随生成进度调整：

   <div class="equation">[γ, β, α] = MLP(tσ)，h ← h + α ⊙ f(γ ⊙ LN(h) + β)。</div>

   PMD输出的是动作潜空间的速度预测，并不是“跳舞、抬手、转身”等可执行符号列表；最后还必须通过潜变量积分和Dₘ解码，才能得到连续3D动作。

### 一个完整例子

沿用原图3的**Salsa dancing**提示，设希望获得一段萨尔萨舞动作。以下步骤解释计算链；潜变量的中间含义是教学说明，并非本站实际运行结果。

1. **文本与两份噪声。** 文本编码器处理提示；系统分别初始化视频噪声εᵥ和动作噪声εₘ。此时没有事先给定的参考视频，也没有输入一段萨尔萨舞动捕。
2. **读取正在形成的视频运动。** 在σ较大的早期，Wan对当前视频潜变量做一次前向计算。PMD读取指定层，经输出头、adapter与Pᵥ得到动作长度上的条件特征，再按当前σ融合。
3. **更新动作潜变量。** 当前动作潜变量通过6个PMD块，同时参考自身时序关系、视频条件和文字，预测从当前状态向下一采样状态的更新方向。
4. **重复同步推进。** 两条流按共同日程继续从σ=1走到0。随着视频人物与运动逐渐形成，动作分支持续获得新条件；它不是只在开头读取一次静态视频摘要。
5. **解码为可用输出。** Dₘ将最终动作潜变量还原为连续3D运动，宿主视频VAE可输出相应视频。作者展示了语义相符的案例，但该例不提供指定脚落点、固定舞步顺序或精确节拍时刻的硬保证。

固定同一视频生成轨迹而改变εₘ，还可以得到多种相关动作实现。原图6正是测试这一随机自由度；因此这套机制学习的是与视频条件相容的动作分布，而非给每个视频确定唯一的3D逆解。

### 训练/推理

**第一阶段：** 配对视频与动作分别经过冻结视频VAE和可训练动作编码器；联合训练Eₘ、Dₘ、Pᵥ，用重建、对齐和幅值正则约束潜空间。原文没有完整披露这一阶段的轮数、学习率和独立耗时。

**第二阶段：** 从配对数据取干净潜变量，随机采样σ和两份独立噪声。冻结宿主在加噪视频潜变量上做一次前向，PMD学习速度目标εₘ−xᵐ₀。损失是预测速度与目标速度的均方误差；宿主DiT、视频VAE、文本编码器及第一阶段三个模块全部冻结，仅更新PMD、逐层adapter与融合MLP。[公式6][html]

训练每次抽取一个σ计算监督，不需要在每次训练迭代里完整生成一段50步视频。推理则联合采样50步；“single joint pass”指完成一趟联合生成流程，不能理解成一次网络前向或单步生成。

**宿主与文本条件：** 去掉视频宿主特征，MCC由0.57降至0.29、MG由0.96降至0.46；去掉直接文本条件，分别降至0.42和0.74。两路条件都有贡献，视频特征不能完全替代文字输入。

**潜空间对齐：** 取消Stage 1对齐，MCC降至0.21、MG降至0.38，Jitter升至0.045。这是表中最明显的退化，支持先处理跨模态表示差异的必要性；它不意味着对齐损失已经保证最终3D动作与视频严格一致。

**跨层融合：** 只用最后一层或L29，MCC分别为0.43、0.46；多层静态平均为0.47，完整动态融合为0.57。结果支持多层信息与σ相关加权共同起作用。

**层数与深度：** 浅层组合和3层组合的MG分别为0.87、0.89；7层与默认5层均为0.96。7层的Jitter和FS略优，MCC略低，因此不能说5层在所有指标最优。原文默认采用5层，强调跨深度覆盖，未提供各层数组合的运行时间或显存对照。

**轨迹与随机性分析：** 原图5在184个提示上比较中心化潜变量余弦相似度，并展示联合PCA；图6固定视频条件，对50段视频各采样8个动作种子，动作之间的pairwise MPJPE为**40±12 mm**。这是同条件输出的差异尺度，<strong>不是与真值相比的关节误差</strong>，也不证明这些差异全都语义有效。

### 关键发现

1. **较少新增参数能够带来较强文本匹配，但优势依赖大宿主。** Protocol B的MCC/MG达到0.58/0.72，高于表内ViMoGen的0.53/0.68；冻结的14B先验不计入19M可训练参数，因此该结果不能换算成同等幅度的总算力节省。
2. **语义与分布指标存在取舍。** PMD在HumanML3D的三项R-Precision最高，但FID=0.098，高于DisCoRD的0.032和MoMask的0.045；MM-Dist亦略高于GenM3。作者以更广的宿主分布解释FID差异，这是解释性假设，实验没有单独隔离并证明这一因果关系。
3. **对齐接口比简单接上条件更关键。** 去掉Stage 1比去掉文本分支退化更大，说明动作流并非天然就能消费视频DiT特征。跨模态几何、层间分布和生成进度必须一起处理。
4. **物理质量没有被语义提升自动解决。** Protocol B中PMD的Jitter和Foot float都不是最低；接触、足滑和多样性需要分别评价，不能从MCC提升推导它已适合物理角色或机器人直接执行。

## 亮点与洞察

- **持续读取生成过程：** 视频先验不只是一个离线标签或最终视频结果，而是在每个去噪时刻提供新的条件。这为跨模态迁移提供了比一次性特征蒸馏更细的接口。
- **把表示适配与生成学习分开：** 第一阶段负责可解码且相容的潜空间，第二阶段负责速度场。组件消融表明这一分工对当前实现很重要，便于识别失败来自表示还是生成器。
- **冻结宿主保留原有视频能力：** PMD只读取宿主特征，不用动作损失反向改变视频主干；工程上可以单独迭代动作侧模块，但仍要承担宿主的前向成本。
- **文本具有独立通道：** 直接文本cross-attention与视频先验互补，避免把所有语义责任都压给被适配后的视觉表示。
- **连续潜空间的随机解码：** 同视频可对应多种动作实现，说明显式3D输出不必由确定性姿态恢复唯一指定；同时也提醒我们，条件一致性与几何唯一性是两件事。

<span id="reading-6" class="reading-anchor"></span>
## 局限与展望

1. **推理负担仍然很大。** 19M侧网络之外，每一步都运行14B视频宿主，原文使用50步采样。没有延迟或显存实测，不能归为已验证实时动作方案；去掉末端RGB解码可能减少部分开销，但不能免掉宿主DiT计算，这仅是计算图层面的推论。
2. **表示和训练细节不足以保证独立复现。** 第一阶段配置、具体运动学通道、部分视频配对制作方式没有完整展开；数据组成与Protocol A测试集表述也有歧义。截止核查日期未找到官方完整实现和PMD权重，不能声称已开箱复现。
3. **继承先验也会继承错误。** 宿主对罕见动作、视角和长序列的错误可能传给动作分支。潜空间接近不等于关节级正确，论文没有提供硬接触、重心平衡、目标位置或物体交互约束求解器。
4. **语义评估仍受代理模型影响。** Gemini对渲染动作的评分有助于覆盖长尾语义，但不替代逐帧事件核查或真实用户研究；主表未提供足以比较所有小幅差异的统计显著性分析。
5. **控制范围主要仍是文本。** 本文没有实现用户指定关键帧、身体部位时间线或同一部位多条件冲突处理。若用于可编辑角色，需要另外设计显式约束接口并在解码动作上验收，不能把动态层权重当作这些控制能力。
6. **后续值得验证的方向：** 将宿主逐步提供的特征蒸馏到较小动作模型，或只在部分采样步调用宿主，可能降低成本；这是基于当前结构的研究设想，本文没有给出这些加速版本的结果。

## 相关工作与启发

- **[Wan2.1][wan]：** 本文使用的冻结视频宿主。PMD复用其多层特征与流匹配生成进度；Wan本身的公开代码不包含本文新增动作对齐器与PMD的训练成果。
- **[HY-Motion 1.0][hy]：** 作为专门的文本动作模型，为表征探测提供参照。本文比较“视频特征能读出多少动作信息”，不是用HY-Motion在推理时替代Dₘ解码，也没有把其知识蒸馏作为默认训练步骤。
- **[ViMoGen][vimogen]：** 同样研究视频先验如何扩大文本动作泛化，并提供本文使用的数据资源。ViMoGen有动作生成分支及摆脱视频依赖的light版本；PMD强调读取冻结宿主的每步特征，本文没有相应的不依赖视频宿主的学生版本。
- **[EchoMotion][echo]：** 探索视频与动作的双模态联合生成。本文将宿主保持冻结，训练伴随解码器，突出单向利用现成视频生成过程的路线；不能因为都输出两种模态，就把它们的训练与交互方式视作相同。
- **[MoAlign][moalign]：** 关注面向运动的表征对齐，用于视频扩散模型。本文也重视跨表示的对齐，但最终目标是从视频模型获取显式3D动作，输出对象和适配方向有所不同。[原文相关工作][html]
- **[DisCoRD][discord]：** 也用流匹配恢复连续动作，但其条件是离散动作token；PMD的条件是同步运行的视频宿主特征与文字，既没有以前置动作token序列指定内容，也不以离散码本作为核心接口。
- **启发：** 借用强模型时，应明确它在什么时刻提供哪一种表示，接收端怎样适配，最终输出能保证什么，以及宿主能否在部署时移除。PMD对前两点给出了具体实现，后两点仍留下成本与可控性方面的研究空间。
