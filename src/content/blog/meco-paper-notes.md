## 一句话总结

MECo 将语音和参考动作都转换为离散 token，把参考动作放进大语言模型的 system prompt，让模型在参考动作的范围内重新组织与语音相配的手势。它用分阶段微调与示例扰动避免直接复制，并支持把不同身体部位的参考、图片、视频和文字统一接到动作示例接口。

## 研究背景与动机

**领域现状：** 共语手势生成通常从说话音频预测身体动作。为了让同一句话呈现不同的表达方式，一类方法加入说话人、情绪或风格标签；另一类方法用一段动作作为参考，尝试迁移它的姿态习惯、运动幅度或动态特征。

**现有痛点：** “活泼”“沉稳”这样的标签无法精确描述用户想要的动作；把整段参考动作压缩为一个风格向量，也可能只保留粗略情绪，丢掉某些具体姿态和局部运动。例如，用户希望角色沿用参考视频中偏高的手势位置和某种挥手方式，一个宽泛风格标签未必能表达这些要求。

**核心矛盾：** 参考动作包含用户想保留的运动细节，却对应另一段时间结构；生成动作仍应配合新的语音。完全照搬会破坏语音适配，压缩得过狠又失去示例控制。困难在于保留可用的动作内容，同时允许模型重新组织动作顺序和节奏。

**本文目标：** 给定语音和动作示例，生成既接近参考动作特征、又适合当前语音的共语动作；参考可以不覆盖全部身体，也不必是一整段完整表演。论文主要关注运动分布、示例相似度与人类偏好，并不追求逐帧轨迹硬匹配。

**切入角度：** 作者借鉴示例提示的思路，不先把动作变成文字标签或单一风格向量，而是把动作编码为 token，直接作为语言模型生成时可见的上下文。这样可以保留多个动作原型，并利用已有自回归模型完成条件组合。

**核心 idea：** 先训练动作 tokenizer，再让语言模型依次学会新 token、语音到动作、语音加示例到动作。训练时把参考 token 去重、打乱和随机删减，让模型学习“使用这些动作成分”，而不是复读完整答案；推理时再用采样偏置调节参考动作的出现程度。

## 方法详解

### 整体框架

MECo 的主线是“语音 token + 示例动作 token → 微调后的 Qwen → 新动作 token → 动作解码”。训练先准备动作 tokenizer，再分三个阶段训练语言模型；推理时复用这些模块。图片、视频和文字先通过外部重建或检索得到动作示例，并没有直接作为原始视觉/文字控制信号送进同一个端到端生成网络。

### 关键设计

1. **分部动作 token：训练时使用残差量化，生成时只预测基层。**

   动作包括根节点的平面速度、转向速度、高度，以及关节的 6D 旋转。论文把身体分成上身、下身、手部，各自训练动作编码器、量化码本与解码器。这样，参考动作缺少手指信息时，不必伪造手部条件；不同部位也可以使用不同示例。

   动作 tokenizer 采用残差向量量化：基层先近似连续特征，后续层编码剩余信息。训练时随机丢弃后续残差层，迫使基层保留足够多的运动信息。**后续 LLM 建模和推理只使用基层 token，不再预测完整残差栈。** 它不是把六层 RVQ 全部展开后交给语言模型生成。

   这一取舍降低了生成序列长度。附录 B 的重建实验表明，只用基层比使用所有残差层略差，但比完全不用残差训练的普通量化方案更好。不能因此认为细节完全无损；tokenizer 仍是有损的运动表示。[§3.1](https://arxiv.org/html/2507.20220v1#S3.SS1)、[附录 B](https://arxiv.org/html/2507.20220v1#A2)

2. **三阶段适配：先接入新词表，再学语音映射，最后加入动作示例。**

   HuBERT 将语音编码成离散单元，动作 tokenizer 输出动作索引。原始 Qwen 的词表不认识这些 token，作者扩展词表并解除输入嵌入与输出投影的权重绑定。

   第一阶段冻结语言模型主体，只训练新模态相关的嵌入和输出投影，用语音、动作各自的下一个 token 预测任务建立可用的表示。第二阶段解冻语言模型，进行全参数监督微调：user 放语音，assistant 输出对应动作。第三阶段继续全参数微调，在 system 中加入动作示例。

   因此，这不是只写一个提示词就能工作的现成 Qwen，也不是 LoRA 微调方案。三阶段的作用不同：第一阶段减少新词表对原有表示的干扰，第二阶段建立语音与动作的基本对应，第三阶段学习如何受示例控制。没有额外把语音转写文本作为主要训练监督。[§3.2，式 2–5](https://arxiv.org/html/2507.20220v1#S3.SS2)

3. **扰动动作示例：保留动作成分，打破对答案时序的复制。**

   训练集中没有“任意参考动作—新语音—目标动作”的人工三元组。作者直接从目标动作生成参考提示，但若完整保留目标 token 顺序，模型可能复制答案而忽略语音。因此，参考 token 会经过去重、打乱和随机 dropout。去重减少反复出现的 token，打乱移除原始顺序，dropout 模拟用户只给出部分动作内容的情况。

   这里有一个重要区别：模型看到的是示例中可用动作成分的提示，不是必须逐帧遵循的时间表。完整序列的节奏和过渡仍要由语音条件与自回归历史共同决定。

   第三阶段除了动作 token 的交叉熵，还惩罚模型给参考动作中未出现的 token 分配过多概率。计算这个额外惩罚时，使用未经 dropout 的原始示例 token 集，避免把被随机删掉、其实合理的动作也一并排除。它是概率上的偏好约束，并非禁止出现新 token 的硬限制。[§3.2.3，式 4–5](https://arxiv.org/html/2507.20220v1#S3.SS2.SSS3)

4. **统一控制入口：调节示例采样偏置，并把其他模态先变成动作。**

   推理时，音频作为 user query，参考动作作为 system prompt，初始姿态或上一段末尾的动作码作为 assistant 的起始内容。长音频按训练长度分段生成，下一段带入前一段最后三个动作码，并对齐相应音频，以减少接缝。

   对示例 token，采样前增加偏置 β，再根据已经采样的次数施加 γ 衰减，论文式 6 写为 `logit′ = (logit + β) × γᵗ`。默认 β=5、γ=0.9；设计意图是提高示例动作出现频率，同时避免总重复同一 token。它调节生成分布，不保证某动作在指定毫秒发生。

   多模态入口也围绕示例展开：视频通过单目动作捕捉获得 SMPL-X；图片通过 SMPLify-X 获得静态姿态；文字先让 ChatGPT 检查已有动作标注，命中则取对应动作，否则通过 TMR 检索相近动作。**“支持文字控制”在这里包含检索链路，不能解释成 MECo 直接理解任意动作指令。** [§3.3](https://arxiv.org/html/2507.20220v1#S3.SS3)、[§4.5、图 4–5](https://arxiv.org/html/2507.20220v1#S4.SS5)

### 一个完整例子

假设要让角色在一段讲解语音中，沿用示例 A 的上身挥手方式，同时保持示例 B 的下身站姿。下面是基于论文图 5 的**教学示例**，不声称这些具体姿态和 token ID 是作者的实测输出。

1. **准备条件。** 语音不必与两段参考动作原来的音频相同。对 A 只取上身，对 B 只取下身；如果没有手部参考，就不强行提供该部分的具体例子。
2. **转换成提示。** 分部 tokenizer 将参考运动编码为各自的基层 token。提示模板明确区分 upper、lower、hand；新语音经 HuBERT 变成音频 token。这里的动作索引是学习到的码本编号，不是“挥手”“站立”这样的可读动作标签。
3. **联合生成。** 微调后的 Qwen 根据音频、示例成分和已经生成的动作 token，预测接下来的动作。示例偏置提高相关动作出现概率，但模型仍需选择何时抬手、怎样过渡，而不是照搬 A 的原时间轴。
4. **解码与继续。** 三个部位的生成结果分别解码并组合为全身运动；超过一段的音频继续使用尾部动作码作为下一段前缀。最终得到的是新的说话动作，而非在原动作文件上只修改某几个关节。

这个过程允许分部参考，却没有固定脚部接触、严格轨迹或未编辑部位逐帧保持的保证。若示例来自质量较差的视频重建，错误也可能经 tokenizer 传递到生成结果中。

### 训练/推理

- **数据与协议：** BEAT2 全库有 60 小时、25 名说话人，但本文遵循基准，只用第 2 名说话人的训练/测试划分；不能把它写成利用全部 60 小时训练。ZeroEGGS 为一名女性、19 种风格的约 2 小时英语独白，按原工作划分重新训练 MECo。
- **动作 tokenizer：** 30 FPS，时间下采样 4 倍，码本大小与特征维度均为 512；原文设置 Q=6。训练采样 64 帧，batch 256，学习率 4×10⁻⁴，commitment 权重 0.1。后续只用基层，不做残差补全。
- **语言模型：** 默认 Qwen2.5-0.5B-Instruct。4 秒样本对应 200 个 50 Hz 音频 token，三个部位各 30 个动作 token，共 90 个。三个阶段每 GPU batch 分别为 32/20/12，梯度累积 4/6/10，学习率 2×10⁻⁴ / 5×10⁻⁵ / 5×10⁻⁵。
- **计算开销：** 作者报告全部模型用 4 张 RTX 4090 训练 22 小时。单张 RTX 4090、i9-13900KF 下，Hugging Face 路径为 147 token/s，vLLM 为 270 token/s；这些是报告的生成吞吐，不是输入语音到可播放动作的端到端延迟。
- **离线边界：** 附录 G 明确说明 tokenizer 非因果，当前动作会受未来 token 影响，因此本方法是离线生成。论文另称每秒可生成 36 秒动作，但其正文又列出每 4 秒共 90 个分部 token；两者若使用同一种 token 计数，不能直接对应。本文保留 token/s 原报告，不将其换算为经验证的全身实时倍率。

上述设置来自[§4.1](https://arxiv.org/html/2507.20220v1#S4.SS1)及[附录 G](https://arxiv.org/html/2507.20220v1#A7)。当前公开脚本使用单一 `<|motion_…|>` token 流及一套动作 tokenizer，与论文三部位模板存在差别；公开文件可见不等于本文所有控制路径已经复现。

### 消融实验

**词表初始化与冻结策略：** 保留第一阶段但解除主体冻结，BEAT2 FGD 从 3.401 恶化到 8.512，BC 从 7.346 降至 4.551；直接跳过初始化阶段的 `w/o freeze&pretrain` 为 FGD 4.575。原始 Qwen 的 MMLU 为 46.50，正常 MECo 为 46.27，第一阶段不冻结则降为 24.63。局部适配新词表与立即更新整个模型差别很大。[原表 1、3](https://arxiv.org/html/2507.20220v1#S4.T3)

**独立语音到动作阶段：** 去掉第二阶段，直接从新 token 初始化进入示例控制训练，无示例 FGD 从 3.401 变为 4.845，有示例从 2.999 变为 4.413。示例控制训练虽然也包含语音，仍未替代专门建立语音—动作映射的阶段。[原表 1](https://arxiv.org/html/2507.20220v1#S4.T1)

**预训练与模型大小：** 随机初始化同架构的 `w/o llm` 达到 FGD 10.32，使用非 Instruct 底座为 4.133；默认模型为 3.401。换成 7B 后，无示例/有示例 FGD 为 3.456/3.195，没有超过 0.5B 的 3.401/2.999。7B 的 Diversity 更高，因此“更大完全无益”也不准确；主要质量指标没有显示规模收益。[原表 1](https://arxiv.org/html/2507.20220v1#S4.T1)

**残差量化训练：** 只改变 tokenizer 的残差层使用方式，原表 5 的重建结果如下；这些是重建行，不能与主表的生成结果当作同一任务。

| 训练和推理均不用残差层 | 2.974 | 7.940 | 12.48 |

下游生成中，移除残差训练使 FGD 从 3.401 变为 3.762。作者指出较高 BC 可能来自无意义抖动，因此没有据 7.940 判定最后一种设置最好。[附录 B、原表 5](https://arxiv.org/html/2507.20220v1#A3.T5)

**额外文本对齐：** 加入语音转写和 text-to-gesture 训练后，未缩放 FGD 为 0.4104，弱于默认 0.3401；MMLU 从 46.27 降至 43.73。这里的文本是语音转写，不是多模态控制入口中的动作检索说明，二者不要混为一谈。[附录 D](https://arxiv.org/html/2507.20220v1#A4)

### 关键发现

1. **优势集中在动作分布与示例一致性。** MECo 的 FGD 和示例距离优于选取的比较方法，但 BC 没有超过 SynTalker 或 EMAGE。它并非所有指标都领先。
2. **示例控制依赖训练设计。** 新词表的稳定接入、独立语音映射和去时序化的示例提示共同建立能力；不能把效果归结为“LLM 天生理解动作”。
3. **更高 BC、更多参数都不自动代表更好动作。** tokenizer 消融暴露了抖动对节拍指标的影响；7B 也没有改善关键 FGD。评价需要同时看运动质量、参考相似性和可见失败。

## 亮点与洞察

- **直接保留示例成分：** 参考不必先压成情绪标签或单一风格向量，多个离散运动成分可以直接进入生成上下文，给细粒度参考控制留下空间。
- **用合成条件避免昂贵三元组标注：** 从目标动作构造扰动示例，既提供控制监督，又主动打断复制捷径。这是一种数据构造与训练目标配合的设计。
- **少量动作条件可以组合：** 三部位 tokenizer 让不完整参考和不同来源参考能够进入同一系统；不过生成后的协调仍是学习结果，不是物理约束。
- **接口扩展与核心模型分开：** 视频重建、图片拟合和文字检索都以动作示例为交汇点。它为工程扩展提供明确接口，也让每个上游工具的误差来源可被辨认。

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

1. **离线吞吐不等于流式生成。** 非因果 tokenizer 使用未来上下文；长音频分段与尾码续接没有消除这一限制。替换因果 tokenizer 是作者提出的方向，而非本文已完成的结果。
2. **视频提示有明显域外问题。** 作者观察到野外视频经单目动作重建后，再进入 VQ-VAE 会出现较大重建误差，导致控制质量下降。原始视频质量、姿态估计误差和 tokenizer 泛化都会影响最后结果。
3. **缺少关节级硬控制。** 附录 G 明确指出难以精确控制角色轨迹。部位提示与采样偏置不能保证每个目标位置、接触点或发生时刻都满足要求。
4. **脚滑等物理伪影仍存在。** 论文建议结合 IK 或物理仿真；当前方法没有把地面接触、碰撞和力学一致性变成可靠保证。
5. **评测覆盖有限。** BEAT2 使用一个说话人，ZeroEGGS 主要是一位表演者；示例一致性实验只有 20 段参考。它们不足以证明跨人物、跨文化、长时间角色个性或复杂场景交互的稳定性。
6. **公开范围需要逐项核对。** 当前仓库提供单流 BEAT2 路径和权重，代码模板与论文三部位模板不同；未见完整视频/图片/文本适配器及所有数据集的对应发布文件。本次只核查文件与源码，没有验证整套运行结果。

## 相关工作与启发

- **[ZeroEGGS](https://github.com/ubisoft/ubisoft-laforge-ZeroEGGS)：** 同样用动作示例控制共语运动，主要把示例编码为风格条件；MECo 改为把离散动作成分直接放进生成提示。
- **[SynTalker](https://github.com/RobinWitch/SynTalker)：** 同时关注语音与额外动作控制，通过对齐表示和生成条件协调运动；MECo 将显式示例 token 作为主要控制接口，两者在本文 BEAT2 示例实验中直接比较。
- **[EMAGE](https://pantomatrix.github.io/EMAGE/)：** 提供分部动作建模与 BEAT2 基准的重要参照。MECo 也使用分部表示，但核心生成器换成扩展词表后的自回归语言模型。
- **[MoMask](https://github.com/EricGuo5513/momask-codes)：** 残差量化训练给本文提供启发；MECo 为缩短序列只生成基层，不沿用完整残差补全流程。
- **[TMR](https://mathis.petrovich.fr/tmr/)：** 在本文文字控制入口承担 text-to-motion retrieval，而非替代最终的语音条件生成器。
- **启发：** 若要做角色动作控制，可以让上层输出可检查的参考片段或参考成分，再由语音生成器完成时间组织；精确指向、接触和场景规则仍需要额外接口与输出验证。
