## 一句话总结

UniMotion让每一帧人体动作和描述这一帧的文字向量共享同一个时间位置，再给动作、局部文字各设一个扩散噪声步数。这样，同一个模型既能读脚本生成动作，也能为已有动作找出逐帧标签，还可以联合生成两者；用户改写其中一段标签后，便能重新生成语义有变化的动作。

## 研究背景与动机

**领域现状：** 文生动作模型通常读一句描述整段动作的话，例如“走过去，弯腰拿起东西，再走回来”。另一类方法让用户给出带持续时间的短动作脚本。前者方便表达总体意图，后者方便安排不同动作发生在什么时候。

**现有痛点：** 全局句子往往未交代转身、停顿等动作的具体时刻。完整局部脚本又要求用户提前知道每段要持续多久，还可能遗漏跨段保持的意图，例如“手始终举在头顶”。同样的困难出现在反方向：整段描述能概括发生了什么，但很难直接告诉编辑者该改哪几帧。

**核心矛盾：** 合成与理解需要同一份动作—语义对应关系。分别训练两个系统，会让一个系统生成的动作重新进入另一个系统做描述；仅训练文本到动作，又缺少把已有动作翻译成可编辑时间线的机制。

**本文目标：** 一次训练得到能够使用全局句子、局部脚本或两者共同生成动作的模型，同时支持由动作产生局部文字，以及同步生成配对的动作与标签。

**切入角度：** BABEL提供来自AMASS动作的局部时间标注，HumanML3D提供部分相同动作的整段句子。把两个来源按原动作及时间区间对齐，一条训练序列就有三种信息：每帧姿态、该帧的动作标签，以及整段描述。

**核心 idea：** 学习动作和局部文字的联合分布，把全局句子作为可选条件。已知的一路保持干净，未知的一路从噪声开始；两路都未知时一起去噪。相同的网络由此承担不同任务。[正式稿§3–4、图2](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=4)

## 方法详解

### 整体框架

输入包含动作序列 x、逐帧文字向量 y、可选全局描述 c。扩散的对象是 x 和 y 两个连续序列。通过同帧拼接，模型在每个时间位置同时看到该帧的动作和文字特征；独立的噪声步数告诉模型各有多少信息已知。去噪输出干净动作与干净局部文字向量，后者再通过标签数据库检索变成可读词组。

[查看完整架构图](/paper-notes/unimotion/architecture.svg)。先看每个训练样本怎样取得整段与局部文字，再看两路噪声如何控制输入。动作时间决定“哪个姿态配哪个词组”；扩散步数决定“该路输入有多干净”。后者本身不指定动作应出现在哪一帧。

### 关键设计

1. **在动作时间轴上对齐两种标注。**

   HumanML3D的一条动作通常配有多句整段描述。BABEL为原动作中的不同时间区间标注“行走”“转身”“坐下”等短语。作者追溯到两者共有的AMASS时间段，把短语映射到对应帧。因而同一短语可以连续覆盖一段动作；“逐帧文字”描述的是标注的时间分辨率，并不要求每一帧写一句不同的话。

   一条联合训练样本记为 (x₀,y₀,c)：x₀是每帧263维的HumanML3D连续动作特征，y₀是时长相同的局部文字嵌入，c是整段句子。论文还比较仅有BABEL局部标注的训练设置。读数据来源时应以§4.3与表1为准，其中HML给整段句子，BABEL给局部时间标签。[正式稿§4.3](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=5)、[作者补充B、图7](https://coral79.github.io/uni-motion/paper/unimotion.pdf#page=12)

2. **每帧扩展一个动作向量，用预训练文字嵌入表示局部语义。**

   对第 i 帧，把动作 xᵢ 与该帧对应的局部文字 yᵢ 沿特征维拼接，得到一个时间位置。N帧产生N个这样的表示。作者尝试过先放N个动作元素，再放N个文字元素，让模型自己寻找对应关系，报告效果较差；最终采用直接同帧对齐。全局文字 c 经CLIP编码，作为额外的条件元素进入Transformer，不受局部文字的扩散过程影响。

   为免局部文字向量过大，作者对CLIP特征做PCA。正式主文写降至50维，项目补充D写从256维降至51维、保留约70%原始方差，公开配置和示例检查点名使用51。读公式时只需记住 y 是低维连续文字向量；复用公开资源时应采用与检查点相同的PCA和归一化参数。代码中CLIP编码器冻结，动作去噪模型沿用MDM架构并重新训练。[正式稿§4.2](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=5)、[补充D](https://coral79.github.io/uni-motion/paper/unimotion.pdf#page=14)、[固定代码中的同帧拼接](https://github.com/Coral79/Unimotion/blob/b300159b65277060274c0e2922cdf7983ed4c745/model/unimotion.py#L308-L368)

3. **两个扩散步数让同一个模型切换任务。**

   模型为动作选噪声步 tₓ，为文字选 tᵧ。两者采用同一套噪声日程，但可以在训练时采到不同的步数，分别向干净两路加入高斯噪声。网络接收带噪的 x、y、两个步数和可选 c，同时预测原始动作与局部文字嵌入，使用两路均方误差。式3可简写为

   <div class="equation">(x̂₀, ŷ₀) = G(xₜₓ, yₜᵧ, tₓ, tᵧ, c)，　L = E[‖x̂₀−x₀‖² + ‖ŷ₀−y₀‖²]。</div>

   实际使用时，可以按下表读“哪些信息来自用户，哪些由模型生成”。T表示从高噪声开始，0表示已知干净条件；给定的一路会在采样过程中保持为输入条件。

   | 用法 | 已知条件 | (tₓ,tᵧ) 起点 | 读取的结果 |
   |---|---|---|---|
   | 局部脚本生成动作 | 干净 y，可选 c | (T,0) | 动作 x |
   | 为动作生成时间标签 | 干净 x，可选 c | (0,T) | 局部文字 y |
   | 整段句子生成动作及标签 | c | (T,T) | 配对 x、y |
   | 无条件联合生成 | 无 c，也无干净 x 或 y | (T,T) | 配对 x、y |

   例如，全局条件“手举过头顶挥动”可以与局部脚本“行走，然后坐下”一起使用。全局描述不只属于手臂，局部描述也不限定于腿部，它们靠学习协调；作者用互补条件演示这一效果，没有为身体部位设置显式硬掩码。[正式稿§4.1、§5.2](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=4)、[补充算法2–3](https://coral79.github.io/uni-motion/paper/unimotion.pdf#page=14)

4. **动作理解的文字输出经过标签检索。**

   给定动作，反向扩散先得到每帧文字嵌入。再从预计算的标签库取最近的短语，连续相同标签就可以形成可读的时间段。当前公开实现的默认检索是欧氏距离最近一邻。标签边界源于逐帧预测，输出词表受数据库覆盖范围限制；数据库以外的新动作描述即使可被CLIP理解，也不一定能作为新的输出短语被写出来。

   论文的视频注释案例先用外部人体姿态估计器把YouTube画面转换为三维人体动作，再由UniMotion标注。衣物、物体和场景细节没有随RGB画面直接进入这个模型。补充中的ChatGPT-4o和MotionGPT是单独的定性比较，未参与UniMotion核心训练或推理。[正式稿图4](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=7)、[作者补充G](https://coral79.github.io/uni-motion/paper/unimotion.pdf#page=16)、[公开标签检索](https://github.com/Coral79/Unimotion/blob/b300159b65277060274c0e2922cdf7983ed4c745/sample/generate.py#L479-L541)

5. **区分论文的脚本重生成与公开代码的区间重绘。**

   论文图1的编辑链先由粗句子生成动作和局部脚本，用户改变脚本某段，再把新脚本作为条件重生成动作。作者还展示“已有动作 → 局部脚本 → 同语义的新动作”的变体。这个语义中转会丢失姿态、根路径、个体风格等细节，因此保留原脚本中的其他词组，只说明其他条件仍然存在。

   作者当前发布的区间编辑脚本提供更具体的例子：输入已有动作和改后的局部脚本，将“向前走”改为“慢跑”，允许重绘索引 [83,135) 内的运动。区间外设置布尔掩码，在每个反向步骤把预测的干净动作特征替换为输入动作的对应特征。该操作位于263维表示空间。公开的关节恢复函数还要累积根朝向与平面位移，若中间一段改变了累积量，后续帧即使沿用原局部特征，世界坐标也可能发生平移或转动。论文没有报告未编辑区世界关节误差。[论文图1](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=1)、[编辑区间](https://github.com/Coral79/Unimotion/blob/b300159b65277060274c0e2922cdf7983ed4c745/sample/edit.py#L155-L170)、[反向步骤覆盖](https://github.com/Coral79/Unimotion/blob/b300159b65277060274c0e2922cdf7983ed4c745/diffusion/gaussian_diffusion.py#L1864-L1876)、[根运动恢复](https://github.com/Coral79/Unimotion/blob/b300159b65277060274c0e2922cdf7983ed4c745/data_loaders/humanml/scripts/motion_process.py)

### 一个完整例子：把走回来的片段改成跑回来

1. **给出总体意图。** 图1从“这个人向前走，捡起东西，然后走回来”的整段句子开始。模型将句子编码为 c，动作与局部文字两路均从噪声开始。
2. **取得可以检查的时间线。** 双路去噪得到一段动作和逐帧文字向量，近邻检索把向量还原为连续的动作短语，例如行走、转身、放下右手、站起等。原句没有给出各动作的精确边界，时间线是模型的一种生成结果。
3. **只编辑需要改变的语义。** 找到返程的“向前走”，把该时间段改成“向前跑”，保留前后其他短语和时长。新局部脚本作为干净 y，动作从噪声开始按新条件采样。
4. **验收动作本身。** 查看返程是否出现跑步、前后过渡是否连贯、捡起动作是否还在；如果目标还包括未改区三维坐标必须保持，就需要再检验局部特征掩码与重建后的世界坐标。图1展示语义编辑的例子，未给整套编辑成功率或逐帧保持数据。[正式稿图1、§5.2](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=1)

### 训练、推理与当前资源

补充D说明模型采用MDM式Transformer，在合并数据上从头训练，使用预训练CLIP，不需要先生成大语言模型文本。论文报告单张A100训练约40小时。正式式3将两个噪声步写为独立采样；补充算法1以10%概率置空全局条件。公开代码还保留针对条件/联合任务的可选步数组合路径。正文与补充没有给出统一的单片段推理时延。[正式稿§4–5](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=5)、[补充D](https://coral79.github.io/uni-motion/paper/unimotion.pdf#page=14)

## 实验关键数据

### 主实验设置

评测分别看短动作段和整段序列。作者合并两种数据划分并排除训练序列，联合测试集有358条序列、998个动作片段。补充B给出的训练数据说明存在数量口径差异：重叠部分有8,829条（不计左右翻转），并称约为23,384条HML序列的30.25%；两项绝对数直接相除约为37.76%。原文未解释分母或筛选差异，下文按数据集与条件类型比较，不从百分比推算确切训练条数。[补充B–C](https://coral79.github.io/uni-motion/paper/unimotion.pdf#page=12)

### 消融与关键发现

1. **先固定局部脚本，看联合标注训练的作用。** 原表1中，仅用BABEL训练的UniMotion，其片段R@3为0.636、FID为0.087；用带全局描述的交集训练后，在测试仍只给 f 的情况下，两项分别变为0.668与0.071。数据组成和可用监督一同变化，这项比较支持联合训练的价值，无法把增益完全归因于某一层网络。
2. **再固定训练模型，看测试时加入全局条件的作用。** f→f+s时，片段R@3从0.668升至0.679，片段FID从0.071降至0.066，整段FID从0.150降至0.133。这直接检验用户额外给出总体意图在本任务中的收益。
3. **序列级分数有真实取舍。** 原表2中，相同全局输入 s 下，UniMotion的FID从MDM的0.449改善到0.195，但R@1是0.375对0.376，未领先。UniMotion仅给 f 时，三档整段检索率0.344/0.508/0.587均低于MDM使用 s 的0.376/0.536/0.639。换成 f+s 后，UniMotion相对MDM才在这三档都提高。
4. **评估器会改变部分结论。** 只用BABEL训练时，在TMR++下UniMotion片段FID优于FlowMDM（0.087对0.101）；换成Guo评估器，片段FID则落后（1.206对0.885）。原表1中同样只用BABEL时，整段多样性1.374也略逊FlowMDM的1.375，两者都低于真实值1.391。
5. **理解和编辑主要是定性展示。** 图4给出MoCap与视频姿态的标签，图5–6展示联合生成，补充图10–11对照GPT-4o和MotionGPT的单例。没有报告标签逐帧分类准确率、动作边界误差或编辑保持误差。主文说同帧拼接与PCA有效，但未给逐项移除这些设计的完整数值表。[正式稿图4–6、表2](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=7)、[补充E–G](https://coral79.github.io/uni-motion/paper/unimotion.pdf#page=14)

## 亮点与洞察

- **同帧配对把监督落在了动作时间线上。** 每一帧都带有局部语义的位置；模型不必先猜某个词组对应哪一批姿态，就能学习动作与标签的联合变化。
- **用输入的信息量表达任务。** 某一路干净、另一路为噪声，就产生一个条件任务；两路皆为噪声，则联合生成。全局条件是可选的第三种信息，使同一模型能服务多种编辑流程。
- **把生成结果同时变成可编辑脚本。** 用户可以先要求完整动作，再只改一个时间段的语义。局部脚本既是从动作读取的结果，又能反向进入模型，形成闭环的创作接口。

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

1. **局部语言受标签库限制。** 连续文字特征最后要检索最近短语。库里没有的细致姿态、主体动机或罕见动作难以原样写出，逐帧匹配还可能造成抖动、边界偏移或多义标签混淆。
2. **能够输入时间表，不代表每条约束均会实现。** 共享帧位置解决表示层对应问题；在目标时间真正做对动作，还取决于生成器。现有检索/FID反映总体质量，没有验证每段动作的开始、结束和幅度都符合要求。
3. **动作改写与几何保真有不同验收标准。** 通过标签中转时，源动作的细节不全在脚本内。公开区间掩码可保留输入特征，但恢复全局关节还依赖根运动积分，编辑后应单独检查站位、朝向、足接触与过渡。
4. **数据覆盖和比较口径影响结论。** 交集减少可用样本，基线使用的训练集与可输入条件也不同。视频应用还继承外部姿态估计误差；两条定性对照不能替代多样视频或稀有动作的测试。

## 相关工作与启发

- **MDM** 用单个全局文本条件去噪动作。UniMotion沿用其连续运动扩散框架，增加一条可被条件化也可被生成的局部文字通道。[MDM项目](https://guytevet.github.io/mdm-page/)
- **STMC与FlowMDM** 均支持时段级动作条件。STMC还可按身体部位组合；本篇对比时将每个局部动作段设为全身。FlowMDM重视动作段的连续过渡；UniMotion同时把局部文字作为输出，并利用全局句子。[正式稿§2、§5.1](https://www.cvlibs.net/publications/Li2025THREEDV.pdf#page=6)
- **FrankenMotion** 后续引入全序列、动作及部位三级文字和时间标注。它将UniMotion适配到自己的数据与评估协议，可用来观察“时间段控制”进一步变成“时间段加部位控制”后需要哪些新监督。[本站FrankenMotion解读](/blog/cvpr2026-frankenmotion/)
- **启发。** 可编辑时间脚本的系统可分别评测三件事：读回的文字是否对，生成的动作是否真的按时发生，没要求改的运动是否仍保持。UniMotion给出前两者之间可双向调用的接口，第三项仍需要单独测量。
