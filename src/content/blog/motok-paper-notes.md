## 一句话总结

MoTok 把动作生成拆成两层：先用少量离散 token 规划动作，再用条件扩散把 token 还原为连续动作；同一条轨迹既参与前面的规划，也参与后面的连续动作修正，让“做什么”和“关节具体怎么走”能够一起影响最终结果。[原文 §3](https://arxiv.org/html/2603.19227v1#S3)

## 研究背景与动机

**领域现状：** 文本生成动作已经有两条成熟路线。一条直接在连续动作空间用扩散模型生成骨架序列；另一条先把动作压缩成离散 token，再由类似语言模型的生成器预测 token，最后解码回动作。离散路线把长动作变成较短的符号序列，便于使用自回归模型或掩码预测模型；MoMask、T2M-GPT 就属于这条路线。

**现有痛点：** 一段动作同时包含较粗的行为结构和很细的身体运动。例如“向前走、转身、再向前走”说明了行为顺序，却没有精确指定骨盆轨迹、脚落在哪里、手腕如何经过目标位置。普通离散 tokenizer 既要保留动作的大意，又要记录足够的连续细节，压缩太多会损失重建质量；用更多残差 token 补细节，又增加后续生成器的预测负担。另一方面，文本驱动的 token 生成器即便知道“转身”，也未必能精确满足某几帧、某几个关节的位置要求。

**核心矛盾：** 适合语义规划的紧凑离散序列，与适合精确轨迹控制的连续高分辨率动作，并不是同一种表示需求。只在 token 层加入轨迹，精度容易受量化和时间下采样影响；只在动作生成末端追轨迹，又可能让原先规划出的动作与控制目标不协调。这是论文要处理的两层矛盾：表示容量如何分工，以及控制信号在哪些层进入。

**本文目标：** 用更少的动作 token，保持有竞争力的文本生成质量，同时支持文本与关节轨迹联合控制。论文正文主要验证 text-to-motion 与 text-and-trajectory control；“支持多种条件”的框架描述，应与已经量化评测的任务范围分开理解。

**切入角度：** 作者把离散动作解码器从直接回归网络改成条件扩散模型。token 不必单独承载全部重建细节，扩散模型可以在 token 提供的条件下逐步恢复连续运动。然后，轨迹控制被分成两次接入：经过下采样的特征告诉 token 规划器“大体该怎样安排”，原精度的轨迹在连续解码时告诉模型“这些关节还差多少”。

**核心 idea：** 给两种表示安排不同职责，并让同一份控制意图贯穿两层。可以先记住一条主线：**文本与粗轨迹条件 → 离散动作规划 → 扩散重建与细轨迹修正 → 最终连续动作**。这是对架构的直观解释，不意味着每个 token 都对应一个可读动作词，也不意味着语义与运动学信息在数学上已经完全解耦。[原文 §1、§3.1–3.3](https://arxiv.org/html/2603.19227v1#S3)

## 方法详解

### 整体框架

完整系统有两个需要分清的部分：第一部分学习 MoTok tokenizer，把真实动作压缩成离散码，再通过扩散解码学会还原；第二部分学习条件 token 生成器，使它能从文本和可选轨迹预测这些离散码。生成新动作时不需要先提供一段真实动作，真实动作编码分支主要用于学习表征、提供 token 监督及重建。

图按“上方学习表示、下方生成动作”阅读。上方的卷积解码器输出的是**逐帧扩散条件**，最终动作由后面的扩散模型生成；下方的轨迹有两条去向，一条进入 token 规划器，一条进入连续动作的控制损失。DDM 和 AR 是两种可替换的规划器，并不串联。架构依据[原文图2与 §3](https://arxiv.org/html/2603.19227v1#S2.F2)整理。

### 关键设计

1. **重新分配 tokenizer 的工作：离散码给出条件，扩散模型负责重建动作。**

   输入动作有 T 帧，时序卷积编码器先把它下采样为 N 个连续向量；压缩比为 ρ = T/N。每个向量再寻找码本中最近的条目，得到一个离散索引。MoTok 使用单层量化、1024 个码本条目，而不是逐层增加残差码来承载细节。

   <div class="equation">z<sub>n</sub> = arg min<sub>k</sub> ‖h<sub>n</sub> − c<sub>k</sub>‖²；q<sub>n</sub> = c<sub>z<sub>n</sub></sub></div>

   h 是编码器输出，c 是码本里的向量，z 是生成器将来需要预测的整数编号，q 是按编号取出的向量。这里的 token 是学出来的运动表示，并没有被人为标注成“走路”“抬手”等动作单词。

   关键变化发生在解码端。卷积解码器 D 把量化向量 q 上采样为 T 帧条件 s；随后，条件扩散模型根据带噪动作 x<sub>t</sub>、扩散步 t 和 s，预测干净动作 x̂<sub>0</sub>。换句话说，D 的结果只是“怎样重建”的条件，不能直接当作可播放的骨架动作。

   <div class="equation">s<sub>1:T</sub> = D(q<sub>1:N</sub>)；x̂<sub>0</sub> = f<sub>φ</sub>(x<sub>t</sub>, t, s<sub>1:T</sub>)</div>

   其中 t 是扩散过程的步数，与动作序列的第几帧不同。推理时从高斯噪声开始，多次反向扩散后得到动作。去噪器含残差一维时序卷积，以及用类似 AdaIN 的变换注入条件的 MLP，因此它能利用时间上下文恢复动作变化，不是每一帧各自独立生成。

   MoTok 本身端到端学习，目标是扩散重建的 Smooth-L1 损失加上权重为 0.02 的量化 commitment loss。作者认为，把细节恢复交给扩散模型，可以让紧凑 token 更适于承载语义结构；后面的重建、生成与 captioning 实验提供了支持，但不能据此把 token 解释成完全独立于姿态细节的纯语义符号。[原文 §3.2，式1–6](https://arxiv.org/html/2603.19227v1#S3.SS2)

2. **在离散规划阶段同时输入文本和对齐后的轨迹，让动作结构先适应控制目标。**

   文本属于全局条件：一句“向前走、转身、再向前走”约束整段动作，不需要天然对齐到每一帧。论文使用预训练 CLIP ViT-B/32 得到 512 维文本特征，把它放在规划器序列的第一个位置，作为全局条件 token。

   轨迹属于局部条件：它指定某个时刻、某个关节的目标位置。轨迹编码器使用与 MoTok 动作编码器相同类型的卷积结构，把按帧给出的轨迹压缩成长度 N 的特征序列，再加到对应的动作 token 位置上。这样，规划器不只知道“要转身”，也能提前感知哪些时间段需要沿指定路线移动。论文没有明确说轨迹编码器与动作编码器共享同一份权重，图中也不应自动把它标成预训练或冻结模块。

   这一套条件接口接到两类生成器上。**MoTok-DDM** 采用 MoMask 式的掩码 token 预测：从被遮住的位置出发，迭代预测动作码；**MoTok-AR** 采用 T2M-GPT 式的自回归预测：根据已有前缀逐个生成动作码。AR 每次预测下一个 token，所以局部条件的输入位置也要向前错开一位：第一个动作 token 的轨迹条件加在全局条件位置，后续条件加在前一个动作 token 的输入位置。这样才能让条件与正在预测的时刻对齐。

   多条件 CFG 也发生在规划阶段。作者交替使用两种比较：保留轨迹、比较有无文本；保留文本、比较有无轨迹。两种方式等概率交替，用来避免引导过度偏向某一种条件。它没有额外引入一套控制网络或新的训练目标。

   需要分清这里的两个“扩散”：DDM 在**离散 token**中做掩码恢复，MoTok 解码器在**连续动作**中做高斯去噪。AR 版本替换的是前一个规划器，后面的连续扩散解码仍然保留。[原文 §3.3–3.4、§4.1](https://arxiv.org/html/2603.19227v1#S3.SS3)

3. **保留原精度轨迹，在连续解码过程中进一步修正关节位置。**

   经过量化与时间下采样后，token 层的轨迹条件适合影响动作的大体结构，却不适合独自保证逐帧位置精度。因此，MoTok 不会在编码完轨迹后就丢掉原始目标：同一份轨迹还进入扩散解码阶段的控制损失。

   每一步去噪得到当前完整动作估计后，计算它与局部条件的偏差，再沿减小偏差的梯度方向调整连续动作估计，随后继续扩散解码。原文式12给出如下形式：

   <div class="equation">x̂<sub>k</sub> ← x̂<sub>k</sub> − η ∇<sub>x̂<sub>k</sub></sub> L<sub>ctrl</sub>(x̂<sub>k</sub>, c<sup>s</sup>)</div>

   x̂<sub>k</sub> 表示当前整段动作的估计，c<sup>s</sup> 是局部控制条件，η 决定修正强度。图2将控制梯度画在预测的干净动作 x̂<sub>0</sub> 上。这里修改的是推理中的连续动作估计，不是重新训练网络，也不是把离散 token 改成某个硬编码动作指令。

   这两次接入的作用不同：前一次让规划出来的动作更适合给定路线，后一次降低连续关节位置误差。消融表明，仅在解码时追轨迹可以把误差压低，却明显损害 FID；仅在规划时输入轨迹可以得到较好的 FID，却留下很大的位置误差。两者配合才得到较好的折中。

   这种梯度引导仍是优化过程。它不等价于把受控关节在每一步严格投影到目标位置，也不承诺未指定的关节、帧、接触或动力学约束自动成立。[原文 §3.3，式12；表4](https://arxiv.org/html/2603.19227v1#S3.SS3)

### 一个完整例子

用论文图3最下方的真实案例来理解：文本要求“向前走、转身、再向前走”，同时给出**骨盆、左脚和左手腕在 25% 帧上的目标位置**。下面是依据方法整理的流程说明，不是本次实际运行得到的输出。

1. **准备两种条件。** 文本说明整段动作的顺序；关节轨迹与帧掩码说明哪些位置需要满足目标。25% 是被控制的帧比例，不能理解成每一帧都已给出完整动作。
2. **把条件送入规划器。** CLIP 将整句文本编码为全局特征；卷积轨迹编码器将稀疏时间控制转换成与 token 对齐的局部特征。假设为了说明长度关系，一段动作有 120 帧，选压缩比 4，则规划器需要生成 30 个动作 token。这个帧数仅是算例，论文图3没有给出该案例的 120 帧设定。
3. **生成离散动作计划。** DDM 迭代填充这 30 个位置，或 AR 按顺序预测。结果是码本编号，不是可读的“走路—转身—走路”三个标签；文本与轨迹共同影响整段编号序列。
4. **在连续空间恢复并控制。** token 经查表和卷积上采样形成每帧条件，扩散模型从噪声逐步生成动作。在每次连续动作估计中，再检查已指定帧上的骨盆、左脚、左手腕是否偏离目标，用控制损失修正。
5. **检查最终动作。** 最终输出覆盖全部帧、全部身体关节。需要同时观察语义顺序、目标关节误差、脚滑与整体自然度；未指定的 75% 帧仍由模型补全，不能因关键点接近目标就推断整段轨迹被严格锁定。

作者图3用红色标出目标轨迹、蓝色标出生成轨迹，用于展示联合控制的定性效果。它与表1的总体统计承担不同的证据作用，不能只凭一张可视化推断所有样本都能稳定满足控制。[原文图3](https://arxiv.org/html/2603.19227v1#S4.F3)

### 训练 / 推理

**学习 tokenizer。** 真实动作经过卷积编码、单层量化与条件扩散重建；编码器、码本及解码侧共同适应重建任务。训练时使用 1000 个扩散时间步。需要留意：附录A.1另有“先训练 tokenizer，再固定编码器与码本、只训练解码器”的受控消融，它不能当成默认 MoTok 主训练流程。

**学习条件生成器。** 用离散动作表示作为预测目标，分别学习 DDM 或 AR 规划器。DDM 主干为 6 层、隐藏维度 384；AR 为 9 层、隐藏维度 768。条件 dropout 为 0.1，随机 token 替换概率分别为 DDM 的 0.1、AR 的 0.2。正文未明确完整 tokenizer 在这一步的冻结范围，因此这里不补写“全部冻结”的实现结论。

**生成新动作。** 输入文本、动作长度及可选的局部轨迹条件，先完成 token 规划，再把 token 送入连续扩散解码器。附录报告 DDM 使用 10 次 token 去噪迭代；AR 逐个生成 token。连续解码使用 GLIDE 的 Fast27 间隔采样，控制任务在解码过程中叠加前述梯度修正。这里的 10 次离散规划与 27 步连续解码是两个阶段，不能合并理解为同一模型的总采样步数。

**公开的训练规模。** 附录称 tokenizer、DDM 和 AR 均训练 24 个 epoch，每个 epoch 约 2000 次迭代，均使用 8 张 GPU；MoTok 每卡 batch size 为 512，DDM/AR 为 64。优化器是 AdamW，初始学习率 2×10⁻⁴，第 20 个 epoch 降到 2×10⁻⁵。训练 GPU 型号和总训练时长未明确给出，不能据此换算确定的训练费用。附录另外报告了 H100 上的推理耗时，见下方效率比较；推理硬件不能自动当作训练硬件。[原文 §4.1](https://arxiv.org/html/2603.19227v1#S4.SS1)、[附录D.2](https://arxiv.org/html/2603.19227v1#Pt0.A4.SS2)

这里能看到论文最鲜明的结果：与 MaskControl 相比，MoTok-DDM-4 的 FID 从 0.083 降到 0.029，平均位置误差从 0.0072 m 降到 0.0008 m，也就是摘要中的 **0.72 cm → 0.08 cm**。但文本匹配 Top-3 从 0.805 降到 0.777，因此不能说它在所有维度都胜出。MoTok-DDM-2 的 FID 更低，为 0.025，不过它使用的是 MaskControl token 预算的 **1/3**；**1/6** 预算对应 MoTok-DDM-4，不能把两者最好的数字拼成一个配置。[原文表1](https://arxiv.org/html/2603.19227v1#S4.T1)

还要区分表1的三种轨迹指标：Avg. Err. 是受控位置的平均欧氏距离；Loc. Err. (50 cm) 是误差超过 50 cm 的受控位置比例；Traj. Err. (50 cm) 是至少出现一次这种超限的序列比例。后两项为 0，只说明没有超过这个阈值，不能当成位置误差严格为零。正文 §4.2 的 Pelvis 段存在与表1不一致的 FID 和小数位，本篇以表格为准：MoTok-DDM-4 的 Pelvis FID 为 0.029，MaskControl / MoTok-DDM-4 的平均误差为 0.0098 / 0.0049 m。

**纯文本生成：HumanML3D 与 KIT-ML，原文表2。** 数值为 20 次评测的均值 ± 95% 置信区间。这里同时列 FID 与文本匹配，避免只看分布质量忽略语义一致性。

| 方法 | HumanML3D FID ↓ | HumanML3D Top-3 ↑ | KIT-ML FID ↓ | KIT-ML Top-3 ↑ |
| --- | ---: | ---: | ---: | ---: |
| T2M-GPT | 0.141 ± 0.005 | 0.775 ± 0.002 | 0.514 ± 0.029 | 0.745 ± 0.006 |
| ReMoDiffuse | 0.103 ± 0.004 | 0.795 ± 0.004 | 0.155 ± 0.006 | 0.765 ± 0.055 |
| MoMask | 0.045 ± 0.002 | 0.807 ± 0.002 | 0.204 ± 0.011 | 0.781 ± 0.005 |
| MoTok-AR-2 | 0.061 ± 0.005 | 0.770 ± 0.002 | 0.211 ± 0.003 | 0.750 ± 0.006 |
| MoTok-DDM-2 | 0.033 ± 0.002 | 0.799 ± 0.002 | 0.144 ± 0.005 | 0.762 ± 0.006 |
| MoTok-AR-4 | 0.053 ± 0.004 | 0.773 ± 0.003 | 0.297 ± 0.002 | 0.734 ± 0.005 |
| MoTok-DDM-4 | 0.039 ± 0.002 | 0.793 ± 0.002 | 0.192 ± 0.016 | 0.760 ± 0.006 |

MoTok-DDM-2 在这两套数据上的 FID 都优于表中的 MoMask，同时没有在 Top-3 上超过它。压缩比 4 的版本仍有很强的 HumanML3D FID，但在 KIT-ML 上的 0.192 高于 ReMoDiffuse 的 0.155。论文支持的是紧凑 token 与扩散解码的竞争力，以及可见的质量—压缩权衡，不是每个设置都全面最好。[原文表2](https://arxiv.org/html/2603.19227v1#S4.T2)

**生成耗时：附录C的效率比较。** 作者报告在同一 H100 环境下，以文本和轨迹作为条件生成单条动作序列的耗时：

| 方法 | 单序列生成耗时 ↓ |
| --- | ---: |
| MaskControl（full version） | 32.79 s |
| MoTok | 2.63 s |

这提供了作者测量的效率证据；但该段没有进一步注明序列长度、MoTok 的具体规划器/压缩比配置或完整计时细节。它可用于说明报告环境中的速度差异，不能直接当作所有长度、硬件和交互场景的延迟承诺。[原文附录C：Efficiency Comparison](https://arxiv.org/html/2603.19227v1#Pt0.A3.SS0.SSS0.Px1)

### 消融实验

**扩散解码有效，但还需要时间建模。** [表3](https://arxiv.org/html/2603.19227v1#S4.T3)中，普通卷积解码器的重建 FID 为 0.0704；逐帧扩散头降到 0.0396，却没有同步改善 DDM 的文本生成 FID（0.0640 → 0.0678）。加入时序卷积的扩散解码器、使用核宽 5 后，重建 FID 为 0.0244，生成 FID 为 0.0394。这说明更强的逐帧重建能力，还需要与时间结构建模结合。

**轨迹要在两层进入，各自解决不同问题。** [表4](https://arxiv.org/html/2603.19227v1#S4.T4)的 DDM 结果最直接：只有规划器接入轨迹时，FID 为 0.028，但控制误差仍为 0.2170 m；只有扩散解码接入轨迹时，误差降到 0.0056 m，FID 却升到 0.365；两处都接入时，FID 为 0.029、误差为 0.0049 m。联合方法并非单看 FID 最低，而是在动作分布质量与位置精度之间达到更好的平衡。

**重建指标不能替代下游生成指标。** 表3中，码本向量维度 512 的重建 FID 为 0.0177，优于 768 维的 0.0244；但对应 DDM 生成 FID 是 0.0505，差于 768 维的 0.0394。更紧的重建，不一定意味着生成器更容易预测这些 token。这里的 512/768 是向量维度，不能与 1024 个码本条目混淆。

**减少 token 有最佳范围。** 表3里，DDM 在下采样倍率 2、核宽 7 时的生成 FID 为 0.0332；倍率 1、核宽 7 为 0.1551；倍率 8、核宽 5 为 0.0707。作者在多个倍率与核宽组合上做了实验，结果支持适度压缩有利，不能推广成 token 越少越好。

**固定 token 后，更换解码器仍有收益。** [附录表5](https://arxiv.org/html/2603.19227v1#Pt0.A1.T5)专门做了受控实验：先用卷积 tokenizer 学到一套表示，再固定其编码器与码本，将第二阶段解码器从卷积换成扩散，重建 FID 从 0.0954 降到 0.0544，文本生成 FID 从 0.1271 降到 0.1098。这是“相同 token 信息下扩散解码更强”的直接证据；表中不同第一阶段训练出来的表示彼此不同，不能说整个 2×2 表共享同一套 token。

### 关键发现

1. **紧凑表示与高质量解码可以一起设计。** 单层离散码没有阻止模型取得有竞争力的 FID；核心在于连续解码器也承担恢复细节的工作，而不是把全部细节都要求为离散码。
2. **控制条件不仅能限制输出，也能帮助选择合适的动作。** MoTok-DDM-2 的纯文本 FID 为 0.033，加入随机一个、两个、三个关节控制后，表1对应 FID 为 0.025、0.016、0.014。这个趋势出现在该组设置中，不能据此保证任意新增约束都会改善结果。
3. **“token 少”与“运行快”需要分别给出证据。** 论文既报告了更小的离散预测预算，也报告了 H100 上 2.63 s 对 32.79 s 的单序列生成耗时。两者是不同测量：实际运行还包括连续扩散与控制修正，因此不能直接把 1/6 token 换算成六倍加速。

## 亮点与洞察

- **把表示学习与控制接口放在一起设计。** MoTok 的 tokenizer 改动不只提高重建质量，还提供了连续解码中的控制入口。轨迹控制并非在模型输出后另加一个完全独立的后处理器，而是进入生成过程。
- **同一条件可以按不同精度服务不同模块。** 轨迹先被压缩为适合规划的特征，再以原精度约束连续动作。这种分工值得迁移到“语义意图 + 具体目标点”的系统中：上层提前感知目标，下层再检查几何偏差。
- **tokenizer 的好坏，要看它供谁使用。** 重建 FID 更好却不一定带来更好的生成 FID，是这篇很有价值的提醒。面向生成器的离散表示，既要保留信息，也要让后续模型容易组织和预测。
- **有意识地保留两类生成器。** DDM 与 AR 共享条件接口，让论文的主张不局限于某一种规划顺序。表格同时也显示 DDM 与 AR 结果不同，不能因为接口统一就假设两种主干性能等价。

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

**控制仍是数值优化，不能替代最终验证。** 表1的低位置误差很有吸引力，但脚滑率并非零；论文没有证明严格的接触、碰撞、动力学或全关节约束。若用于角色与场景交互，仍需要在解码后检查实际关节轨迹、接触和场景关系。这是面向应用的推论，不是论文已经完成的系统。

**“语义—运动学分工”有实验支持，尚不是严格可解释表示。** 作者展示了压缩、生成、控制等收益，也在附录讨论 motion-to-text；但没有逐一给出码本条目的语义定义。不能直接将这些 token 当作可编辑的动作语法，更不能把它们等同于 MotionMERGE 或 LaMoGen 中的文本化推理步骤。

**量化验证覆盖的条件类型有限。** 正文主要是文本和关节轨迹。框架中列举的风格、接触提示、节奏等局部或全局条件，不代表这些条件已经全部完成独立实证。附录还有 MotionFix 上的动作编辑示例，但不应据此宣称已经验证任意源动作的局部严格保留。

**推理成本与实际复现仍有空白。** Fast27 减少了采样步数，附录也报告了 H100 上单序列 2.63 s 的结果，但连续扩散和每步控制修正仍有开销，且尚缺不同序列长度、硬件和控制密度下的延迟曲线。当前仓库也尚未提供实现或权重，本次能确认的是作者报告的实验和架构，不能确认本机可复现、可部署或可实时运行。

## 相关工作与启发

- **[MoMask](https://arxiv.org/abs/2312.00063)：用多层离散码保存动作细节。** MoMask 通过残差量化形成多层 token，并结合掩码预测与残差预测生成动作。MoTok 延续掩码式规划的优点，但把细节恢复更多交给扩散解码器。阅读时可重点比较：细节究竟存入更多离散码，还是交由连续生成器恢复。
- **[T2M-GPT](https://arxiv.org/abs/2301.06052)：离散动作序列的自回归生成。** 它为“动作 tokenizer + GPT 式预测”提供了直接基础。MoTok-AR 在这一接口上增加对齐的局部条件，并改用连续扩散解码；AR 版本也说明本文的核心不只是某一种掩码策略。
- **[InterControl](https://arxiv.org/abs/2311.15864)：在连续动作中施加关节控制。** 它通过关节控制与逆运动学引导处理动作交互，MoTok 的 §4.1 引用其控制策略。MoTok 的进一步设计是先把局部条件也送入离散规划，使连续控制不必完全从一个未考虑轨迹的动作计划出发。
- **[DisCoRD](https://openaccess.thecvf.com/content/ICCV2025/html/Cho_DisCoRD_Discrete_Tokens_to_Continuous_Motion_via_Rectified_Flow_Decoding_ICCV_2025_paper.html)：同样增强连续解码，但训练目标不同。** DisCoRD 复用并固定已有 tokenizer 的编码器与码本，复用原 token 生成器，训练条件投影与 rectified-flow 解码器；MoTok 则端到端学习带扩散重建的 tokenizer，并专门设计轨迹在规划和解码中的双重接入。前者更直接回答“已有 token 如何解码得更好”，后者同时追问“表征怎样学习，以及条件怎样贯穿生成”。两篇结果来自各自设置，不能仅凭相近 FID 直接排出通用优劣。
- **对可控角色系统的启发。** 如果上层系统给出一句动作意图和少量关节目标点，可以借鉴这种分工：让规划器提前接收目标，再在连续动作层验证和修正。但是否能在具体角色骨架、坐标系与场景里完成目标，还需额外适配和实测。论文当前的 benchmark 结果不能自动覆盖引擎中的角色交互。
