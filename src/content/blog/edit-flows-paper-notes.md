## 一句话总结

Edit Flows 把生成状态从“固定长度的一排 token”改为**可以增删的完整序列**，学习在当前位置附近插入、删除或替换 token 的速率；训练时借助带空白位的辅助对齐过程提供监督，推理时模型只看真实序列。它改善了 Mask DFM 的图像描述、文本和代码结果，但默认主实验以**空序列前向插入**为主，采样仍需大量迭代，不能直接理解为三种编辑同时启用的一步快速模型。[§3、§5、表5][paper]

## 研究背景与动机

**领域现状：** 自回归语言模型从左向右追加 token，自然支持不同输出长度；离散扩散与流模型可以利用双向上下文、并行修改多个位置，但常先准备固定数量的 mask，再逐步填入内容。两类方法各自保留了不同的生成自由度。[§1–2][paper]

**现有痛点：** 假设已经生成 “A sentence through revision”，接下来真正需要的是在 “sentence” 后面加上 “evolves”。固定槽位模型必须预先留出正确空位，或者调整已有位置上的内容；一开始预测错长度，会影响后续整句组织。代码还常需要在已经形成的结构内部补充条件、变量或语句。[图1–2、§2.2][paper]

**核心矛盾：** 序列语义更依赖“谁在谁旁边”，固定槽位却要求模型同时猜“最终第几个位置应该是什么”。而直接改成整条序列的随机编辑，又会遇到大量可能的编辑路径和对齐关系，导致训练目标难以计算。[§3.2][paper]

**本文目标：** 在统一的概率生成框架中原生支持长度变化，并允许在序列不同位置形成、补充和纠正内容，而不依赖额外长度预测器或只向右续写的生成顺序。[§3.1][paper]

**切入角度：** 用连续时间马尔可夫链描述序列之间的编辑跳转；把复杂的序列级路径暂时提升到容易构造的“带辅助对齐的空间”，在那里采样训练状态，再把空白位去掉交给网络。[§3.1–3.2][paper]

**核心 idea：** 训练时知道一对源序列与目标序列如何对齐，因而知道还有哪些插入、删除和替换没有完成；模型只看到当前真实序列与生成时间，学习这些编辑的发生速率。推理时不断预测、采样并执行编辑，让句子在内容和长度上一起演化。[图3、式23][paper]

## 方法详解

### 整体框架

这里的“流”是**离散状态之间的概率流**：状态是一条 token 序列，事件是编辑操作，连续的是生成时间，并不是把 token ID 当连续坐标做普通 ODE。完整系统包含训练用辅助状态、可训练速率网络和推理编辑采样器；图像条件另外经过冻结的 CLIP 与可训练投影层。[§2–3、附录E][paper]

### 关键设计

1. **序列级状态空间：把“增加一个位置”纳入生成模型本身。**

   状态空间包含从空序列到最大长度上限内的所有序列。一次局部编辑可以在位置 `i` 右侧插入 token `a`，删除当前位置，或将当前位置换成 `a`；插入后，后续位置会自然向右移动。论文示意使用保留的 `BOS` 起始标记，便于从语义上的空序列开始插入。[式10–12、图1、图13][paper]

   CTMC 速率 `uₜ(y|x)` 表示从当前序列 `x` 跳到 `y` 的瞬时倾向。短时间 `h` 内，单个编辑发生的概率近似为其速率乘以 `h`，并不是直接把速率当概率。网络输出按操作分开：

   <div class="equation">插入：uₜ(ins(x,i,a)|x) = λᵢⁱⁿˢ(x,t) Qᵢⁱⁿˢ(a|x,t)<br />删除：uₜ(del(x,i)|x) = λᵢᵈᵉˡ(x,t)<br />替换：uₜ(sub(x,i,a)|x) = λᵢˢᵘᵇ(x,t) Qᵢˢᵘᵇ(a|x,t)</div>

   这是原式13–15的记号整理。非负 `λ` 决定“在这里做这类编辑有多快”，归一化分布 `Q` 决定“插入或替换成哪个 token”。两者分开后，模型不必一次枚举所有可能的完整句子。

2. **辅助对齐过程：训练时知道缺什么，模型输入里却不泄露空位答案。**

   直接计算两个不同长度序列之间所有编辑路径很困难。作者先构造等长辅助序列 `z₀、z₁`，允许其中出现 `ε`：`ε→a` 对应插入，`a→ε` 对应删除，`a→b` 对应替换。对齐不必总是最小编辑距离，也可以随机构造。[§3.2、图3][paper]

   例如，字符序列 `KITTEN→SMITTEN` 可以对齐为 `K ε I T T E N → S M I T T E N`，只剩一次替换和一次插入。训练随机采样时间，再按调度器决定每个位置暂时保留源值还是换成目标值，形成 `zₜ`；**去掉其中所有 `ε` 后才得到真正送进网络的 `xₜ`**。因此这不是在输入里藏着一排 mask 的变体：模型不知道最终长度，也不知道当前两个 token 之间到底还缺几个 token。

   定理3.1证明，在满足其率与概率路径条件时，可以对辅助过程进行边缘化，得到原序列空间的 CTMC；用辅助状态训练 Bregman 散度目标，与对边缘速率训练有相同的参数梯度。它解决的是“如何获得可计算的监督”，并不意味着一个有限容量、有限步采样的模型必然生成完美结果。[定理3.1、附录B][paper]

3. **编辑速率损失：既奖励正确编辑，也限制无意义地反复修改。**

   训练信号不仅是“正确 token 的交叉熵”。式23还有一个所有输出编辑速率之和：

   <div class="equation">L = E［所有候选编辑的预测速率之和<br />− Σᵢ 1［zₜⁱ ≠ z₁ⁱ］ · κ′(t)/(1−κ(t)) · log uθₜ(完成第 i 个目标编辑 | xₜ)］</div>

   第一项抑制无差别地提高所有速率，第二项提高尚未完成的目标编辑的速率。两项共同学习“改哪里、改成什么、何时应该改”。基础路径在辅助坐标上独立采样，但网络仍以整条当前序列作为上下文；“独立路径”不等于网络各位置互不交流。[式23、附录B.1][paper]

   论文主要实验使用 `κ(t)=t³`。它控制训练中不同破坏程度的出现方式，与真实语言的时间顺序无关。图13的简化代码为了讲解使用线性调度，不能直接当成主实验配置。

4. **全双向速率网络：复用语言模型架构，改变输出头和生成规则。**

   作者采用 Llama 系列架构的 280M 和 1.3B 配置**从头训练**；Edit Flow 与 Mask DFM 使用完整自注意力，并加入编码 `t` 的 token，自回归对照使用因果注意力。网络为每个当前位置预测各编辑的速率和 token 分布。这里的 “Llama3” 指架构配置，不是下载现成 Llama3 权重再微调。[§5、表4][paper]

   文本与代码条件来自训练序列的一段前缀，并用二值条件标记区分已给定部分；图像描述任务则把冻结 CLIP 的图像嵌入，经一层可训练 MLP 投影后放入序列作条件。任务验证了文字续写/代码补全与图像条件生成，**没有语音、音乐或人体动作编码器**。[附录E][paper]

5. **默认空序列与随机初态：框架能力和实际主模型要分开看。**

   默认模型取 `X₀=∅`，辅助源序列都是空白，前向从“没有内容”到目标只需插入；若结合反向速率纠正，才会出现删除。`Uniform X₀ + Edit Flow` 则从100个随机 token 出发，正文将其分布定义为训练集的经验 token 分布；构造对齐时，50个初始 token 用于删除，另外50个用于替换，其余目标 token 通过插入补齐。[§5][paper]

   因此“能插删改”是框架的一般能力，不能直接推断表中默认模型在每一步都同时训练和启用了三类前向操作；也不能因为加入了替换，就假定效果一定更好。表3中随机初态变体的多项结果反而低于默认空序列模型。

6. **局部传播路径：让长序列中的已出现内容更像相邻片段。**

   如果长代码的目标 token 独立出现，早期可能只剩下彼此距离很远的词，缺少可用的局部上下文。Localized Edit Flow 改变训练路径：一个位置被激活后，会提高邻居被激活的机会，同时保留少量独立起始机会，所以多个区域仍可同时生长。[图8、附录C.1][paper]

   作者用辅助布尔状态 `m` 表示某位置是否已换成目标值，再增加矩阵状态 `M` 记录多个独立起点向左右传播的过程。各起点沿邻居传播的速率为 `λprop`，列方向取逻辑“或”得到当前激活状态；借助同一辅助过程定理，模型仍只接收去掉空白的真实序列。这里改变的是**生成路径和监督分布**，不是在 Transformer 上加一个名为“局部编辑”的普通注意力层。

   该机制对较长的 MBPP 代码生成帮助明显，却没有在所有图像描述指标或所有 Pass@10 指标上获胜。局部连续性是一种偏好，不是代码语法或执行正确性的硬约束。

7. **反向纠正与采样：可以回头修改，但仍是有代价的随机迭代。**

   推理每一步读取当前序列，按速率抽样是否编辑，再从 `Q` 抽样新 token，执行后重新计算上下文。同一位置的删除与替换互斥；多个位置的编辑可在一步里并行执行。附录C的采样文字中有一处把删除/替换联合概率写成含插入率的组合，与同段后续比例及式13–15不一致；这里按操作定义解释，避免照抄疑似符号笔误。

   反向速率学习从数据分布回到源分布的过程。作者把一次更长的前向推进与一次反向退回组合，净生成时间仍向前；在理想速率下，这种额外成分可以保持对应的概率边缘分布，同时提供修改机会。[§3.3、附录C][paper]

   CFG 分别作用于操作速率 `λ` 与内容分布 `Q`，温度、top-p/top-k 用于调整 token 选择。它们影响生成偏好，不能被当成用户约束求解器。尤其**非自回归不等于一步完成或已经更快**：表5的默认代码模型使用5000或10000个采样步，还可能进行正反向和条件/无条件网络计算。

### 一个完整例子

沿用作者图1–3的句子，以词级显示方便阅读；实际模型使用 tokenizer，因此词与 token 不一定一一对应。以下具体生成时刻与主线来自作者示意，属于机制演示，不是我们运行的输出。

1. **准备训练对齐。** 源序列为 `sentence avocado the`，目标为 `A sentence evolves through revision`。一种对齐是：`ε sentence ε avocado the ε → A sentence evolves through ε revision`。它定义三次插入、一次替换、一次删除。
2. **抽到一个训练中间状态。** 假设 `A、through、revision` 已到位，而 `evolves` 尚未插入、`the` 尚未删除，则辅助状态去空白后是 `A sentence through the revision`。模型只收到这句话、生成时间和可用条件；监督过程知道还要插入 `evolves` 并删除 `the`，于是用式23训练对应速率。
3. **开始实际采样。** 图1从 `sentence avocado the` 开始，先将 `avocado` 换为 `through`，再在句首插入 `A`，删除 `the`，在句尾插入 `revision`，最后在 `sentence` 后插入 `evolves`。产生顺序可以和最终阅读顺序不同。
4. **读取速率。** 在图2的 `A sentence through revision` 状态，作者示意给出了候选 `evolves` 的插入速率15.7、`adapts` 的插入速率5.6等。15.7不是概率；仅作局部一阶直觉，若步长为0.01且保持该速率，对应编辑概率近似0.157。实际选择还需要处理其他候选与事件采样。
5. **得到完整序列。** 最终读取 `A sentence evolves through revision`，长度和内容一起形成，不需要在初始状态给每个目标词预留槽位。该例展示全操作框架；默认空序列版本则从 `BOS` 后逐步插入内容，不能把这个例子误作默认模型的精确配置。

附录图7还展示了对错误 `is_prime` 实现的修改：作者报告经过 **300步、117次编辑**得到正确的最终代码。这个单例说明可以从已有内容开始纠正，不等于模型保证最小修改量，也不等于任意代码都能修好。[图7][paper]

### 训练/推理

**训练链：** 选目标文本/代码及前缀条件，或图像—描述对 → 采样源序列和对齐 → 采样生成时间与辅助状态 → 去空白得到网络输入 → 预测编辑率及 token 分布 → 使用式23或局部传播目标训练。生成骨干、输出头及图像投影可训练，CLIP 冻结；辅助对齐由训练程序构造，不需要额外训练一个对齐预测器。[§3、附录E][paper]

**数据与条件：** 图像描述使用 MS COCO 和 Image Captioning 3M；语言使用 DCLM-baseline 1.0；代码使用 CodeLlama datamix。文本/代码训练前缀占比取随机变量 `c³`，其中 `c` 在0到1间均匀采样；10%的样本丢弃条件，用于无条件预测和 CFG。最大训练长度1024、词表32k。[附录D–E][paper]

**规模与成本：** 280M配置为12层、隐藏维1024、16个注意力头；1.3B为16层、隐藏维2048、32个头。附录E报告500k步、全局批4096、16×8张 H100，AdamW 学习率3×10⁻⁴、2000步预热和余弦调度。相同训练计算预算下，AR/Mask DFM约读入2T token，Edit Flows借助变长打包约读入6T token。这个结果说明训练 token 利用率提高，**比较并非相同有效数据暴露量**；论文未给出可直接换算的总 GPU 小时或账单。

**推理链：** 给定前缀/图像等条件 → 初始化空序列或指定初态 → 迭代速率预测、可选CFG及反向纠正、抽样编辑 → 到终点输出 token 序列并用普通 tokenizer 解码。没有动作解码器、物理控制器或执行反馈回路。上下文是双向的当前完整序列，也没有证明可以像流式语音系统那样只利用过去信息低延迟输出。

### 消融实验

**初始序列：** 将默认空序列改为100个随机 token 的 `Uniform X₀`，HumanEval Pass@1从12.8降到9.7，MBPP Pass@1从10.0降到9.4；HumanEval Pass@10同为24.3。引入更复杂的初始编辑任务没有在该设置下带来统一收益。[表3][paper]

**局部传播：** 默认 Edit Flow 换成 Localized 版本，MBPP Pass@1从10.0升到14.8，相对提升48%；对本文 Mask DFM 的6.2则相对提升约138.7%。同时 MBPP Pass@10从36.4降到34.0，HumanEval+ Pass@10从20.7降到18.9；改进集中在部分指标，不能概括为全线提升。[表3][paper]

**短序列是否需要局部性：** COCO SPICE从21.1升到22.1，但CIDEr从108.1降到105.1；3M的三个指标都低于默认 Edit Flow。作者据此认为短描述上的额外局部传播优势有限。[表1、§5][paper]

### 关键发现

1. **改善固定槽位生成是最稳定的结果。** 在本文重训的 Mask DFM 对照上，Edit Flow 的图像描述、文本基准与代码指标普遍更好，支持可变长度、相对位置编辑值得研究。
2. **并未全面超过自回归。** 同预算重训AR在文本六项指标全部更高，代码六项也全部更高；图像描述是Edit Flow相对优势更明确的任务。外部VLP、ClipCap不能用于同预算胜负判断。
3. **局部性带来取舍。** 长代码中的局部上下文有价值，但对短描述和部分多次采样成功率会下降。48%提升对应MBPP Pass@1这一具体对照。
4. **训练利用率与推理效率是不同证据。** 变长打包减少空位计算、提高训练数据吞吐，不能替代端到端采样速度测试；当前表5反而提醒我们要认真核算数千步生成的成本。

## 亮点与洞察

- **把长度当成生成状态的一部分：** 不必先决定一个固定输出槽位数；插入位置依附当前已有内容，适合研究中途增补结构的生成任务。
- **复杂监督可以存在于训练辅助空间：** 对齐与传播状态帮助构造可训练目标，实际模型却不需要显式预测这些辅助变量。这比把所有中间结构都塞进推理输入更清楚地区分了监督工具与部署接口。
- **统一看待多种序列生成方式：** 禁止插删得到固定长度替换过程，只允许最右侧插入可恢复自回归式生成。差别落在允许哪些编辑和如何定义路径，而不只是更换一个网络名字。[§3.1][paper]
- **局部传播是路径设计：** 可以在不强制固定全局生成顺序的前提下，让多个局部片段分别长出来，为长结构的逐步形成提供了另一种归纳偏置。

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

1. **尚未建立高效少步推理结论。** 论文展示的是生成质量与机制，代码任务用了5000–10000步以及复杂采样设置；缺少与AR同硬件、同质量、同长度的完整延迟对照。减少步数、缓存与高效采样仍需单独研究。
2. **评测受训练上下文与打分方式影响。** 作者指出AR训练天然见到不同前缀，而本文非AR随机抽取条件前缀；文本选择题又用ELBO估计而非精确似然。两者会影响比较，不能把基准差距完全归因于表示形式。[§6][paper]
3. **统计与调参边界有限。** 原表没有系统误差条，检查清单第7项也承认这一点；HumanEval和文本各benchmark本身参与了参数选择。已有数据足以观察趋势，还不足以把小差值称为统计显著。
4. **编辑操作不是任务正确性保证。** 语法、事实、程序执行和用户指定内容是否保留，都需要额外评估；少编辑玩具实验和正确修复示例，不等于一般的最小修改、正确执行或硬约束求解。
5. **可复现材料仍不完整。** 附录提供网络规模、超参数和简化代码，但后者省去批处理、条件构造、速率缩放等细节；其线性调度和均匀抽取初始token也不同于主实验的部分描述。第三方代码有参考价值，不能替代官方实验实现或权重。
6. **向人体动作迁移仍是开放问题。** 如果将动作切成离散 token，插入一个 token 会改变多少真实时长、影响哪些身体部位、解码后是否保持接触和过渡连续，都取决于动作表示与解码器。本文没有动作数据集、运动学约束或控制执行实验，不能直接据此宣称解决了动作事件插删与重定时。

## 相关工作与启发

- **[Discrete Flow Matching](https://arxiv.org/abs/2407.15595)（NeurIPS 2024）：** 提供离散概率路径、CTMC与流匹配训练的基础。Edit Flows将常见的固定长度逐token变化扩展到序列级编辑，进一步利用辅助过程处理长度变化。
- **[Levenshtein Transformer](https://arxiv.org/abs/1905.11006)：** 同样通过插入和删除实现变长生成与修订。Edit Flows强调连续时间概率路径与速率匹配，训练目标不只是模仿一个离散编辑专家策略。[本文§4][paper]
- **[Generator Matching](https://arxiv.org/abs/2410.20587)（ICLR 2025）：** 用马尔可夫过程生成元统一多种生成模型。Edit Flows具体展示了辅助时间过程边缘化如何帮助构造可计算的序列编辑训练目标。
- **[Flow Matching with General Discrete Paths](https://arxiv.org/abs/2412.03487)：** 研究更一般的离散路径与动力学选择；本文进一步改变状态空间及编辑支持，使长度也能在生成过程中变化。
- **[OneFlow](https://arxiv.org/abs/2510.03506)：** 同作者团队后续将插入式离散文本生成与连续图像流结合，探索交错的多模态内容生成。它是后续工作，不是本篇已验证的实验范围。
- **启发：** 对动作研究，值得借鉴的是“编辑位置相对于已有结构”“长度与内容共同生成”“监督空间和推理空间分离”。若要形成可控动作系统，还需明确动作 token 的时长和身体含义、可保留区域、连续解码器及接触/事件验证；这些额外环节不能由文本编辑的概率框架自动获得。
