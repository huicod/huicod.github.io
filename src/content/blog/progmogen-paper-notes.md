## 一句话总结

ProgMoGen 把“走路时手一直贴墙、身体不越界、某一帧低头”等要求写成**可微的动作误差程序**，再让一个冻结的动作生成器反复生成并接受误差反馈，通过优化初始噪声寻找更符合要求的动作。新任务主要靠改程序表达，不必为每一类约束重新收集配对数据、训练专用生成网络。[图2、§3、式1][paper]

## 研究背景与动机

**领域现状：** 文本到动作模型已经能生成“走路”“搬东西”等整体动作；轨迹控制、关键帧补全、人和物体交互等工作，则进一步指定生成过程中的某些条件。许多方法围绕预先确定的一种输入形式设计网络或训练数据，例如提供每帧根节点轨迹。[§1–2][paper]

**现有痛点：** 实际动画需求往往混合多种条件：“走路时一直抱着直径0.4米的球”“从低矮横梁下面经过”“身体始终处于一个方形区域”。这些要求既包括相等关系，也包括距离下界、范围限制和条件触发；把它们全改写成逐帧精确坐标既费力，也可能过度限制动作。[图1、§4][paper]

**核心矛盾：** 用户希望新增控制任务时只改变要求，但模型通常把能接受的条件类型固化在训练中。直接对关节坐标做优化虽然灵活，又容易产生不连贯姿态、脚滑或过度平滑；需要同时利用约束表达能力与已学到的运动规律。[§1、§5.5][paper]

**本文目标：** 建立一种可组合、可扩展的动作控制接口，让同一个生成先验处理训练时未专门定义的约束任务，同时在约束误差、动作连贯性和语义之间取得可用的平衡。[§3.1、§5][paper]

**切入角度：** 很多动作条件都可以转换成“给定一段动作，计算它违反要求多少”的误差。例如手贴墙对应点到平面的距离，待在方形区域对应各坐标越界量。只要误差能对动作求导，就能通过生成器把反馈传回其输入噪声。[§3.2–3.4][paper]

**核心 idea：** 将任务拆成原子约束，用数值运算与控制流程组合成函数 F；固定生成器参数，让初始噪声 z 成为每次任务的优化变量。人工或语言模型负责写 F，扩散模型提供运动先验，优化器把两者连接起来。[图2–3][paper]

## 方法详解

### 整体框架

输入包含任务要求与数值参数 p，例如墙面方程、球直径、关键帧索引；还可以提供文本条件 C，描述“走路”等动作语义。人工或 LLM 把约束写成 F(x,p)。随机初始化 z 后，冻结的 MDM 以确定性 DDIM 过程生成动作 x，将其恢复成全局关节位置，再运行 F。梯度穿过整条生成链回到 z，Adam 更新 z，直到完成设定的优化轮数。[§3、图2][paper]

先看上方任务如何形成“动作语义 C”和“误差程序 F”两条支线，再沿中部看一次生成与误差计算，最后沿反向箭头回到 z。**LLM 输出的是评价动作的程序，MDM 输出的是动作，Adam 更新的是初始噪声。** 主流程不要求用户提供已有完整动作；个别实现会以第一次生成的动作作正则参照，限制根轨迹或身体部位的变化。[式1、附录A.3][paper]、[优化实现][ddim]

### 关键设计

1. **原子约束库：把要求转成可计算的几何和时间关系。**

   模型动作表示先通过可微映射 T 恢复为世界坐标下的关节位置。约束从这里读取关节、时刻、距离或差分量，不依赖文本特征中是否已经学到了特定关系。[§3.2][paper]

   | 原子约束 | 计算对象 | 可表达的例子 |
   | --- | --- | --- |
   | 绝对位置 | 关节位置与目标位置/轨迹的误差 | 手在首尾帧到达给定点 |
   | 高阶运动量 | 位置的数值差分 | 某些关键帧的速度大小与方向 |
   | 几何约束 | 点到直线、平面等几何对象的距离 | 手保持贴墙，双脚沿平衡木 |
   | 相对距离 | 两关节或身体点的距离 | 手与头保持指定间距 |
   | 方向 | 骨骼向量与目标方向的偏差 | 上臂指向某一方向 |
   | 关键帧 | 在指定时刻调用以上约束 | 首、中、末三帧的头部高度 |

   “手贴墙”只限制手到平面的距离，仍允许手在墙面内自由移动；完整手部轨迹则规定每个时刻的具体位置。前者保留的自由度更大，是本文超出传统轨迹控制的重要例子。这里的时间索引、平面与数值边界来自调用者或任务程序，并非模型自动检测出的动作事件。

2. **程序输出标量误差，逻辑关系采用数值惩罚组合。**

   F 的输入是动作和参数，输出一个标量。循环可把同一条件施加到所有帧/关节，条件语句可让约束只在某个区域内激活，例如“当头部进入横梁覆盖的 z 区间时，压低头部”。原文把常见逻辑关系写成如下运算：[§3.3、图3][paper]

   <div class="equation">要求 q ≤ b：max(q−b, 0)；要求 q ≥ a：max(a−q, 0)<br/>AND：E₁+E₂；OR：min(E₁,E₂)；NOT：−E</div>

   前两项是越界惩罚，在满足不等式的区域为0。后面三项是作者设计的数值组合约定，并非带完备性保证的布尔求解器。min/max 通常可以做分段求导，但分支选择、误差尺度、负项和相互冲突的要求仍会影响优化；程序合法也不等于目标可行。

   LLM 是可选的编程助手：先告知输入结构、原子函数和规则，再给任务描述，让它生成 Python 误差函数。作者没有在这里训练一个动作语言模型；附录评估的是生成程序与人工程序是否相符，而不是任意语言要求都能可靠执行。[附录B、图B1][paper]

3. **优化初始噪声：每次更新都要穿过完整的动作生成过程。**

   论文使用 HumanML3D 上预训练的 MDM，权重 θ 冻结，以 DDIM 把随机性集中到初始噪声 z。任务的核心问题为：[式1、§3.4][paper]

   <div class="equation">z* = arg min<sub>z</sub> F(G<sub>θ</sub>(z,C), p)，θ 固定<br/>x = G<sub>θ</sub>(z,C) → F(x,p) → ∂F/∂z → Adam 更新 z</div>

   存在两个不同循环：**内层100步 DDIM** 把当前 z 变成一段动作；**外层噪声优化**重新运行生成器、算误差、反向传播并更新 z，正文通常使用100次。不是只生成一次，再把手臂直接搬到目标位置，也不是用 F 更新模型权重。[§5.3][paper]

   公开代码明确设置模型参数 `requires_grad=False`，并让 `noise_init.requires_grad=True`，Adam 的参数列表只有初始噪声。主路径使用 η=0 的 DDIM；动作反标准化后从局部位置恢复22关节全局位置，再计算任务误差。[任务入口][entry]、[DDIM与坐标恢复][ddim]

4. **几何松弛：先在更合适的坐标布局中求解，再变回目标位置。**

   预训练动作的根轨迹覆盖范围有限，要求手去触碰远处的墙可能使优化很困难。作者利用水平平移、旋转不改变动作类型的性质，先把目标转换到更接近当前动作的等价几何布局。对贴墙任务，可拟合当前手轨迹对应的竖直平面；对搬运首尾点，可保持目标点间距、调整其朝向和中心，使其靠近生成轨迹。[§3.4、附录A.3][paper]

   实际过程可按若干步更新一次放松后的几何目标，在该目标下继续优化，最后对动作做相应空间变换。作者只在 GEO-1、GEO-2、HOI-1 使用这条路线，并为表2中的优化基线也使用松弛。它利用特定几何不变性降低难度，不是把任意矛盾约束都变成可满足条件。[附录A.3、表A1][paper]

5. **运动先验与约束分工：保持合理动作是取舍，不是硬性保障。**

   直接改动作的 IK 基线容易在稀疏关键帧处产生突变；给 IK 加时序正则又可能抹平真实变化。ProgMoGen 把搜索限制在生成器能产生的动作中，希望用其运动先验缓和这些问题。代价是有时无法像直接优化坐标那样把约束误差压得很低，或使动作偏离原文本语义。[§5.5、附录C][paper]

   对“抱球”的公开示例，实际任务配置还加入左右手顺序、根运动保持以及分阶段启用的胸部距离项；并非只有示意图里的两行距离误差。重球示例用人体与球的质量估计重心，再惩罚其水平投影到双脚中点的距离。论文的支撑区域描述与这段具体实现应分开；二者都未构成接触力、摩擦和动力学仿真的验证。[抱球配置][ball]、[重球配置][heavy]

### 一个完整例子

沿用原文图2：“一个人走路，同时抱着直径0.4米的球”。下列程序式子是教学简化，动作结果以作者展示为准。

1. **拆出语义与参数。** C 为“一人正在走路”；p 包括球直径 d=0.4米和胸部厚度 c。任务不需要先给一条完整行走动作。
2. **写接触关系。** 对每帧，双手间距应接近 d，误差可写成 |‖p<sub>L</sub>−p<sub>R</sub>‖−d|。
3. **写避碰近似。** 以双手中点作为球中心，要求它与胸部的距离不小于 d/2+c，用 max(d/2+c−距离,0) 处罚过近。这是球与身体点之间的几何近似，并未检查完整表面接触。
4. **生成并反馈。** 随机 z 经100步冻结 DDIM 得到动作；恢复全局位置，逐帧计算两项误差。反向传播得到 z 的梯度，Adam 更新 z，再重新生成。
5. **按需保留运动特征。** 实现可把初次生成的根速度作为参照，避免满足手部关系时退化成原地站立；这份参照来自生成器自身。
6. **增加重量要求。** 若要抱重球，另加重心相关项并继续优化。最终分别检查手距、避碰、根运动和脚滑；一项总误差减小不足以证明所有视觉与物理要求同时成立。[图1–2、附录A.3][paper]、[任务实现][heavy]

### 训练/推理

**预训练与当前任务优化是两回事。** 方法复用官方 HumanML3D 预训练 MDM，不为本文每个约束任务重新训练生成器；每次生成仍要付出噪声优化开销。LLM 编程也不改变 MDM 参数。[§5.3][paper]

| 环节 | 论文报告 / 当前实现 |
| --- | --- |
| 动作先验 | 官方 MDM，HumanML3D 预训练，冻结权重 |
| 采样内循环 | 100步 DDIM |
| 外层优化 | Adam；正文常用学习率0.005、100次迭代 |
| 任务调整 | 附录允许部分任务将学习率提高至0.05，并按需要加运动保持正则 |
| 几何松弛 | GEO-1、GEO-2、HOI-1；其他任务不默认启用 |
| 多初值搜索 | 附录比较1次与5次，按约束误差选结果 |
| 时间开销 | 附录称每个定制任务约需数分钟，面向离线内容制作；未提供统一硬件下的完整速度表 |

**配置复现边界。** 当前 HSI-1 发布脚本虽然写 `num_samples_limit=512`，入口按 `512//32+1` 计算17个批次，每批32条，实际对应论文的544个样本，不能据参数名字误判为样本数不一致。其任务优化器设为50次外层迭代，正文则给出通常100次；其他任务配置也各有步数，复现时需逐项核对。[HSI-1脚本][evalscript]、[批次生成入口][entry]、[HSI-1优化器][hsiconfig]

**发布资源。** 仓库提供原子函数、示例程序、基线与评估流程，链接外部 MDM 权重；演示需要相应归一化统计，完整评估还需要 HumanML3D 数据，网格与可视化另有模型和工具依赖。仓库中的 GPT 示例是已保存的生成代码，不意味着任意新任务已有自动纠错闭环。[README][repo]

四种 C.Err. 的定义不同：**HSI-2** 计算头部与双脚高度约束的 MAE；**HSI-3** 对所有帧、关节及 x/z 方向的上下界越界惩罚取平均，附录式2的分母为4NNⱼ，其中N为帧数、Nⱼ为关节数；**GEO-1** 是整段左手到指定平面的平均距离；**HOI-1** 是首尾两帧左手到对应目标点的平均距离。不能把这些数值简单横向排名，也不能为未报告成功率的任务套用 HSI-1 的5厘米阈值。[附录A.1、式2][paper]

MDM Edit 与 PriorMDM 原本要求具体轨迹，作者为相应任务构造轨迹、转换坐标并进行修补；不是这些模型直接读取同一约束程序。[§5.2、附录A.2][paper]

### 关键发现

1. **收益主要是约束与动作质量的折中。** HSI-1中，ProgMoGen 与IK有相同的0.012约束误差和8.8%失败率，但最大加速度0.094低于0.414，脚滑0.075低于0.093；其 R-precision 0.597又低于无约束MDM的0.610。不能概括为全部指标最优。
2. **更困难的约束仍会留下明显残差。** HSI-2约束误差为0.097，高于IK的0.047；贴墙、搬运也不是误差最低。先验有助于动作自然性，同时限制了能优化到的解。
3. **换目标无需重训，不等于每次生成便宜。** 外层要反复穿过100步DDIM，且多初值搜索进一步增加工作量；作者明确将其定位于离线内容制作。
4. **“能写程序”和“能生成满足程序的动作”是两层证据。** 14/20衡量任务程序，5厘米失败率衡量某项动作实验，不能相互替代。抱球与重球恰是论文成功的人工设计演示，却也是LLM编程未成功的任务。

## 亮点与洞察

- **把控制接口改为可计算要求：** 用户不必给出所有逐帧位置，可以规定“接触这面墙”“留在这片区域”等更宽松的关系，让生成器自行选择其余运动自由度。[§3.2、§4][paper]
- **可解释程序与运动先验分工：** 函数F说明什么算违反要求，冻结生成器提供动作分布，噪声优化连接二者。新增任务不一定需要新增网络接口。[式1][paper]
- **展示了程序组合的实际价值：** 同样的距离、范围和关键帧模块能够组合成自接触、空间限制与搬运等任务；这种扩展发生在推理程序层，而非新增动作类别标签。[图1、图4][paper]
- **报告了自动编程失败及优化取舍：** 14/20、随机重启的FID变化和几何松弛的脚滑代价，为后续系统设计提供了比“全部可控”更具体的依据。[表A1–A3][paper]

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

- **约束表达尚不覆盖所有动作属性。** 作者检查 BABEL-120 后指出，接近16%的动作涉及周期、旋转或对称运动，当前库没有直接支持；附录也将频域、旋转与对称约束列为后续方向。[附录C][paper]
- **语言模型可能选错关系。** 常见错误包括不等号方向错误、额外加入不合适的物理条件。程序可运行、可求导与忠实表达用户意图，仍需要分别检查。[附录B][paper]
- **几何或重心代理不能替代物理执行。** 手到墙的距离没有检查手掌朝向和接触面，重心位置没有求解摩擦、力矩与碰撞。代码也可能仅在选定关节或简化几何上算误差；论文没有给出机器人或物理角色控制器执行验证。[§4.6、附录C][paper]、[重球示例][heavy]
- **优化可能改变语义或失败。** 作者观察到不自然姿态、较大约束残差以及文本语义轻微变化；损失项设计、初始噪声和生成器分布共同影响结果。多初值选择改善约束误差时，也可能损失多样性。[表A2、附录C][paper]
- **离线计算与复现设置仍是成本。** 每任务数分钟的噪声搜索不适合即时交互；默认发布配置与论文通常设置也不完全一致。论文没有披露可据以计算统一GPU成本的硬件、总时长和系统测量。[附录C][paper]、[发布脚本][evalscript]

## 相关工作与启发

- **[MDM](https://guytevet.github.io/mdm-page/)：** 提供本文冻结的文本动作先验。其原有补全接口面向具体运动值，ProgMoGen在外部添加可微关系误差，并沿完整生成链优化初始噪声。[§3.4、§5.2][paper]
- **[PriorMDM](https://priormdm.github.io/priorMDM-page/)：** 复用动作先验并支持运动组合与控制。ProgMoGen比较的是其经过任务适配的轨迹修补路线；程序式不等式和跨关节关系仍是不同的控制接口。[附录A.2][paper]
- **[OmniControl](https://neu-vi.github.io/omnicontrol/)：** 处理任意关节的空间轨迹控制。ProgMoGen把轨迹作为绝对位置约束的一种，还允许平面、范围、关节关系与时间条件组合；代价在于逐任务的迭代优化。[§2–3][paper]
- **IK与轨迹优化：** 都能使用显式目标函数，本文区别在于优化变量通过学习到的生成器映射成动作。直接优化位置通常更容易降低约束残差，生成先验则帮助缓和姿态与时间连续性问题，二者的优势可互补。[§5.5、附录C][paper]
- **启发：** 设计语言到动作系统时，可以把用户意图编译为可检查的误差程序，把动作生成和约束求解分开。但完整系统还要检查程序是否表达正确、目标是否可行，以及解码动作是否满足每条要求；不能只看程序存在或总损失下降。
