## 一句话总结

LMM先把不同骨架、帧率和条件的数据整理成**十部位统一动作表示**，再用**ArtAttention扩散模型**同时处理文本、语音、音乐、视频与动作补全；通过无条件动作预训练和多任务条件微调，让不同任务共享动作先验。[§3–4、图2–4][paper]

它的重点是“**不同来源的数据如何共同训练一个动作生成系统**”。这里的统一包含共享主干、数据集专用输入输出层和评测转换器，并不意味着所有任务使用完全相同的外部数据格式，也不意味着它能做动作问答或自动裁决相互矛盾的指令。

## 研究背景与动机

**领域现状：** 文本生成动作、音乐生成舞蹈、语音生成手势和动作预测，往往各自使用专门的数据集与模型。MDM、MotionDiffuse等扩散方法表明，动作生成可以由连续去噪完成；UDE、MCM等开始连接多个条件任务，但数据覆盖和格式兼容仍有限。[§1–2][paper]

**现有痛点：** 舞蹈数据可能有完整身体但没有手指，演讲数据可能只有上身，另一些数据有SMPL-X与表情；同样的“运动”还可能以旋转、关键点或不同帧率存储。直接合并会把缺失部位误当作真实静止动作，也难以沿用各数据集原来的评测。

**核心矛盾：** 想利用更多数据，需要一种可共享的动作描述；但为了保留真实数据的信息与评测口径，又不能把所有数据强行压成同一种不完整骨架，或者假设缺失的手和脸都已经观测到。

**本文目标：** 建立能整合异构数据的MotionVerse，并训练一个接受多种条件、能生成和补全动作的通用模型，检查扩大数据和模型后能否获得跨任务收益。

**切入角度：** 以**身体部位**作为共享单元，以**可见动作掩码**表达预测和补间任务；同时把文字、音频和视频条件编码成可共同使用的特征。这样既保留身体结构，也能明确区分“原本没有这个部位”和“有数据但训练时主动遮住”。

**核心 idea：** 先统一动作和条件的接口；再用部位注意力与真实时间查询，吸收不同来源的运动规律；最后先学无条件动作先验，再学条件与动作的关系，使同一主干可以承担多种生成任务。[§3–4][paper]

## 方法详解

### 整体框架

MotionVerse负责离线整理数据：动作统一为十部位表示，条件经ImageBind编码。生成时，带噪动作及可选的已知动作上下文先进入**数据集专用Read-In**，共享主干通过**空间与时间两路ArtAttention**融合部位关系和多模态条件，再由专用Read-Out预测干净动作，重复采样得到连续序列。训练分为不使用条件的预训练与使用成对条件的微调；评测另接转换器恢复目标数据集格式。[图2–4、§3–4][paper]

先看上方数据如何统一，再沿中部“条件与动作输入→共享主干→动作输出”阅读；底部的真实动作与重建监督只在训练时提供。空间支路和时间支路并行，**时间模板是连续特征中的计算结构，不是人工标注的动作事件或可读动作词**。

### 关键设计

1. **用“条件 + 可见动作”统一任务，但输出始终是动作。**

   正文式1以Θ=M(x,m,c)概括任务：x是动作序列，m标识哪些位置可见，c是外部条件。动作预测给前缀，补间给前后两端；文本生成只给描述，多条件生成可以同时给文字和音乐。这些差异不必都变成完全不同的网络。[§3.2、表1][paper]

   | 任务 | 已知动作 | 外部条件 | 输出 |
   |---|---|---|---|
   | Text-to-Motion / Action-to-Motion | 无 | 动作描述 / 动作类别 | 动作序列 |
   | Music-to-Dance / Speech-to-Gesture | 无 | 音乐 / 语音 | 舞蹈 / 共语动作 |
   | Motion Imitation | 无 | 视频 | 对应三维动作 |
   | Motion Prediction | 前k帧 | 无 | 后续动作 |
   | Motion In-betweening | 缺口前后帧 | 无 | 缺口内动作 |
   | Conditional Motion Prediction | 前k帧 | 一种外部条件 | 受条件影响的后续动作 |
   | Conditional Motion In-betweening | 缺口前后帧 | 一种外部条件 | 受条件影响的补间 |
   | Multi-condition Motion Generation | 无 | 多种外部条件 | 联合条件下的动作 |

   前两行各含两个任务，总计10项。**这里没有动作描述生成、动作理解问答或语言输出任务**；“多模态”指输入条件与动作数据的来源，不等于一个同时生成各种模态的聊天模型。

2. **统一表示保留动作细节，同时显式承认部位缺失。**

   作者在TOMATO式表示基础上去掉足接触项，保留根节点角速度、水平速度、高度，以及局部关节位置、速度、6D旋转和表情。使用22个主要身体关节与30个手部关节，再划分为根、头、脊柱、左右手臂、左右腿、左右手与面部。[式2、§3.3][paper]

   官方代码对应每帧**669维连续数值**：4维根运动 + 51×3位置 + 51×6旋转 + 52×3速度 + 50维表情。这些不是离散token ID，也不是669个动作词；网络Read-In后的部位特征同样是连续向量。[统一表示实现][representation]

   原数据缺少整只手或面部时，记录部位可用性，不要求网络为这些不存在的真值承担重建损失。对于部位内部缺失关键点，作者采用人工设计的估计或插值补齐，多余关键点则丢弃；因此它仍然依赖映射到统一骨架，**不是任意拓扑、任意缺点都能原样接入**。[补充A.1、D][supp]

3. **共享主干与专用接口并存，避免把不同数据分布混为一谈。**

   格式统一后，动捕、视频估计和演讲动作的分布仍不同。因此Read-In和Read-Out按数据集区分，每个部位分别映射，主干才共享。训练有10%概率把数据集名换成`all`，让模型同时学习较通用的接口，便于真实应用。[§4.2][paper]

   **Motion Translator又是另一层工作**：它把生成的统一表示转换回HumanML3D评测向量或不同关键点格式。补充A.2使用MLP处理三种评测表示，是否先恢复全局关键点取决于该任务是否评估全局平移与朝向。Read-Out是生成器的一部分，Translator是跨评测格式的桥接；二者都不能简单省略成“输出SMPL-X参数”。[补充A.2][supp]

4. **ArtAttention空间支路：让部位关联随当前可见信息改变。**

   主干特征形状为F×H×d，H=10对应部位。空间支路对每帧的部位特征进行归一化与MoE映射，再计算部位间注意力，得到Yₛ。原始数据会缺部位，训练又会人工遮住部位，固定的部位混合系数无法适应所有输入，因此作者把FineMoGen中的对应机制改为动态注意力。[§4.3、图4][paper]

   这提供的是**身体结构上的信息交换**：例如手臂预测可以利用躯干和头的信息。它不直接构成手掌必须到达某个三维点、脚必须维持接触的几何求解器。

5. **ArtAttention时间支路：先控制不同来源的归一化，再按真实时间查询。**

   ImageBind输出再经过两层可学习Transformer，得到文字、语音、音乐和视频的条件序列。时间分支中每个注意力头对应一个部位，经MoE形成动作和条件的K/V。作者发现，把很长的条件序列和动作序列直接拼接后一起Softmax，会削弱动作自身相关性的建模；因此**动作K单独归一化，条件K另行归一化**。条件侧加入64个可学习K/V占位token，支持无条件生成。[§4.3][paper]

   聚合后得到一组带时间中心的全局模板：每个模板预测中心时刻、局部状态及Taylor展开系数；某帧按自己与各中心的时间距离加权查询模板。补充式2–4可以简写为“**某时刻的特征 = 各模板在该时刻的局部预测之加权和**”。这里的“状态、速度、加速度”属于latent特征建模，不能直接当成物理关节速度或接触约束。[补充B.2][supp]

   相比FineMoGen使用帧索引，LMM使用k/fps这样的**秒位置**，从而支持不同帧率。最后Y=Yₛ+Yₜ，经Stylization、残差和FFN继续处理；Stylization注入扩散步、帧率和数据集身份。**扩散步t和动作发生的秒位置是两个不同的时间轴。**[§4.3、补充B.3][paper]

   **论文与发布代码的差别：** 上述“动作K与条件K分别归一化”是正式论文机制；核对当前固定版本时，时间支路先将各路K除以可学习的`key_scale`，随后拼接并统一执行Softmax。代码中的64个额外K/V由48个数据集相关项与16个旋转类型相关项构成。空间支路另有自己的Softmax，不能拿它充当时间支路的“分别归一化”。因此本文图示解释论文设计，不能声称当前仓库逐行实现了完全相同的机制。[ArtAttention实现][attention]

6. **随机降采样与两种mask：既学习动作先验，也避免忽略条件。**

   预训练忽略条件，仅用动作。随机降采样后必须重新计算速度分量，否则同一条慢动作会因时间间隔变化而留下错误速度；位姿状态则按对应帧取样。[§4.4][paper]

   mask分两类：**原始缺失部位**没有可信真值，损失忽略；**人工随机遮住的部位/位置**有真实数据，Read-In后换成可学习空token，但仍需恢复。模型既去噪，也利用可见部分推断被遮住的动作。作者认为，这能减少模型在后续微调中过度依赖带噪动作、忽略外部条件的倾向；主文消融支持该现象，但没有把它证明为对所有架构都成立的定律。[§4.4、表6][paper]

   微调再接入成对条件，10%概率丢弃条件以支持CFG。这里的“无监督预训练”仅指这一阶段不使用条件标签，**完整系统仍依赖预训练ImageBind和微调阶段的条件—动作配对数据**。

### 一个完整例子

原图5(f)展示<strong>“拍手”文字描述 + 音乐</strong>共同控制的动作。下面沿这类实例解释内部流程；具体中间向量与动作时长为教学说明，未运行生成。[图5(e)(f)][paper]

1. **输入：** 提供“clap hands”以及一段音乐，并选择输出时长、帧率和数据集/`all`接口。这些是用户条件，系统没有先让LLM写出“第2秒左手到某坐标”的动作程序。
2. **编码条件：** 文字与音乐分别经ImageBind和条件Transformer，成为两路条件token；二者可以同时进入时间注意力，不必在这次生成中二选一。
3. **建立待生成动作：** 初始化F帧统一动作噪声，转换为10个部位特征；若做补全任务，还需合并用户提供的可见动作，此处无已知前缀。
4. **反复预测：** 空间支路协调躯干和双臂等部位，时间支路结合文字、音乐与动作自身信息，按秒位置查询模板。Read-Out输出干净动作预测，采样器据此更新，最终得到连续动作。
5. **解释结果边界：** 论文展示拍手内容与音乐节奏兼容的定性例子；没有报告“手掌接触误差为零”或同一部位受到互斥命令时的优先级实验。若音乐倾向快速摆臂而文字要求双手始终固定，现有注意力融合没有给出显式裁决规则。

这也解释了为什么不能把本文说成“只支持互斥的单条件任务”：原图5已有文字与音乐联合输入；但进一步声称它解决了任意三条件、同部位控制冲突，同样超出了论文证据。

### 训练/推理

**数据。** MotionVerse整合16个数据集，论文报告约320K序列、100M帧。来源包括HumanML3D、KIT-ML、Motion-X、BABEL、UESTC、HumanAct12、NTU-RGB-D 120、AMASS、3DPW、Human3.6M、TED-Gesture++、TED-Expressive、Speech2Gesture-3D、BEAT、AIST++和MPI-INF-3DHP。补充A.1说明会排除跨数据集与测试动作重叠的训练序列；这项处理很重要，因为多个数据集源自AMASS。[表2][paper]、[补充A.1][supp]

**采样比例。** 多任务batch不是按原始序列数量直接混合：文本动作40%，无条件动作25%，类别动作10%，语音手势10%，音乐舞蹈5%，视频模仿10%。文本内部HumanML3D和Motion-X各15%，KIT与BABEL各5%；视频模仿训练使用MPI-INF-3DHP和H36M，不使用3DPW。比例是训练设计，不能拿总数据帧数推断每种模态获得相等监督。[补充C.1][supp]

**训练目标与规模。** 扩散模型预测干净动作x₀，以恢复原始动作作为监督；原始缺失部位不参与重建。Tiny/Small/Base/Large分别为**90M/160M/410M/760M参数**，层数4/8/12/20，MoE专家数16/16/16/32；人工mask概率分别为0.1/0.2/0.3/0.4。[§5.1][paper]、[补充B.1、C.1][supp]

**训练成本。** 总batch固定512。Tiny使用**8张32GB V100，每卡64样本**；更大模型使用FP16和梯度累积，作者只披露不超过32张V100，没有逐型号分配。Adam预训练80K步、学习率2×10⁻⁴；微调先20K步同学习率，再20K步降为2×10⁻⁵。论文未给训练墙钟时间、各型号GPU小时或账单，不能据GPU数量直接算出总训练费用。[§5.1][paper]

**推理与公开实现。** 当前配置训练扩散链为1000步，demo以50步DDIM采样；CFG权重随扩散步变化，并非始终使用一个固定5.5。公开demo单段上限200帧，20 fps下为10秒；多段利用模板时间偏移交互后拼接，不宜改写成已验证的自回归历史续写或实时流式接口。[采样与主干实现][model]、[官方demo][demo]

**已知动作如何进入采样。** 实现确实有数值覆入：每次DDIM去噪前，按当前噪声级缩放已知动作，在`context_mask`标识的位置替换采样输入；随后继续模型预测和DDIM更新。但该步骤结束后未再对最终结果执行一次硬投影。因此这里既不能说“已知帧只是一种软语义提示”，也不能直接宣称最终每个已知帧都精确不变。[DDIM上下文处理][sampler]

**复现范围。** 公开目录可见Tiny demo权重及ImageBind，数据下载目录也并非16个源数据集全部齐备；当前仓库中demo配置引用的同目录基础配置缺失，需补齐依赖后再实际测试。demo会关闭面部mask，只可据其代码确认身体与手部可视化路径；“表示包含面部”与“发布demo已经验证面部生成”是不同结论。[权重目录][weights]、[配置][config]、[demo][demo]

## 实验关键数据

### 主实验

### 消融实验

**随机降采样、随机mask和注意力替换，正文表6完整转录。** 全部使用LMM-Base；3DPW列为MPJPE(mm)，越低越好。

**随机mask：** 固定降采样与ArtAttention，只移除mask，FID从**0.138恶化到31.365**，Top-1从**0.511降到0.028**。作者解释模型过于擅长从带噪动作恢复原序列，微调时未充分使用条件；较高MM此时伴随语义与质量崩坏，不能单独当成进步。

**随机降采样：** 在已有mask和ArtAttention时加入降采样，FID从**0.151到0.138**，3DPW 1000 ms误差从**76.1到73.6 mm**；Top-1则从**0.515到0.511**，说明它改善的不是所有指标。

**ArtAttention：** 保留两种增强，将SAMI换为ArtAttention，FID从**1.866到0.138**，3DPW 1000 ms从**80.9到73.6 mm**。该对照支持整套注意力改动的作用，但没有分别隔离“64个占位token”“分开归一化”和“真实时间查询”各自的贡献。

**预训练与多数据集：** 补充表7中，Large完整模型的HumanML3D FID/3DPW 1000 ms为**0.040/68.0**；不预训练为**0.075/74.2**，单数据集训练为**0.086/75.9**。Small则存在取舍：不预训练FID **0.144**优于完整设置**0.227**，但预测误差**87.6 mm**差于完整设置**82.8 mm**。不能把“大规模联合预训练对任意容量和任务都提高成绩”写成结论。

**通用`all`接口：** Large使用`all`标签时，FID由**0.040变为0.107**，MM由**2.683升为2.915**，3DPW 1000 ms由**68.0变为69.0 mm**。作者认为评估器偏向目标数据集分布，可能使更广泛但合理的动作受到惩罚；这是作者对现象的解释，不能据此断言所有较差FID都只是评估器问题。[补充C.3、表7][supp]

### 关键发现

1. **扩大模型后，共享动作先验更容易体现收益。** HumanML3D FID从Tiny的0.415降到Large的0.040；Tiny还弱于FineMoGen，说明合并更多任务本身不保证小模型变好。论文改变层数、宽度与专家数来扩容，并没有建立可用于外推任意规模的训练缩放定律。
2. **预测优势主要出现在较长跨度。** 3DPW 80 ms时Large为13.1 mm，差于GCNext的11.8；1000 ms时Large为68.0，优于72.0。作者把短期不足部分归因于表示转换器噪声；泛化收益与转换误差同时存在。
3. **多模态覆盖不等于每个专项都最佳。** 舞蹈Large的FID<sub>k</sub>22.08落后TM2D的19.01，BeatAlign也低于Bailando；BEAT三项指标均不及CoG。音乐数据采样占比仅5%是作者提出的可能原因，未做控制占比的专项因果实验。
4. **文本可以改善已有动作上的补全。** 同样给前25帧，增加文本使误差63.8→54.7 mm；同时给前后端时59.1→51.9 mm。这是条件补全的量化证据，不能替代精确关键帧投影、接触或事件时刻控制测试。
5. **联合输入有演示，但系统性冲突评测缺失。** 图5(e)(f)提供文字与音乐联合结果，补充图2展示文字影响预测和补间；没有给出同一身体部位上的互斥指令基准或明确优先级。后续比较应保留这两层证据。

## 亮点与洞察

- **先处理数据兼容，再谈模型统一：** 真正费力的部分包括关节映射、缺失部位、帧率、跨数据集测试重叠与评测转换，不能只通过在摘要中列出多种输入完成。
- **分离原始缺失与人工遮挡：** 前者决定哪里没有监督，后者决定哪里应该推断恢复。同样一个mask操作，在训练中承担的责任可能相反。
- **条件竞争会发生在归一化层面：** 条件序列比动作序列长时，共同Softmax可能改变信息权重；LMM先分别归一化，是一个具体的多模态工程改动，而不只是增加输入分支。
- **用真实时间连接不同采样率：** 按秒查询模板，并在降采样时重算速度，使“不同fps的数据共享运动知识”有了相应机制；但它不是节拍标注，也没有把每个token解释为相位。
- **允许统一模型中的局部专用性：** 共享主干配数据集专用接口和`all`接口，提供了实际折中。评估统一程度时，应分别查看权重共享、外部表示与使用入口，而不是只看模型名称。

<span id="reading-6" class="reading-anchor"></span>
## 局限与展望

1. **统一骨架仍有损失。** 作者明确指出，当前表示适合缺少整个部位，却难以处理部位内部任意关键点缺失；Translator会引入额外噪声。任意拓扑角色、轮椅姿态或不同手部结构不在已验证覆盖内。[补充D][supp]
2. **没有硬几何约束层。** 输出为统计生成的连续动作，表示中还移除了足接触项。本文没有证明手掌精确接触、指定关节轨迹、无穿插或每个关键帧最终严格相等；这不等于必然失败，而是需要独立约束与结果测量。
3. **多条件没有显式控制权。** 多路K/V能共同参与，也能做文字与音乐的组合；但没有明确规定语音、音乐、文字在同一部位矛盾时谁优先。若用于可编辑角色系统，我的启发是把部位/时间范围与冲突规则设计成外部接口，再验证生成器是否遵守。
4. **长序列受显存与拼接机制限制。** 作者承认长期动作依赖零样本组合；公开demo用分段模板与拼接，不构成在线感知、低延迟因果输出或长期不漂移的证据。[补充D][supp]
5. **模型与发布完整性有差距。** 最强结果来自760M的Large，当前公开下载目录主要可核实Tiny demo权重；配置继承缺口、数据许可与部分源数据准备还需处理。本文完成了全文与源码检查，未做训练、推理或速度测试。
6. **评测范围仍偏单人动作生成。** 文本检索、分布距离、节拍分数和关键点误差回答不同问题；它们不能单独确认模型理解了动作因果、角色意图或对话中的精确手势语义。

## 相关工作与启发

- **[FineMoGen](https://mingyuan-zhang.github.io/projects/FineMoGen.html)：** LMM明确以其扩散结构和SAMI为起点，保留时间模板思想，增加动态部位注意力、多模态独立归一化及按真实时间查询。这里最值得追踪的是从“文本细粒度动作”到“异构任务共同训练”时，哪些结构必须改动。
- **[MotionDiffuse](https://mingyuan-zhang.github.io/projects/MotionDiffuse.html)：** 二者都直接在连续动作表示上进行扩散。LMM的主要扩展是跨数据集接口、部位结构、多条件编码与预训练，并未先把动作量化成离散语言词表。
- **[UDE](https://zixiangzhou916.github.io/UDE/)：** 原文把它作为统一文本和音乐动作生成的前序工作。LMM进一步面对不同骨架、缺失部位与更多任务；不能仅凭“统一”二字认为双方都验证了完全相同的输入组合。
- **[MoMask](https://ericguo5513.github.io/momask/)：** 主表中的文本动作对照走离散残差量化和掩码生成路线；LMM则用连续动作去噪。两者都出现“mask”，但被遮住的对象与生成机制不同，LMM没有因此成为离散token模型。
- **[ImageBind](https://imagebind.metademolab.com/)：** 为LMM提供跨模态条件特征的公共起点；共享特征空间能降低接入成本，却不能代替具体动作配对学习、时序对齐或控制冲突处理。
- **启发：** 对希望同一个角色既跳舞、说话打手势又执行文字动作的系统，LMM说明了共享动作先验的一条可行路线；更完整的控制系统还应明确动作内容、身体部位、有效时间与冲突优先级，并在解码后的动作上验证，而不是把注意力权重当成执行保证。
