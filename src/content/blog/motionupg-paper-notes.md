## 一句话总结

MotionUPG 把“细粒度自然语言描述”和“各身体部位的学习型动作 token”连成混合句子，用它训练 LLaMA 同时学习动作理解、计划和生成。推理时先把文字、语音或音乐转成更具体的动作描述，再把描述连同原输入送回模型生成 token，最后用带文字条件的解码器恢复连续动作。

## 研究背景与动机

**领域现状：** 文本生成动作、语音生成手势、音乐生成舞蹈已经各有专用模型。另一条路线把动作和音频量化成 token，加入语言模型词表，以统一的下一个 token 预测处理不同任务。这样能统一接口，却不意味着不同模态之间已经建立了细致对应。

**现有痛点：** 一句“模仿踢足球”同时包含躯干稳定、单腿支撑、另一条腿摆动和手臂平衡。若一个动作 token 混合了数帧的全身变化，而训练描述只给出一个粗动作名字，语言模型很难知道哪一部分 token 负责哪一部分指令，更难重新组合已有动作经验来响应新场景。

**核心矛盾：** 文字可以按部位、方向、姿态和阶段拆解动作，普通全身 token 的内部含义却高度混合。音频又往往只提供节奏、情绪或语义线索，不直接描述身体怎样移动。仅把几种 token 拼在一个输入框里，无法自动解决这两种粒度差异。

**本文目标：** 让一个模型支持文本动作、语音手势、音乐舞蹈，以及文字与音频联合控制，并改善文字与最终动作的细粒度对应。作者还希望利用语言模型的先验，把不常见的情景转化为可由已有动作基本成分组合出的计划。

**切入角度：** 一方面按身体部位组织学习 token，降低全身动作混在一起的程度；另一方面扩充训练描述，让它明确交代身体各部位的动作。自然语言由此成为音频条件、场景理解和动作编码之间的中间表示。

**核心 idea：** 用几何算子和 GPT-4o 为已有多模态数据补充细粒度描述，构成 MotionWords；训练带文字条件的分部位 tokenizer；再用“描述在前、部位 token 在后”的混合句子训练 MotionUPG。生成时先写计划再出动作，并让解码器继续参考这份计划。

## 方法详解

### 整体框架

可以把方法分成**数据标注、动作表示、语言模型训练、两步推理**四部分。数据侧的 GPT-4o 用于补充训练描述；任务模型则是经过 LoRA 训练的 LLaMA 3.2 Instruct 3B。文字计划既进入语言模型生成 token 的过程，也进入连续动作解码器，因此它不是仅供读者阅读的旁注。

### 关键设计

1. **MotionWords：先从几何提取证据，再由 GPT-4o 整理细节**

   直接让大模型看一段动作并写长描述，可能出现部位错认或凭常识补充不存在的动作。作者先计算主要关节的旋转角、相对距离和位置关系，转成简短的原子描述，再把这些线索交给 GPT-4o。

   例如，肩—肘—腕关系提供手臂弯曲程度；两关节距离小于 **10 cm** 时可描述它们靠近；若水平位置接近、垂直位置存在小偏移，可形成“左腕大致位于右腕上方”的关系。这里的几何判定是数据标注步骤，不是最终生成动作必须满足的硬约束。

   GPT-4o 还接收论文所述的原始动作数据、均匀采样的动作帧、粗描述与少量示例，输出每段动作的三份细粒度描述。HumanML3D、Motion-X 使用原有粗描述，AIST++、FineDance、BEAT2 则可使用“正在跳舞／说话”这样的简单起点。它把原本缺少动作文字的音频数据也纳入同一种描述体系。（§3.4）

   MotionWords 汇集 **245.7 小时动作、60 小时语音、12.9 小时音乐**，原始粗描述约 210 万词，新增细粒度描述约 **6,820 万词**。这里的统计单位是 words，不能将其写成 6,820 万条独立动作或人工标注。

2. **SDMT 分部位量化：降低全身 token 内部的耦合**

   Semantic-aware Decoupled Motion Tokenization 将身体拆成躯干、左腿、右腿、头、左臂、右臂六部分；存在详细手部数据时，另处理左手和右手。每个身体部分有独立编码器和三层残差量化，手部则分别使用普通单层 VQ-VAE。

   残差量化先用第一层码表达主要特征，再用后续层表达尚未重建的残差。正文实现设置为身体每层码本 1,024 项、共三层，码向量维度 1,024；每只手的单层码本为 512 项。身体部分的时间下采样率为 4，因此这些 token 仍保留时间顺序，只是额外按身体部位组织。

   这种拆法让“改左臂”和“改右腿”有可区分的 token 区域，但每个编号仍是学习出来的码本索引。“原子”在这里指更局部的动作单元，不能理解为每个编号都天然对应一个可直接读懂、可精确执行的动作词。（§3.3、§3.5、§4.1）

3. **文字进入解码器：计划参与恢复连续动作**

   部位 token 转回量化向量后，先与相应部位的文字特征通过 DiT block 融合。各身体部位特征再拼接，与全局动作描述进一步融合，经前馈网络输出不含手部的身体动作。两只手则由各自 VQ-VAE 解码，最后与身体结果组合。

   这使同一份细粒度文字同时约束局部动作和全身协调：部位描述告诉模块怎样处理某只手臂，全局描述提供整体动作背景。论文使用了 DiT block 作为条件融合模块，但所述动作生成主流程是自回归 token 生成加条件解码，不能仅凭模块名字把它写成扩散采样流程。

   消融中的“去掉 Semantic-aware Tokenization”特指不再向解码器注入文字特征，仍保留分部位与残差量化。这个区别很重要，否则会把一个文字条件消融误读为完全换回普通全身 tokenizer。（§3.3，Figure 3，§4.2）

4. **混合动作句子：可读计划在前，学习型 token 在后**

   混合句子先放细粒度描述，再用特殊标记包住按部位排列的动作序列。其结构可简化表示为：

   <div class="equation">细粒度描述 → &lt;SOM&gt; → 躯干 → 左腿 → 右腿 → 头 → 左臂 → 右臂 → 可选双手 → &lt;EOM&gt;</div>

   每个部位内部仍包含按时间排列的多层量化索引。描述先于动作出现，适合自回归模型先决定“要怎么做”，再逐步生成动作符号；身体部位顺序则为文字和动作提供稳定的对应组织。

   例如，一个教学用的 120 帧身体片段，按下采样率 4 得到每部分 30 个时间位置；六部分、三层量化合计需要 6×30×3 = **540 个身体码索引**，还没算文字、分隔符与可选手部。这个例子说明分解提高了可组合性，也可能带来较长序列；论文没有据此提供在线延迟保证。

   因而，混合句子应理解为“可读描述＋学习型离散表示”的组合，而非把所有动作变成了纯自然语言符号系统。（§3.5，Figure 4）

5. **多任务训练与两步生成：让细粒度文字连接不同条件**

   预训练包含三类任务：细粒度文字→动作、动作→细粒度文字，以及给定部分动作 token 续写后续 token。这既教模型生成，也使它在训练中见到动作和描述之间的双向联系。

   随后的指令微调覆盖粗／细粒度文字动作、语音手势、音乐舞蹈及文字与音频联合任务。语音和音乐统一为 16 kHz WAV，由 **WavTokenizer** 转成离散音频 token，进入同一个语言模型。这里的音频 token 与动作码本不同，也没有被宣称具备逐词可读语义。

   普通生成时，模型先根据粗文字、语音或音乐产生细粒度动作描述，再把描述与原始条件一起输入，生成动作 token。联合控制时，先从音频产生描述，再把用户文字要求反映到描述中，最后结合原音频生成动作。

   正文说明了描述修改的接口与过程，却没有给出足以证明所有冲突指令都能被满足的验证机制。可编辑计划使控制位置更明确，最终是否落实仍要看解码后的动作。（§3.5、Table 1）

### 一个完整例子

以论文 Figure 1 提到的“人在说话时模仿踢足球”为主线。下面的分部位计划是解释机制的教学示意，不是作者公开的模型逐步日志，也不是已经运行验证的输出。

1. **输入条件。** 给出一段说话音频，并增加“讲到踢球时做出踢球动作”的文字要求。音频通过 WavTokenizer 编码，文字则进入 LLaMA 的文字 token 通道。
2. **先拟定动作。** MotionUPG 根据音频形成细粒度动作描述，再融入踢球要求。计划可以表达：一条腿支撑，另一条腿向前摆动，躯干维持平衡，双臂作相应调整。具体左右腿、摆幅和时间如果没有在输入中明确，仍由模型选择，不能从任务名称推断固定答案。
3. **展开成混合句子。** 修改后的描述与原始音频一起作为条件，模型按躯干、双腿、头、双臂及可选双手的顺序生成动作 token。这里产生的是可供码本查表的索引，并非直接把“向前踢”交给一个预设动画函数。
4. **恢复连续动作。** 各部位索引转成量化向量，与对应文字融合；全局文字再参与身体特征融合。身体解码结果与手部解码结果组合，得到连续动作序列。
5. **检查真正的输出。** 有效结果应同时呈现说话状态和踢腿意图。论文的多模态示例说明了这种能力方向，但正文主表没有报告“指定词语时刻准确踢出、脚尖精确命中目标、支撑脚完全不滑动”的成功率，因此不能把合理的文字计划当成这些条件已经实现。

与直接从音频预测全身 token 相比，这条流程多了一个能够检查和修改的计划层。但如果计划先写错、生成器没有跟上计划，或解码器改变了细节，最终动作依然可能不符合要求。

### 训练/推理

MotionWords 由 HumanML3D、Motion-X、BEAT2、AIST++、FineDance 组合，并为它们补充细粒度描述。身体表示采用 HumanTOMATO 格式；正文提到其可容纳更细的手指与面部信息，但方法描述主要展开六身体部位和可选双手，没有给出足以单独核对面部输出能力的实验。

语言模型基于 **LLaMA 3.2 Instruct 3B**，采用 LoRA：rank 64、alpha 128、dropout 0.05；AdamW 学习率 2×10⁻⁵，batch size 4，余弦学习率调度。原文披露预训练 800 epoch、跨任务指令微调 1,000 epoch，但没有同时给出足够的实际步数、采样定义和硬件耗时；因此不把这些数字换算成训练费用。

这是需要训练的动作语言模型，不是仅向通用 LLM 写提示。GPT-4o 主要承担数据标注，经过任务训练的 MotionUPG 则承担条件到计划、计划到动作 token 的映射。推理后的连续动作还依赖训练好的 SDMT 解码器；仅获得可读计划或语言模型权重不足以恢复完整流程。

### 消融实验

**细粒度文字与语义解码：** Table 5 依次比较不使用细粒度文字及语义文字注入、使用细粒度文字但不向解码器注入、完整模型。FGD 为 **5.978→5.443→5.224**，Diversity 为 **12.751→13.114→13.219**，但 BC 同时从 **7.695→7.228→7.198**。质量与多样性提高，语音节奏对应有所下降，这正是新增语义条件的实际取舍。

**SDMT 重建：** Table 3 在 HumanML3D 测试集比较动作重建，SDMT FID 为 **0.012**，MoMask 为 0.019，T2M-GPT 为 0.070。正文说明分部位与语义文字融合都有帮助；公开索引中的部分单项勾选列排版不清，本文不据此给两个中间行强行分配模块名称。重建 FID 与上一节生成 FID 属于不同任务，不能用 0.012 代替生成结果 0.069。

**几何线索辅助描述：** Table 2 的最大明显改善出现在部位覆盖与表达清晰度，分别为 **6.83→7.97**、**6.65→7.76**。这符合数据构建的动机：先给具体部位和关系证据，再请模型组织语言；但评价者与生成器均使用 GPT-4o，仍需要更独立的核对来判断真实描述错误率。

### 关键发现

1. **文字对齐是更突出的收益。** HumanML3D 上 Top-1 达到 0.549，MultiModal Dist 为 2.802；MoMask 的生成 FID 仍更低，说明语义匹配优势不自动意味着动作分布质量全面最好。
2. **统一多模态生成存在取舍。** 手势 FGD 较好，而 BC 低于 ProbTalk、EMAGE、MambaTalk 和 SynTalker；舞蹈多样性较高，而 Lodge 的 FIDₖ 与 BAS 更好。评估应同时看语义、动作质量和节奏。
3. **描述计划与解码文字条件各有作用。** 手势消融表明，仅加入细粒度描述已经改善 FGD，进一步向解码器注入文字还有增益；它们不是同一个模块的两个名字。
4. **零样本能力目前主要由案例展示。** 论文举出被熊追赶、模仿鸟飞等情景，说明细粒度描述可帮助把场景拆成已有动作成分。正文没有提供充分的开放词汇大规模成功率，不能把示例扩展为任意复杂情景都可靠。

## 亮点与洞察

- **计划参与两个生成层次：** 它先引导 LLM 生成离散符号，又指导连续解码。相比只把计划打印出来，这使计划有更直接的训练与执行路径。
- **同一描述体系连接不同数据源：** 有粗文字的数据、只有音频的舞蹈和手势数据，都可以被补充为部位级动作描述，减少统一模型遇到的监督形式差异。
- **把时间分解与部位分解结合起来：** 动作序列没有丢掉时间结构，同时为身体局部建立更明确的表示区域，为重组不同部位的行为提供了更合理的接口。
- **公开表格暴露了控制取舍：** 增加细粒度语义后节奏指标下降，提醒后续系统不能仅凭描述更详细或匹配分数更高，就假设音频同步也一定改善。

<span id="reading-6" class="reading-anchor"></span>

## 局限与展望

1. **自然语言计划仍是软条件。** 正文没有证明指定关节角、精确目标位置、足底接触或左右手约束得到严格满足。几何标注算子不能替代生成后的几何验证。
2. **描述错误会沿链条传播。** GPT-4o 标注、MotionUPG 拟定计划、动作 token 预测和条件解码都可能引入偏差。计划写得合理，并不能证明后续连续动作已经落实每项细节。
3. **分部位不等于完全独立控制。** 身体需要全局协调，解码器还要融合不同部位与全局描述。改变一个部位对应的 token 或文字，是否严格保持其余动作不变，正文没有提供保存性评测。
4. **零样本和联合控制的评价还不充分。** 三张主生成表主要覆盖标准文本、语音、音乐任务，缺少系统性的音频与文字冲突测试、精确时刻控制以及长时连续动作评估。
5. **数据统计与数据可获得性是两回事。** MotionWords 的 6,820 万是词数，数据源也来自多套既有数据。当前网页仓库未提供可确认的完整标注包、逐样本清单、模型权重与运行代码，不能把演示站视为已经具备复现条件。
6. **部分实现和实验细节仍待原材料补齐。** 当前可读正文没有足够的训练耗时、端到端延迟、采样策略或完整补充证据；本文也尚未完成原 PDF 的视觉核对。可读的主表支持上述结论，模糊排版和未披露细节不据经验补全。

## 相关工作与启发

- **[MotionGPT](https://motion-gpt.github.io/)（NeurIPS 2023）：** 把动作看作可学习的离散语言，支持文字与动作任务。MotionUPG 进一步把细粒度描述与部位 token 组织成混合句子，并纳入语音、音乐条件。
- **[MoMask](https://ericguo5513.github.io/momask/)（CVPR 2024）：** 通过残差量化保留动作细节。MotionUPG 同样使用多层量化，但把身体分成多个分支，并在解码中加入部位与全局文字。
- **[PoseScript](https://github.com/naver/posescript)：** 用关节几何关系构造姿态的可读描述，是本文原子动作线索的启发来源。MotionUPG 将几何线索与采样帧、粗描述结合，再交给 GPT-4o 扩展为时序动作文字。
- **[SynTalker](https://robinwitch.github.io/SynTalker-Page/)**：同样关注语音与文字联合控制。MotionUPG 选择统一 token 与细粒度计划路线；其手势主表在 FGD 上更好、BC 上更低，体现了不同机制的取舍。
- **[Lodge](https://li-ronghui.github.io/lodge/)（CVPR 2024）：** 面向音乐舞蹈的专用生成方法。MotionUPG 用统一语言模型处理更多任务，但 FineDance 表中 Lodge 仍保持更好的 FIDₖ 与 BAS。
- **启发：** 可读动作计划只有在训练数据、离散生成和连续解码之间建立对应，才有机会成为有效控制接口。后续可以把几何规则同时用于计划生成与结果核验，检查“计划说了什么”和“身体最终做了什么”之间的差距。
