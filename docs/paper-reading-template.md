# 论文解读模板

版本：试行 v1 · 2026-10-13。用于网站论文解读；根据阅读反馈调整。

本模板从 [Paper-Notes 的 LaMoGen 成品文章](https://papernotes.org/CVPR2026/human_understanding/lamogen_language_to_motion_generation_through_llm-guided_symbolic_inference/)及其[源仓库](https://github.com/zhaoyang97/Paper-Notes)提炼。两者属于同一个项目。沿用阅读顺序与解释方法，以原创文字重述每篇论文，不沿用未经核验的结论。

## 先确定一条讲述主线

整篇解读回答：**读者遇到什么具体困难 → 旧方法为什么卡住 → 本文改变哪个环节 → 这个改变如何产生能力 → 实验支持到哪一步。**

不要把摘要扩写成若干术语段落。选一个贯穿案例，让它经过输入、表示、训练或推理、输出、评估。每个关键设计先讲直觉，再讲操作，最后解释为什么有必要。

按论文类型调整：没有对应内容的小节可以删去。理论、数据集或评测论文不强行填训练、冻结与推理流程；分别讲清论证、数据构建或评价协议。模板规定的是解释质量，不是固定填空题。

## 网站标题规则

标题以 `[出处年份]` 开头，例如 `[CVPR2026] 方法名：具体问题`。会议名采用常用缩写，年份采用正式会议年份；未核实正式录用的预印本使用 `[arXiv2026]`，不得从期刊模板页眉推定录用。新增文章同时更新 frontmatter 标题；保留事实依据。

网站正文位于 `src/content/blog/`，配图位于 `public/paper-notes/`，沿用现有博客布局。本文模板本身不是论文，不添加会议标签。

## 0 论文身份卡

记录完整标题、作者、版本日期、发表状态、研究任务、论文与官方项目入口、代码/权重/数据状态、阅读日期。会议主会、工作坊、期刊、预印本分开；只有正式出处核实后才标对应 CCF 等级。期刊模板页眉不能证明录用。

注明本次材料范围：正文、附录、官方仓库、实际运行分别是否覆盖。状态集中放在这里，正文只在它影响结论时再提醒。

## 1 一句话总结

用一到两句说清“针对什么问题，采用什么关键做法，获得什么能力”。随后给三条记忆锚点：**任务、机制、边界**。不把“首次”“全面领先”等作者主张直接作为事实。

## 2 研究背景与动机

从一个具体失败案例开始，说明当前做法缺的是什么。背景只保留理解本文必需的内容。收束为一个清楚的问题，例如：“已有动作加局部指令输入后，怎样修改指定时段，同时保留其余动作？”

## 3 方法详解

### 3.1 先走一遍整体流程

给出明确输入与输出，用一张简图连起关键步骤。箭头写传递的数据：文本、特征、符号、动作 token、连续动作。训练和推理分别画，不能混成一个不明阶段的流水线。

动作编辑论文额外说明：源动作是否必需、编辑范围由谁指定、哪些部分应保留、目标长度如何决定、最终解码表示是什么。

### 3.2 拆开关键设计

每个设计用连贯段落回答：**困难是什么 → 输入是什么 → 做了什么 → 输出是什么 → 为什么比简单做法更合适 → 代价或边界是什么。**

最多保留 1–3 个关键公式；逐一解释变量和运算，不堆推导。讲解改写式与论文原公式分清。原图附图号、来源和阅读提示；原创简图明确标为讲解示意。

### 3.3 用一个例子完整走通

从具体输入追到中间表示和最终输出。优先用论文自己的案例；自行构造时标明“教学示意”，不用虚构运行日志、成功率或精确输出。对时间编辑明确说明时间坐标是否随前序操作变化。

### 3.4 训练与数据从哪里来

区分复用预训练、重新训练、微调、冻结和仅推理优化。写清监督来自真实采集、程序生成、模型合成、人工标注还是混合。数据条数、独立样本数、改写次数分别统计。硬件、训练时长与完整成本分别报告，未披露的保留未知。

## 4 实验关键数据

先解释测试什么、指标的方向与含义，再展示主表。每个表标原表号与设置；优先选能回答核心问题的数据，不搬全排行榜。

每张表后写两件事：**它支持什么；它还没有证明什么。** 用百分比的差值时写“百分点”。至少保留一项不占优或失败的结果。

消融围绕因果问题组织：去掉什么、变化多少、还有什么变量没有排除。检索相似度、视觉演示和主观评价不能直接替代逐关节误差、接触、时序或指令成功率。

## 5 亮点与洞察

选择最多三项真正值得记住的设计，解释各自作用。分别辨认任务/数据/表示/训练/评测贡献。提出自己的理解时直接写“我的理解”，避免伪装成作者结论。

## 6 局限与展望

保留论文承认的限制，也指出实验范围尚未覆盖的要求。每个展望落到一个可以测试的问题；例如检查解码后未编辑区域误差，而不是泛泛说“提升鲁棒性”。

发布和复现状态用简短表呈现：代码、权重、数据、依赖、实际执行。公开 README 与可运行模型分别判断。

## 7 相关工作与启发

挑 3–5 篇相邻方法，说明它们在哪一步相同、在哪一步不同，并给原始论文链接。随后用一小段连接到当前研究问题：能借鉴什么、还缺什么、最小对照是什么。将阅读启发标为待验证的研究假设，并说明需要怎样的对照实验。

## 8 阅读判断与复习卡

评分采用三个有理由的维度：**阅读相关性、证据覆盖、复现准备度**。不提供缺少标尺的综合质量分；如需星级，只用于个人阅读优先级并写理由。

最后留下三条记忆和两道自测题，答案能在正文定位。目标是隔一周不用重读全文，也能回答“这篇在干什么，为什么有效，我能用什么”。

## 9 来源与更新

正文在重要结论附近链接原论文章节、图表或公式；文末汇总论文、官方代码和数据。保留版本与修订日期。引用图片注明作者、图号、链接和许可；不把网页摘要作为关键技术结论的最终依据。

## 默认交付与验收

- 一份可编辑的 Markdown 正文，一份带目录、清晰图表和折叠细节的阅读预览。
- 预览开头能在一分钟内看清身份与主旨，主文以方法和贯穿案例为重心，复杂细节放到末尾或折叠区。
- 提交前检查：读者能否复述输入、核心机制和输出；每个实验数字是否有原表；训练/推理是否混淆；有无把示意当实测；一周后是否能用复习卡恢复理解。
- 可核查的来源与检索记录单独保存，不用它们打断正文的阅读节奏。
